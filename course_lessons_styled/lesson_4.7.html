Урок 4.7. Библиотека готовых промптов: разбор структуры

Суть библиотеки промптов в автоматизации

Библиотека промптов — это централизованное хранилище структурированных текстовых инструкций, которые управляют поведением AI-модели в рамках вашей цепочки (workflow). Технически это набор переменных, где каждый промпт состоит из жестко заданных блоков: контекста, ограничений и ожидаемого формата вывода.

В No-Code системах библиотека позволяет избежать дублирования кода. Вместо того чтобы прописывать инструкцию внутри каждой ноды AI Agent, вы обращаетесь к единому объекту-шаблону. Это гарантирует, что при изменении логики обработки данных вам нужно отредактировать промпт в одном месте, а не в десятках нод по всей схеме автоматизации.

Разбор интерфейса и логика интеграции

Для реализации библиотеки в n8n или аналогичных платформах используются следующие компоненты:

  • Нода "Static Data" или "Code" (JavaScript): Используется как база данных промптов. Вы создаете объект, где ключи — это названия задач (например, "Summarization", "Sentiment_Analysis"), а значения — строки с инструкциями.
  • Поле "System Message" в ноде AI Agent: Вместо прямого ввода текста, в это поле вставляется выражение типа {{ $json.prompts.manual_check }}. Это делает систему динамической.
  • Интерфейс "Expression Editor": Окно, в котором происходит связка данных из вашей библиотеки с нодой AI Agent. Здесь вы видите структуру JSON, которая передается в API модели.
  • Нода "Edit Fields" (или Set): Используется для переопределения переменных промпта на лету. Если данные из Webhook меняют контекст задачи, вы через эту ноду подменяете значение в переменной промпта перед тем, как она попадет в AI Agent.

Технические требования к структуре промпта

  • Ролевая модель: Первый блок промпта всегда определяет роль (System Prompt). Пример: "Ты — технический ассистент".
  • Ограничения: Блок инструкций, запрещающий модели выходить за рамки заданного формата JSON.
  • Примеры (Few-Shot): Блок с примерами входных данных и ожидаемых ответов. Это ключевой элемент, обеспечивающий стабильную работу условия If, которое вы настроили в предыдущем задании.
  • Output Format: Строгое требование вывода только в формате JSON для последующей корректной обработки нодами типа If или Switch.

Пошаговая настройка библиотеки промптов

Для создания хранилища промптов внутри n8n выполните следующие действия:

  • Создайте ноду Edit Fields (Set) в начале цепочки, до AI Agent. Назовите её "Prompt Library".
  • В настройках ноды выберите тип JSON.
  • Добавьте поля: ключ system_prompt (в значении напишите инструкцию для AI) и ключ error_handler (в значении напишите инструкцию для обработки неизвестных команд).
  • В ноде AI Agent перейдите в поле System Message. Нажмите на иконку шестеренки и выберите Add Expression.
  • В открывшемся редакторе выберите ноду "Prompt Library" из списка доступных данных слева и перетащите переменную system_prompt в поле ввода.
  • Теперь AI будет использовать текст из вашей ноды "Prompt Library" как системную инструкцию.

Типичные причины сбоев и их устранение

  • Несоответствие структуры JSON: AI вернул текст без ожидаемых полей (например, забыл про intent). Решение: В системном промпте добавьте строгое правило: "Отвечай исключительно в JSON формате с ключом intent".
  • Ошибка в Expression: Ссылка на переменную из ноды "Prompt Library" не работает. Решение: Проверьте панель Execution Data. Если нода не была запущена (серый индикатор), данные не попадут в AI Agent. Нажмите Execute Node на ноде библиотеки перед запуском всего сценария.
  • Конфликт типов данных: Нода If ожидает строку, а AI прислал объект. Решение: В ноде If убедитесь, что в выпадающем списке выбран тип сравнения String (строка) и четко указано значение для сравнения.

Практическое задание

  • Создайте в ноде "Prompt Library" три разных варианта системных промптов (для вежливого общения, для технической поддержки и для "неизвестного" статуса).
  • Добавьте ноду Switch после Webhook, которая будет переключать поток в зависимости от темы запроса (например, "сказка" или "поломка").
  • Привяжите разные промпты из вашей библиотеки к разным веткам Switch.
  • Запустите цепочку с разными входящими сообщениями и проверьте в логах Execution Data, подставил ли AI Agent правильную инструкцию в поле System Message для каждого отдельного сценария.
