Урок 0.4. Как читать схемы автоматизации: «ноды», «триггеры» и «потоки данных»

Суть инструментов автоматизации

Автоматизация в n8n базируется на модели направленного графа. Система работает как конвейер: данные последовательно проходят через набор блоков (нод), где каждый блок выполняет строго определенную функцию: получение, изменение или передачу информации.

Процесс запускается событием (триггером), после чего создается объект данных в формате JSON. Этот объект перемещается между нодами по соединительным линиям (потокам данных), сохраняя состояние на каждом этапе обработки.

Основные элементы интерфейса и логика работы

  • Триггер (Trigger Node): Это первая нода в схеме. Она не просто обрабатывает данные, а «прослушивает» внешнюю среду (HTTP-запросы, изменения в Google Таблицах, входящие письма). Как только условие триггера выполнено, он инициирует создание потока данных.
  • Рабочая нода (Action Node): Любая нода, стоящая после триггера. Она принимает входные данные от предыдущей ноды, выполняет операцию (например, фильтрацию или отправку) и передает результат дальше.
  • Потоки данных (Connections): Линии, соединяющие ноды. Технически это каналы передачи JSON-структур. Если линия серая — данные не передавались или нода неактивна. Зеленая линия означает успешное выполнение передачи данных при последнем запуске.
  • Окно предпросмотра (Output Data): Панель справа от каждой ноды. В ней отображается состояние данных (Input/Output) в конкретной точке схемы. Это основной инструмент отладки: если данные не отображаются в окне, значит, поток разорван или триггер не получил запрос.
  • Панель конфигурации (Node Settings): Меню, открывающееся при нажатии на ноду. В нем содержатся поля ввода параметров (Path, URL, Headers, JSON-структуры). Изменение любого параметра требует сохранения настроек и повторного запуска триггера для обновления данных в потоке.

Пошаговая настройка потока данных

Для создания первого рабочего узла следуйте алгоритму:

  • Нажмите кнопку Add first step в центре рабочего поля и выберите Webhook.
  • В открывшейся панели настройки установите HTTP Method в значение POST.
  • В поле Path впишите test-endpoint. Скопируйте полный URL из поля Test URL.
  • Перейдите в Postman: выберите метод POST, вставьте скопированный URL, во вкладке Body выберите raw (тип JSON) и вставьте {"user_query": "Проверка связи"}.
  • Нажмите Send в Postman. Вернитесь в n8n: в окне предпросмотра ноды Webhook (справа) появятся полученные данные в структуре json.
  • Нажмите на «+» рядом с нодой Webhook, выберите Edit Fields (или Set).
  • В настройках новой ноды выберите Add Field, укажите тип String, в поле Value нажмите на иконку выражения (Expression), выберите из списка Webhook -> Data -> Body -> user_query.
  • Нажмите кнопку Execute Node для проверки связи.

Типичные ошибки и способы их устранения

  • Ошибка: «404 Not Found» при отправке запроса. Причина: вы не нажали кнопку Listen for Test Event в ноде Webhook. Решение: активируйте режим ожидания запроса перед отправкой из Postman.
  • Ошибка: Нода Edit Fields не видит данные из Webhook. Причина: разорвано соединение или нода не была запущена вручную. Решение: проверьте наличие зеленой линии между нодами. Если она отсутствует — перетащите коннектор от одной ноды к другой.
  • Ошибка: Пустые данные в поле Value (нода Edit Fields). Причина: неверный путь к JSON-ключу. Решение: убедитесь, что в предпросмотре ноды Webhook данные действительно находятся внутри ключа body, и перевыберите путь через редактор выражений.

Практическое задание

  1. Создайте цепочку из трех нод: Webhook -> Edit Fields -> HTTP Request.
  2. Настройте ноду Edit Fields так, чтобы она добавляла новое поле timestamp с текущей датой (используйте встроенную функцию now() в редакторе выражений).
  3. Убедитесь, что после нажатия Execute Node на последней ноде, все соединительные линии стали зелеными.
  4. Изучите содержимое окна предпросмотра на каждой из трех нод, сравнив, как изменяется JSON-объект на каждом этапе пути.
