НАЗВАНИЕ: Урок 0.1. Кто такой специалист по AI-автоматизации (технический обзор)
==================================================

=== Суть инструмента AI-автоматизации ===

        Специалист по AI-автоматизации работает с визуальными средами разработки, такими как n8n. Технически это процесс создания логических цепочек (воркфлоу), где данные передаются между программными интерфейсами (API) различных сервисов. Вместо написания программного кода вы соединяете блоки, называемые нодами, в единую последовательность.

        Система работает по принципу обработки событий: входящий сигнал (например, получение письма или заполнение формы) запускает цепочку действий. Автоматизация пересылает данные из одной системы в другую, применяя к ним заданные трансформации или пропуская их через AI-модели для анализа, классификации или генерации контента, после чего результат передается в конечную точку назначения.

=== Интерфейс и логика визуального программирования ===

              * Рабочее полотно (Canvas): Основная рабочая область, на которой размещаются ноды и соединяются направленными линиями (связями). Каждая линия определяет направление потока данных.

              * Библиотека нод (Nodes Panel): Боковое меню с перечнем всех доступных интеграций (Google Sheets, Telegram, OpenAI, Slack). Каждая нода имеет узкоспециализированную функцию: триггер (старт цепочки) или действие (выполнение шага).

              * Параметры ноды (Configuration Panel): Открывается при клике на блок. Содержит поля ввода для API-ключей, параметров запроса и выбора конкретных методов (GET, POST, PATCH).

              * Режим исполнения (Execution View): Инструмент отладки. Позволяет увидеть JSON-структуру данных, которые проходят через каждый блок. Вы видите, какие именно данные "пришли" в ноду и какие "вышли" из нее после обработки.

              * Выражения (Expressions): Встроенный редактор внутри полей ввода. Используется для извлечения данных из предыдущих шагов (например, подставить имя отправителя письма в тело ответа AI).

              * Кнопка Execute Workflow: Команда для принудительного запуска текущей цепочки для проверки работоспособности логики без ожидания внешнего события.

=== Пошаговая настройка базового сценария ===

        Для создания простейшей связки «Получение данных — Обработка AI — Сохранение» выполните следующие действия:

              * Нажмите кнопку Add Node на пустом полотне и выберите Webhook. В поле HTTP Method выберите POST. Скопируйте Production URL — это адрес, на который будут приходить данные.

              * Добавьте ноду AI Agent (из раздела Advanced AI). Чтобы наделить её интеллектом, перетащите на холст под-ноду OpenAI Chat Model и подключите её кабелем к порту Model ноды AI Agent. В параметрах OpenAI Chat Model выберите создание нового Credential и вставьте API-ключ из личного кабинета OpenAI.

              * Соедините выходной порт ноды Webhook с основным входным портом ноды AI Agent.

              * Внутри ноды AI Agent в поле Prompt / Input Text нажмите кнопку с иконкой шестеренки или «+», выберите Add Expression. В открывшемся дереве данных слева найдите выходные параметры ноды Webhook и выберите нужный ключ (например, «body.message»).

              * Нажмите кнопку Execute Node для теста. Если данные переданы верно, в окне вывода отобразится ответ от ИИ в свойстве output.

=== Типичные ошибки и методы отладки ===

              * Ошибка 401 (Unauthorized): Проблема в API-ключе. Решение: Откройте настройки Credentials в боковом меню, проверьте корректность вставки ключа, убедитесь, что он активен на стороне сервиса (например, OpenAI).

              * Ошибка "Data not found": Проблема в путях выражения (Expressions). Решение: Проверьте панель Input в нижней части экрана. Если данные, на которые вы ссылаетесь, не отображаются в структуре JSON, значит, нода-источник не передала их дальше. Убедитесь, что линия связи физически соединяет блоки.

              * Тайм-аут запроса (504 Timeout): Ответ от внешнего сервиса идет дольше, чем лимит ожидания ноды. Решение: В настройках ноды (вкладка Settings) увеличьте значение параметра Timeout (например, с 30 до 120 секунд).

=== Практическое задание ===

        Для закрепления материала необходимо выполнить следующее:

              * Создать в n8n цепочку Advanced AI: Webhook -> AI Agent (с подключенной под-нодой OpenAI Chat Model) -> Google Sheets.

              * Настроить Webhook на получение POST-запроса с JSON-структурой {"user_query": "текст"}.

              * Настроить ноду AI Agent так, чтобы она принимала значение из "user_query" и выдавала ответ.

              * Настроить ноду Google Sheets для добавления новой строки, где в первом столбце будет "user_query", а во втором — результат генерации ИИ (поле output).

              * Запустить процесс через Execute Workflow и проверить появление записи в Google Таблице.

НАЗВАНИЕ: Урок 0.2. Инструменты, которые мы установим, и результат
==================================================

=== Инструментарий автоматизации: n8n и интеграционный стек ===

n8n — это среда визуального программирования (Workflow Automation Tool), работающая по принципу потоков данных (data flow). Программа представляет собой рабочее поле (Canvas), на котором размещаются узлы (Nodes). Каждый узел выполняет атомарную операцию: прием запроса, отправку данных в API, трансформацию текста или запись в базу данных. Соединение узлов линиями создает логический конвейер, по которому передается JSON-объект с данными.

Google Sheets API и OpenAI API выступают в роли внешних сервисов, к которым n8n обращается для выполнения специфических задач: хранения данных и генерации контента на основе нейросетевых моделей. n8n выступает "оркестратором", который связывает эти сервисы между собой, передавая выходные данные одного узла на вход другому.

=== Разбор интерфейса n8n ===

      * Nodes Panel (Боковая панель): Содержит список всех доступных интеграций. Поиск осуществляется через строку Search. После клика на название ноды она добавляется на рабочее поле.

      * Canvas (Рабочее поле): Основная область для размещения нод. Связи между нодами создаются путем перетаскивания (Drag-and-Drop) коннектора (кружка с правой стороны ноды) к левому коннектору следующей ноды.

      * Node Configuration (Панель настроек): Открывается при двойном клике на ноду. 

              * Credential: Поле для авторизации через токены или API-ключи. Вкладка Create New Credential позволяет ввести секретный ключ сервиса.

              * Resource & Operation: Выпадающие списки для выбора действия. Например, для Google Sheets это "Rows" (ресурс) и "Append" (операция).

              * Expression Editor: Редактор выражений. Позволяет использовать данные из предыдущих узлов. Вызывается кликом на иконку шестеренки или при нажатии на поле ввода. Позволяет динамически подставлять переменные (например, {{ $json.user_query }}).

      * Workflow Controls (Верхняя панель): Содержит кнопку Execute Workflow для ручного запуска процесса и переключатель Production/Test.

      * Execution History (Панель выполнения): Доступна после запуска. Показывает структуру JSON-данных, которые передаются между нодами на каждом этапе. Вкладка Input/Output позволяет видеть, какие данные нода получила от предыдущей и что отправила следующей.

=== Пошаговая инструкция по настройке цепочки ===

      * Создание Webhook: Нажмите кнопку "+" в панели нод, введите "Webhook". Выберите метод POST. Скопируйте Test URL. В поле Authentication оставьте None. Нажмите Listen for Test Event, чтобы перевести ноду в режим ожидания данных.

      * Настройка Advanced AI: Добавьте ноду "AI Agent" (из раздела Advanced AI). Чтобы наделить её интеллектом, добавьте на холст под-ноду "OpenAI Chat Model" и соедините её с портом Model ноды AI Agent. В параметрах OpenAI Chat Model выберите Create New Credential и вставьте ваш API-ключ. В поле Prompt / Input Text ноды AI Agent нажмите на иконку шестеренки -> Add Expression. В открывшемся окне найдите в списке доступных данных Webhook -> body -> user_query. Нажмите Save.

      * Настройка Google Sheets: Добавьте ноду "Google Sheets". В Credential авторизуйте свой аккаунт Google. В поле Resource выберите "Row", в Operation — "Append". Укажите Document ID (из ссылки на вашу таблицу) и Sheet Name. Нажмите Add Column дважды: для первого столбца выберите Expression с данными из Webhook, для второго — результат генерации ИИ напрямую из ноды AI Agent (поле output).

=== Технические причины сбоев и их устранение ===

      * Ошибка авторизации (401/403): Проблема в невалидном API-ключе OpenAI или отсутствии прав доступа у n8n к Google Таблице. Решение: проверьте настройки в разделе Credentials, удалите старую запись и создайте новую, перепроверив права доступа.

      * Отсутствие данных в Expression (JSON path error): Возникает, если вы не прогнали тестовый запрос через Webhook заранее. Решение: нода не видит структуру данных, если она не была получена. Отправьте тестовый JSON через Postman или сервис-тестировщик по Test URL, чтобы n8n "увидел" структуру user_query.

      * Превышение таймаута: Если ИИ-модель долго генерирует ответ, процесс прерывается. Решение: откройте Settings ноды AI Agent, найдите поле Timeout и установите значение 120 секунд.

=== Практическое задание ===

      * Запустите выполнение процесса кнопкой Execute Workflow в режиме Test.

      * Откройте сервис для отправки POST-запросов (например, Postman или расширение для браузера), вставьте туда ваш Test URL и отправьте JSON: {"user_query": "Привет, как дела?"}.

      * Вернитесь в интерфейс n8n и проверьте визуальное отображение данных на линиях связи между нодами: они должны подсвечиваться зеленым цветом.

      * Откройте Google Таблицу и убедитесь, что в соответствующих ячейках появились значения из запроса и ответа нейросети.

НАЗВАНИЕ: Урок 0.3. Регистрация и первый запуск n8n (облако бесплатно)
==================================================

=== Суть инструмента n8n ===

n8n — это система автоматизации рабочих процессов, построенная на визуальном редакторе узлов (нод). Каждый процесс представляет собой цепочку действий, где одна нода передает данные следующей. Система оперирует объектами JSON (JavaScript Object Notation), перенося информацию между API различных сервисов без написания программного кода.

Технически n8n работает как серверная среда исполнения: она принимает входящий запрос (триггер), обрабатывает его через логические блоки и отправляет результат в стороннюю систему через HTTP-запросы. Вы визуально строите граф, где связи — это потоки данных, а ноды — точки их трансформации.

=== Интерфейс и логика работы ===

      * Canvas (Рабочее поле): Центральная область, где происходит сборка логической схемы. Перетаскивание нод осуществляется из боковой панели.

      * Nodes (Ноды): Блоки функционала. Бывают двух типов: Trigger (стартовая нода, запускающая процесс) и Action (нода, выполняющая действие).

      * Connections (Связи): Линии, соединяющие точки вывода (output) одной ноды с точками ввода (input) другой. Передача данных идет строго слева направо.

      * Configuration Panel (Панель настроек): Открывается при клике на ноду. Содержит поля для авторизации (Credentials), параметры API-запроса и настройки времени ожидания (Timeout).

      * Test URL / Production URL: Уникальные адреса, которые n8n предоставляет для каждой Webhook-ноды. Это конечные точки (endpoints), на которые отправляются внешние POST-запросы для запуска автоматизации.

      * Execution View: Режим отображения данных. После запуска процесса на линиях связи появляются кружки с превью данных. Зеленая подсветка означает успешную передачу пакета данных, красная — ошибку выполнения.

      * Execute Workflow: Кнопка принудительного запуска логической схемы в тестовом режиме. Используется для отладки перед публикацией процесса (активацией).

=== Пошаговая инструкция по регистрации и запуску ===

      * Перейдите на сайт n8n.cloud и нажмите Sign up, используя почту или Google-аккаунт для создания экземпляра.

      * После входа в интерфейс нажмите кнопку Templates или Blank workflow для начала работы.

      * В панели поиска слева введите Webhook и перетащите его на Canvas.

      * Кликните по ноде Webhook. В поле HTTP Method выберите POST. Скопируйте содержимое поля Test URL — оно понадобится для отправки тестового запроса.

      * Нажмите кнопку Listen for Test Event в нижней части окна ноды. Индикатор начнет мигать, ожидая входящий запрос.

      * Внешним инструментом (Postman) отправьте POST-запрос на скопированный URL, добавив в теле запроса (JSON) ключ user_query.

      * После получения данных нода Webhook отобразит входящий JSON во вкладке Output.

=== Технические причины сбоев и способы решения ===

      * Неверный HTTP метод: Вы отправляете данные методом GET, а нода настроена на POST. Решение: Убедитесь, что в настройках ноды Webhook и в программе-отправителе выбран один и тот же метод (POST).

      * Отсутствие активации процесса: Вы используете Production URL, но нода не переведена в активный режим. Решение: Нажмите переключатель Active в верхнем правом углу экрана n8n для сохранения и постоянной работы Webhook.

      * Тайм-аут соединения: Внешний сервис (например, OpenAI) не успел ответить за отведенное время. Решение: Зайдите в Settings целевой ноды, найдите параметр Timeout и установите значение 120 секунд.

=== Практическое задание ===

      * Создайте новый Workflow и добавьте в него ноду Webhook.

      * Установите значение Path для Webhook, например, "test-endpoint".

      * Скопируйте Test URL и отправьте запрос из Postman/Browser-расширения с параметром {"user_query": "Проверка связи"}.

      * В интерфейсе n8n проверьте, отображается ли JSON в окне предпросмотра ноды Webhook.

      * Добавьте вторую ноду (например, Edit Fields), соедините её с Webhook и убедитесь, что при повторном запуске данные передаются по линии связи (линия должна стать зеленой).

НАЗВАНИЕ: Урок 0.4. Как читать схемы автоматизации: «ноды», «триггеры» и «потоки данных»
==================================================

=== Суть инструментов автоматизации ===

Автоматизация в n8n базируется на модели направленного графа. Система работает как конвейер: данные последовательно проходят через набор блоков (нод), где каждый блок выполняет строго определенную функцию: получение, изменение или передачу информации.

Процесс запускается событием (триггером), после чего создается объект данных в формате JSON. Этот объект перемещается между нодами по соединительным линиям (потокам данных), сохраняя состояние на каждом этапе обработки.

=== Основные элементы интерфейса и логика работы ===

      * Триггер (Trigger Node): Это первая нода в схеме. Она не просто обрабатывает данные, а «прослушивает» внешнюю среду (HTTP-запросы, изменения в Google Таблицах, входящие письма). Как только условие триггера выполнено, он инициирует создание потока данных.

      * Рабочая нода (Action Node): Любая нода, стоящая после триггера. Она принимает входные данные от предыдущей ноды, выполняет операцию (например, фильтрацию или отправку) и передает результат дальше.

      * Потоки данных (Connections): Линии, соединяющие ноды. Технически это каналы передачи JSON-структур. Если линия серая — данные не передавались или нода неактивна. Зеленая линия означает успешное выполнение передачи данных при последнем запуске.

      * Окно предпросмотра (Output Data): Панель справа от каждой ноды. В ней отображается состояние данных (Input/Output) в конкретной точке схемы. Это основной инструмент отладки: если данные не отображаются в окне, значит, поток разорван или триггер не получил запрос.

      * Панель конфигурации (Node Settings): Меню, открывающееся при нажатии на ноду. В нем содержатся поля ввода параметров (Path, URL, Headers, JSON-структуры). Изменение любого параметра требует сохранения настроек и повторного запуска триггера для обновления данных в потоке.

=== Пошаговая настройка потока данных ===

Для создания первого рабочего узла следуйте алгоритму:

      * Нажмите кнопку Add first step в центре рабочего поля и выберите Webhook.

      * В открывшейся панели настройки установите HTTP Method в значение POST.

      * В поле Path впишите test-endpoint. Скопируйте полный URL из поля Test URL.

      * Перейдите в Postman: выберите метод POST, вставьте скопированный URL, во вкладке Body выберите raw (тип JSON) и вставьте {"user_query": "Проверка связи"}.

      * Нажмите Send в Postman. Вернитесь в n8n: в окне предпросмотра ноды Webhook (справа) появятся полученные данные в структуре json.

      * Нажмите на «+» рядом с нодой Webhook, выберите Edit Fields (или Set).

      * В настройках новой ноды выберите Add Field, укажите тип String, в поле Value нажмите на иконку выражения (Expression), выберите из списка Webhook -> Data -> Body -> user_query.

      * Нажмите кнопку Execute Node для проверки связи.

=== Типичные ошибки и способы их устранения ===

      * Ошибка: «404 Not Found» при отправке запроса. Причина: вы не нажали кнопку Listen for Test Event в ноде Webhook. Решение: активируйте режим ожидания запроса перед отправкой из Postman.

      * Ошибка: Нода Edit Fields не видит данные из Webhook. Причина: разорвано соединение или нода не была запущена вручную. Решение: проверьте наличие зеленой линии между нодами. Если она отсутствует — перетащите коннектор от одной ноды к другой.

      * Ошибка: Пустые данные в поле Value (нода Edit Fields). Причина: неверный путь к JSON-ключу. Решение: убедитесь, что в предпросмотре ноды Webhook данные действительно находятся внутри ключа body, и перевыберите путь через редактор выражений.

=== Практическое задание ===

      * Создайте цепочку из трех нод: Webhook -> Edit Fields -> HTTP Request.

      * Настройте ноду Edit Fields так, чтобы она добавляла новое поле timestamp с текущей датой (используйте встроенную функцию now() в редакторе выражений).

НАЗВАНИЕ: Урок 1.1. Интерфейс n8n: что где находится и зачем
==================================================

=== Суть n8n: визуальная оркестрация данных ===

n8n — это система визуального программирования, работающая по принципу потоков данных (data flow). Каждый процесс представляет собой цепочку узлов (нод), где выходные данные предыдущей ноды становятся входными данными для следующей. Взаимодействие происходит через передачу объектов в формате JSON между элементами рабочего процесса.

Инструмент работает асинхронно: каждая нода выполняет конкретную операцию над данными (преобразование, фильтрацию или отправку запроса), а визуальный редактор позволяет отслеживать состояние объекта на каждом этапе обработки.

=== Разбор интерфейса и логика работы ===

      * Canvas (Холст): Рабочая область, где размещаются ноды. Перемещение между нодами осуществляется перетаскиванием соединительных линий.

      * Node Library (Меню нод): Панель справа, содержащая список всех доступных функций. Используется для поиска нужного действия (например, "Webhook" или "HTTP Request") и перетаскивания его на холст.

      * Node Configuration (Окно настройки ноды): Открывается двойным кликом по ноде. Содержит параметры для конкретного действия. 

              * Parameters: Основные настройки (URL для запроса, методы, параметры полей).

              * Expression Editor (Редактор выражений): Иконка шестеренки или "Expression" внутри полей ввода. Позволяет использовать переменные из предыдущих нод и функции (например, now()) для динамического изменения данных.

      * Input/Output Preview (Окно предпросмотра): Нижняя часть окна настройки ноды. Отображает JSON-структуру, полученную от предыдущего шага, или результат выполнения текущей ноды.

      * Execute Node (Кнопка запуска): Расположена внизу панели настроек. Принудительно запускает текущую ноду для тестирования. После выполнения данные в окне предпросмотра обновляются.

      * Workflow Controls (Верхняя панель): 

              * Execute Workflow: Кнопка запуска всего сценария целиком.

              * Save: Сохранение текущего состояния рабочего процесса.

=== Пошаговая настройка цепочки ===

Для создания первого рабочего сценария выполните следующие действия:

      * Размещение: Откройте Nodes Panel справа, введите в поиске Webhook, перетащите ноду на холст. Повторите для Edit Fields и HTTP Request.

      * Соединение: Наведите курсор на серый круг справа от ноды Webhook, зажмите левую кнопку мыши и протяните линию к левому кругу ноды Edit Fields. Повторите действие для соединения Edit Fields с HTTP Request.

      * Настройка Edit Fields: Откройте ноду двойным кликом. Нажмите Add Field -> String. В поле Name введите timestamp. Нажмите кнопку с иконкой шестеренки напротив поля Value, выберите Add Expression. В окне редактора найдите вкладку Date & Time, выберите функцию now(). Нажмите Save.

      * Настройка HTTP Request: Укажите URL (например, https://webhook.site). В параметре Send Body выберите JSON. Нажмите Add Field -> Add Key/Value, введите ключ data, а в значении выберите Expression и через редактор укажите путь к полю timestamp из предыдущей ноды.

=== Типичные ошибки и методы их устранения ===

      * Отсутствие данных в следующей ноде: Если нода не видит данные, значит, предыдущая нода не была выполнена. Решение: Нажмите Execute Node на каждой ноде по очереди, пока соединительные линии не станут зелеными.

      * Неверная структура JSON (Path Error): Ошибка возникает при попытке обратиться к несуществующему пути в Expression Editor. Решение: В окне предпросмотра ноды раскройте объект json. Если нужное поле находится внутри вложенного объекта (например, body), путь должен быть прописан строго через точку: $json.body.timestamp.

      * Невалидный URL или метод: Нода HTTP Request выдает ошибку 404 или Connection Refused. Решение: Проверьте параметры Method (GET/POST) и наличие протокола https:// в поле URL. Убедитесь, что нода переведена в режим Manual execution при тестировании.

=== Практическое задание ===

      * Удалите ноду Edit Fields и создайте цепочку заново, добавив Set Node.

      * В Set Node настройте добавление двух новых полей: user_id со значением 123 и status со значением active.

      * Используя редактор выражений, передайте значение status из Set Node в заголовок (Header) или тело (Body) ноды HTTP Request.

      * После выполнения Execute Node откройте вкладку Output в последней ноде и убедитесь, что в итоговом объекте JSON присутствуют оба добавленных поля.

НАЗВАНИЕ: Урок 1.2. Первый workflow: автоматическая отправка письма по расписанию

=== Суть инструмента: n8n и событийная логика ===

n8n — это система визуального проектирования логических цепочек (workflow), работающая по принципу передачи потоков данных между нодами. Каждая нода — это отдельный функциональный блок, выполняющий одну конкретную операцию: запрос к API, трансформацию данных или задержку по времени. Данные передаются между нодами в формате JSON (JavaScript Object Notation), где каждый ключ и значение структурированы для машинного чтения.

Автоматизация по расписанию строится на событийной модели: стартовая нода выступает триггером, который генерирует "событие" в заданный момент времени. После срабатывания триггера управление передается по соединительной линии к следующей ноде в цепочке, которая обрабатывает полученный от предыдущего блока контекст.

=== Разбор интерфейса и логики ===

      * Интерфейс Canvas: Рабочее поле, где размещаются ноды. Соединение между ними создается путем перетаскивания вывода (круглая точка на правой стороне ноды) ко входу (точка на левой стороне) следующей ноды.

      * Нода "Schedule Trigger": Используется для настройки периодичности выполнения. 

              * Поле Trigger Interval: определяет частоту запуска (минуты, часы, дни).

              * Поле Start Time: устанавливает время первого запуска процесса.

      * Нода "Gmail" (или "SMTP"): Отвечает за отправку сообщений. 

              * Поле Resource: выбирается действие (в данном случае — "Message").

              * Поле Operation: выбирается функция (в данном случае — "Send").

              * Поле To: адрес получателя.

              * Поле Subject: тема письма.

              * Поле Text Content: тело письма, куда через Expression Editor (кнопка "Add Expression") можно подтянуть данные из предыдущих нод.

      * Панель настроек ноды: Открывается кликом по блоку. Вкладка Parameters содержит обязательные поля для заполнения. Вкладка Output доступна после нажатия кнопки Execute Node и отображает результат обработки данных конкретным блоком.

      * Редактор выражений (Expression Editor): Вызывается через пиктограмму шестеренки или нажатие кнопки "Expression" в полях ввода. Позволяет обращаться к данным из любой предыдущей ноды через синтаксис {{ $json.имя_ключа }}.

=== Пошаговая настройка отправки письма ===

      * В панели Nodes введите в поиске Schedule и перетащите ноду Schedule Trigger на холст. Установите интервал Every 1 Day.

      * Добавьте ноду Gmail (или SMTP), соедините её с триггером, перетащив линию от точки выхода Schedule к точке входа Gmail.

      * В настройках ноды Gmail нажмите Credential -> Create New Credential, введите данные авторизации почтового сервиса и нажмите Save.

      * В поле To введите адрес получателя. В поле Subject введите: "Ежедневный отчет".

      * В поле Body нажмите кнопку Add Expression. В открывшемся окне слева в списке Nodes выберите Schedule Trigger, кликните на объект Output Data, чтобы система автоматически сформировала выражение {{ $json.timestamp }}.

      * Нажмите Execute Node, чтобы отправить тестовое письмо и проверить корректность авторизации.

=== Типичные ошибки и их устранение ===

      * Ошибка аутентификации: Приложение выдает "401 Unauthorized" или "Invalid Credentials". Решение: Проверьте корректность OAuth2 токена или пароля приложения в настройках Credential. Если это Gmail, убедитесь, что в Google Cloud Console включен API Gmail.

      * Отсутствие данных в выражении: Выражение {{ $json.key }} возвращает undefined. Решение: Убедитесь, что предыдущая нода была выполнена (горит зеленая галочка) и данные физически переданы в поток. Если нода не была запущена, последующий блок не увидит входящий JSON.

      * Тайм-аут соединения: Решение: Проверьте соединение с интернетом и отсутствие фаерволов в вашей сети, блокирующих исходящие запросы к SMTP-серверам или API внешних сервисов.

=== Практическое задание ===

      * Создайте цепочку из трех нод: Schedule Trigger -> Set Node -> Gmail.

      * В Set Node создайте новое поле: message_body со значением "Автоматическое уведомление выполнено успешно".

      * Запустите цепочку кнопкой Execute Workflow и проверьте входящее письмо на наличие текста, заданного в Set Node.

=== Суть ноды HTTP Request ===

Нода HTTP Request — это универсальный инструмент для передачи данных между n8n и любыми внешними веб-сервисами, у которых есть API (интерфейс прикладного программирования). Если для конкретного сервиса в n8n нет готовой ноды, HTTP Request позволяет обратиться к нему напрямую, отправляя «запросы» на веб-серверы и получая от них ответы в формате JSON.

Технически процесс выглядит как обмен структурированными сообщениями: вы формируете пакет данных (запрос), указываете адрес сервера (URL) и метод взаимодействия (GET для получения данных, POST для отправки), а сервер возвращает результат выполнения операции.

=== Разбор интерфейса и логики ===

Внутри ноды HTTP Request критически важны следующие настройки:

      * Method (Метод): Определяет тип действия. GET используется для получения информации, POST — для отправки новых данных на сервер.

      * URL: Поле для ввода адреса API-конечной точки (endpoint). Сюда вставляется прямая ссылка на сервер, с которым вы планируете взаимодействовать.

      * Authentication (Аутентификация): Меню выбора способа подтверждения доступа. Обычно используются Header Auth (ключ в заголовке) или OAuth2. Без этого этапа сервер отклонит ваш запрос с ошибкой 401 или 403.

      * Send Body (Отправка тела запроса): Активность этого переключателя требуется при методе POST. Здесь вы формируете структуру данных (JSON), которые сервис должен принять и обработать.

      * Headers (Заголовки): Дополнительные параметры запроса. Используются для передачи мета-информации: например, указание формата данных (Content-Type: application/json) или токенов авторизации.

      * Query Parameters (Параметры запроса): Дополнительные фильтры, которые добавляются в конец URL. Используются для уточнения запроса, например: ?limit=10 или ?category=news.

Логика работы ноды всегда строго последовательна: ввод конфигурации -> отправка запроса -> получение ответа (Response). Ошибки в ответе (например, 404 — Not Found или 500 — Internal Server Error) отображаются во вкладке Output ноды, что позволяет диагностировать проблему на уровне API.

=== Пошаговая инструкция по настройке HTTP Request ===

Для интеграции внешнего API выполните следующие действия в редакторе n8n:

      * Добавьте на холст ноду HTTP Request и соедините её с предыдущим этапом сценария.

      * В поле Method выберите необходимое действие (например, GET для запроса данных).

      * В поле URL вставьте API-адрес конечной точки.

      * Если API требует авторизацию, нажмите Authentication, выберите Header Auth или API Key и введите предоставленные сервисом данные в соответствующие поля.

      * При использовании POST-запроса перейдите в раздел Send Body, установите переключатель в положение JSON, нажмите Add Field и вручную пропишите ключи и значения согласно документации API.

      * Нажмите кнопку Execute Node. Результат выполнения отобразится в нижней панели во вкладке JSON или Table.

=== Ошибки и способы их устранения ===

      * Ошибка 401 (Unauthorized): Система отклоняет запрос из-за неверного ключа. Решение: Проверьте раздел Authentication. Убедитесь, что токен скопирован полностью без лишних пробелов, а название заголовка в разделе Headers соответствует требованиям API.

      * Ошибка 400 (Bad Request): Сервер не понимает структуру данных. Решение: Проверьте вкладку Body. Убедитесь, что все обязательные поля, требуемые документацией API, заполнены, а их типы данных (число или строка) соответствуют ожиданиям сервера.

      * Ошибка 404 (Not Found): Запрос ушел по несуществующему адресу. Решение: Проверьте URL в поле ввода. Ошибки часто возникают из-за опечаток или пропущенных символов в пути к API. Также убедитесь, что вы используете правильный метод (GET вместо POST).

=== Практическое задание ===

      * Используйте сервис JSONPlaceholder (адрес: https://jsonplaceholder.typicode.com/posts/1) в поле URL для теста GET-запроса.

      * Добавьте после HTTP Request ноду Set Node и выведите в ней значение поля title, полученное от сервера, используя Expression Editor.

НАЗВАНИЕ: Урок 1.4. Условия и фильтры (нода IF): делаем автоматизацию «умной»
==================================================

=== Суть ноды IF: логическая маршрутизация данных ===

Нода IF — это логический вентиль, который разделяет поток данных на две ветки: true (истина) и false (ложь). Она принимает на вход объект из предыдущей ноды, сравнивает значение указанного поля с заданным условием и направляет исполнение сценария по соответствующему пути.

В отличие от простого прохождения данных, использование IF позволяет создавать ветвление: если условие выполняется, автоматизация идет по одной цепочке нод; если нет — по другой, или вовсе останавливает выполнение конкретной ветки.

=== Интерфейс и настройка логики ===

Для активации логического условия выполните следующие действия в редакторе n8n:

      * Добавление ноды: Нажмите на знак «+» после ноды Set Node и в поиске введите IF. Выберите её из списка доступных нод.

      * Поле Value 1: Сюда через Expression Editor передается значение из предыдущей ноды (например, поле title, полученное от HTTP Request).

      * Оператор (Operation): Меню выбора логического сравнения. Основные варианты:

              * Equal — значение в поле 1 в точности совпадает с полем 2.

              * Not Equal — значения не совпадают.

              * Contains — значение в поле 1 содержит внутри себя подстроку из поля 2.

              * Greater Than / Less Than — сравнение числовых значений.

      * Поле Value 2: Константное значение или переменная, с которой вы сравниваете данные из Value 1.

      * Ветки вывода: После настройки ноды IF вы увидите два порта вывода:

              * Верхний порт (с иконкой галочки): true. Сюда подключаются ноды, которые должны сработать при выполнении условия.

              * Нижний порт (с иконкой крестика): false. Сюда подключаются ноды, которые должны сработать, если условие не выполнено.

=== Практическая настройка ноды IF ===

Для внедрения условия в вашу текущую схему выполните следующие шаги:

      * Нажмите на соединительную линию между Set Node и любой следующей нодой (или на выходной порт Set Node) и выберите в поиске If.

      * В панели настроек ноды If нажмите кнопку Add Condition.

      * В поле Value 1 нажмите на шестеренку, выберите Add Expression. В открывшемся окне найдите в списке Current Node -> Output Data -> json -> title.

      * В выпадающем списке Operation выберите Contains.

      * В поле Value 2 введите текстовую строку, например: sunt.

      * Закройте окно настроек. Теперь от ноды If отходит два выхода. Соедините верхний выход (true) с новой нодой Edit Fields (Set), в которой напишите сообщение «Условие выполнено».

=== Типичные причины сбоев и способы устранения ===

      * Несоответствие типов данных: Вы пытаетесь сравнить строку с числом (например, 1 как текст и 1 как число). Решение: В поле Value 2 выберите тип данных, соответствующий данным из Value 1, или используйте приведение типов в Expression Editor.

      * Пустые значения (Null): Поле, которое вы проверяете, отсутствует в ответе от сервера (сервер вернул пустой объект). Решение: Добавьте перед нодой If ноду If (или Switch) с проверкой на наличие данных через оператор Is Set.

      * Чувствительность к регистру: Использование оператора Equal для текста, где различаются заглавные и строчные буквы. Решение: Используйте оператор Contains или переключите опцию Ignore Case (если доступно в версии ноды), чтобы игнорировать регистр.

=== Практическое задание ===

      * Самостоятельно настройте ноду If так, чтобы она проверяла, содержит ли поле title слово aut.

      * Подключите к выходу true ноду Set, которая устанавливает параметр result в значение "Совпадение найдено".

      * Подключите к выходу false ноду Set, которая устанавливает параметр result в значение "Совпадение не найдено".

      * Нажмите Execute Workflow и через вкладку Output убедитесь, что значение в result соответствует логике вашего запроса к JSONPlaceholder.

НАЗВАНИЕ: Урок 1.5. Циклы и массивы (нода Loop)
==================================================

=== Суть инструмента Loop (Loop Over Items) ===

В автоматизации n8n данные часто приходят в виде массивов — списков объектов (например, список из 100 пользователей). Стандартные ноды обрабатывают весь массив целиком. Если требуется применить логику к каждому элементу по отдельности (например, отправить email каждому пользователю из списка), используются циклы.

Современным стандартом в n8n версии 2026 года является нода Loop (Loop Over Items). Она пришла на смену устаревшей ноде Split In Batches. Нода Loop автоматически перебирает входящий массив поэлементно и имеет два удобных выхода: Loop (для отправки текущего элемента в тело цикла) и Done (для продолжения сценария после завершения итераций). Это избавляет от необходимости сложного ручного замыкания связей и настройки обратных петель.

=== Разбор интерфейса и логики работы ===

      * Loop Over Items:

              * Batch Size / Limit: параметр, позволяющий настроить порционную обработку (например, по 1 элементу за итерацию или всеми элементами сразу). Для пошаговой обработки каждого элемента обычно устанавливается размер пакета равный 1.

              * Loop (выход): этот порт передает текущие элементы поочередно во внутреннюю цепочку обработки (тело цикла).

              * Done (выход): этот порт активируется автоматически, когда все элементы массива были успешно обработаны. К нему подключаются ноды, которые должны сработать после завершения цикла (например, отправка итогового отчета).

      * Особенности работы с данными:

              * В процессе цикла ноды внутри тела цикла имеют доступ к текущему обрабатываемому элементу напрямую через входные данные.

              * Благодаря современной архитектуре, n8n сам отслеживает состояние цикла, поэтому вам больше не нужно протягивать обратную связь от последней ноды тела цикла к самой ноде Loop — сценарий выглядит лаконично и читаемо.

=== Пошаговая настройка цикла ===

Для создания рабочего цикла в современном n8n выполните следующие действия:

      * Добавьте ноду Loop (Loop Over Items) сразу после ноды, получающей массив данных (например, HTTP Request).

      * В настройках ноды Loop укажите размер пакета (Batch Size) равным 1 (или оставьте автоматический режим для пошагового перебора).

      * Соедините выход Loop ноды Loop Over Items с первой нодой тела цикла (например, нода Set).

      * Настройте тело цикла. Обратите внимание, что возвращать связь назад в ноду Loop больше не требуется — система сделает это автоматически!

      * Соедините выход Done ноды Loop Over Items со следующими шагами сценария, которые должны выполниться по завершении всей обработки.

      * Запустите процесс кнопкой Execute Workflow. Нода Loop последовательно прогонит все элементы через тело цикла.

=== Типичные ошибки и способы их устранения ===

      * Ошибки бесконечного выполнения: В старых версиях с ручным замыканием петель часто возникали бесконечные циклы. В современной ноде Loop эта проблема решена на уровне архитектуры.

      * Потеря данных из-за перезаписи: Происходит, если во внутренних нодах вы сохраняете результат с одинаковыми именами полей без накопления. Решение: используйте уникальные названия полей или встроенный сборщик результатов на выходе Done.

      * Неверный ввод (Input Type): Нода Loop выдает ошибку, если на вход поступает единичный объект вместо массива. Решение: проверьте через вкладку Input, что предыдущая нода действительно выдает список (иконка массива []), а не единичный объект. При необходимости используйте код или ноду Edit Fields для преобразования объекта в массив.

=== Практическое задание ===

      * Создайте HTTP Request, который получает данные по адресу https://jsonplaceholder.typicode.com/posts.

      * Добавьте современную ноду Loop (Loop Over Items) со значением Batch Size = 1 для поэлементного перебора.

      * Подключите к выходу Loop ноду Set (Edit Fields), которая берет поле title из текущего элемента и переименовывает его в processed_title.

      * К выходу Done ноды Loop подключите финальное действие (например, отправку уведомления или запись лога о завершении обработки).

      * Нажмите Execute Workflow и в панели Execution History пронаблюдайте, как нода Loop последовательно и автоматически перебирает каждый объект из JSON-ответа, а затем передает управление на выход Done.

=== Суть инструмента Edit Fields (Set) ===

Нода Edit Fields (Set) — это функциональный блок трансформации данных, предназначенный для принудительного создания, изменения или удаления полей внутри JSON-объекта, проходящего через процесс автоматизации. В отличие от других нод, она не выполняет сетевых запросов, а работает исключительно с оперативной памятью потока выполнения.

Логика работы заключается в перезаписи структуры входящего объекта согласно заданным правилам. Если поле уже существует, нода обновляет его значение; если поле отсутствует — нода создает его. Это основной инструмент приведения данных к нужному формату перед их отправкой в базы данных, мессенджеры или сторонние API.

=== Интерфейс и настройка логики ===

      * Панель параметров (Settings): При открытии ноды вы видите список Assignments. Нажатие кнопки Add Field добавляет строку для конфигурирования нового параметра.

      * Поле Name: В это поле вводится строковый идентификатор (ключ), который будет присвоен полю в итоговом JSON-объекте.

      * Поле Value: Здесь задается значение. Переключатель рядом с полем позволяет выбрать тип данных: String (текст), Number (число), Boolean (логическое значение) или Expression (выражение).

      * Режим Expression: При активации этого режима вы получаете доступ к интерфейсу построения путей к данным. Вы можете использовать синтаксис {{ $json.имя_поля }}, чтобы динамически извлечь значение из предыдущей ноды и передать его в новое поле.

      * Тип операции: Нода поддерживает два режима: Keep Other Fields (сохраняет все исходные поля объекта и добавляет/изменяет только указанные) и Replace All Fields (удаляет все старые данные, оставляя только то, что прописано в настройках ноды).

=== Пошаговая настройка узла трансформации ===

Для выполнения трансформации данных следуйте алгоритму действий в интерфейсе n8n:

      * Откройте ноду Edit Fields (Set), нажав на неё в рабочем поле (Canvas).

      * В блоке Assignments нажмите кнопку Add Field. Выберите тип данных String.

      * В поле Name введите: processed_title.

      * В поле Value нажмите на иконку шестеренки (или значок {{ }}) и выберите Add Expression.

      * В открывшемся редакторе выражений в левой колонке Variables раскройте список Current Node -> Input Data -> JSON.

      * Кликните по полю title. В редакторе появится выражение {{ $json.title }}. Нажмите Save.

      * Убедитесь, что в выпадающем списке параметров ноды выбрана опция Keep Other Fields (это позволит видеть результат трансформации вместе с исходными данными).

      * Нажмите кнопку Execute Node для проверки результата. В окне Output должен появиться новый ключ processed_title, дублирующий значение title.

=== Типичные ошибки и методы их устранения ===

      * Ошибка "Undefined" в значении: Возникает, если путь в выражении указан неверно или предыдущая нода не передала данные. Решение: Проверьте панель Input в настройках ноды. Если там пусто, убедитесь, что предыдущий узел был выполнен (кнопка Execute Workflow) и данные дошли до текущего шага.

      * Конфликт типов данных: Попытка записать массив или объект напрямую в поле String. Решение: В поле Value переключите тип с String на JSON или используйте метод .toString() в выражении, если необходимо превратить массив в текст.

      * Неверная привязка (Mapping): Ссылка на поле, которого не существует в текущем объекте (например, попытка взять $json.body, когда пришло только $json.id). Решение: Внимательно просмотрите структуру JSON-объекта на панели Input и используйте только те имена ключей, которые визуально отображены в дереве данных.

=== Практическое задание ===

      * Создайте новую ноду Edit Fields (Set).

      * Добавьте два новых поля: user_id_string (тип String) и is_processed (тип Boolean, значение true).

      * Используя режим Expression для user_id_string, преобразуйте числовое значение userId из входящих данных в строковый формат.

      * Добавьте в ту же ноду еще одно поле timestamp и вставьте выражение {{ new Date().toISOString() }}, чтобы зафиксировать время обработки.

      * Запустите выполнение и проверьте в панели Output наличие трех новых ключей с соответствующими типами данных.

НАЗВАНИЕ: Урок 1.7. Отладка и поиск ошибок: как читать красные ноды

=== Принципы отладки: визуализация сбоев ===

В n8n визуализация ошибок реализована через изменение состояния ноды на красный цвет. Когда нода окрашивается в красный, это означает, что выполнение процесса прервалось из-за необработанного исключения. Система фиксирует ошибку на уровне выполнения конкретного этапа, блокируя передачу данных (JSON-объектов) дальше по цепочке.

Механизм отладки основан на сравнении входных данных (Input) с логикой, заданной внутри ноды. Если нода не может обработать входящий массив или объект согласно заданным правилам (например, неверный тип данных или отсутствие ключа), она переходит в статус Error, возвращая лог системного сбоя вместо ожидаемого выходного пакета.

=== Интерфейс отладки и диагностика ===

      * Индикатор статуса ноды: Появление красного значка «крестик» или восклицательного знака поверх ноды сигнализирует о критическом сбое. Клик по ноде открывает панель Execution Data.

      * Панель Input/Output: При возникновении ошибки вкладка Output будет пустой или содержать системное сообщение об ошибке (Error Message). Сравните структуру входных данных во вкладке Input с требованиями настроек ноды.

      * Вкладка Error: В правой части панели параметров ноды появится дополнительная вкладка Error. В ней находится текстовое описание причины: например, "Expression Error" или "Invalid Data Type".

      * Инспектор выражений (Expression Editor): Если ошибка произошла внутри поля с выражением, откройте редактор Expression. Подсветка синтаксиса укажет на некорректный путь к переменной (например, если вы пытаетесь обратиться к полю, которого нет во входящем объекте).

      * Кнопка Execute Node: Позволяет запустить конкретный узел повторно после внесения исправлений, не перезапуская весь сценарий целиком. Это основной инструмент для точечной отладки данных.

=== Алгоритм локализации ошибки в узле ===

Для обнаружения причины сбоя при работе с данными следуйте пошаговому алгоритму:

      * Кликните на красную ноду. В правой панели перейдите во вкладку Error.

      * Скопируйте текст ошибки в буфер обмена. Если сообщение содержит "undefined", значит, нода пытается обратиться к полю, которого нет в JSON-структуре на входе.

      * Перейдите во вкладку Input. Прокрутите структуру данных до конца, чтобы убедиться, что имя ключа в JSON в точности совпадает с тем, что вы указали в Expression (регистр символов имеет значение).

      * Если ошибка указывает на Expression Error, откройте поле ввода, нажмите на иконку Expression и проверьте, не используется ли функция преобразования типов (например, .toString()) на значении, которое пришло как null.

=== Типичные технические сбои и их устранение ===

      * Несоответствие типов данных: Вы пытаетесь применить строковый метод к числу или наоборот. Решение: используйте явное приведение типов в выражении, например, оберните значение в String() или Number().

      * Отсутствующий ключ (ReferenceError): Нода запрашивает поле, которое не было передано от предыдущего узла. Решение: используйте оператор опциональной цепочки, например {{ $json.user?.id }}, вместо прямого обращения.

      * Синтаксическая ошибка в выражении: Пропущенная фигурная скобка или лишний символ в JS-коде. Решение: интерфейс n8n подсветит красным строку с ошибкой внутри редактора выражений; удалите неверные символы, пока подсветка не станет зеленой.

=== Практическое задание ===

      * Создайте умышленную ошибку: в ноде Edit Fields (Set) в поле user_id_string введите несуществующее имя переменной (например, {{ $json.non_existent_key }}).

      * Нажмите кнопку Execute Node и дождитесь появления красного индикатора.

      * Откройте вкладку Error и изучите текст системного сообщения.

      * Исправьте ошибку: верните корректное выражение для поля userId, используя визуальный выбор переменной в левой колонке Input Data.

      * Убедитесь, что нода окрасилась в зеленый цвет, а во вкладке Output отображается корректный JSON-объект.

=== Суть интеграции Google API в n8n ===

Интеграция n8n с Google сервисами (Drive, Sheets, Gmail) строится на протоколе OAuth2. Суть метода заключается в создании связующего звена — Credential. Этот объект хранит зашифрованные токены доступа, которые позволяют n8n взаимодействовать с вашими данными от лица вашего Google-аккаунта без передачи самого пароля от почты.

При использовании сервисных ключей (Service Account) n8n авторизуется как "робот" в рамках проекта Google Cloud. Это используется для автоматизированных систем, не привязанных к конкретному браузерному сеансу пользователя, что обеспечивает стабильность при выполнении фоновых задач.

=== Интерфейс и логика настройки ===

Для подключения аккаунта используются следующие элементы интерфейса n8n:

      * Credentials Manager: Левая боковая панель, вкладка Credentials. Здесь находится кнопка Add Credential, которая открывает список всех доступных сервисов.

      * Credential Type: Поле для выбора конкретной службы Google (например, Google Sheets OAuth2 API или Google Service Account).

      * OAuth2 Configuration: Содержит поля Client ID и Client Secret. Эти данные получаются в консоли Google Cloud после создания проекта и настройки OAuth Consent Screen.

      * Authentication Flow: При выборе типа OAuth2 в интерфейсе n8n появляется кнопка Connect My Account. Она инициирует всплывающее окно браузера для подтверждения прав доступа, после чего n8n получает авторизационный токен.

      * Service Account JSON: При выборе метода Service Account появляется текстовое поле для вставки содержимого файла .json, выгруженного из Google Cloud Console. Этот ключ содержит закрытый RSA-ключ, необходимый для криптографической подписи запросов к API.

Важное примечание: После создания Credentials в левой панели, они становятся доступны для выбора в выпадающем списке Credential for ... внутри любой ноды Google (например, Google Sheets Node). Статус подключения отображается в виде иконки статуса: серая — не настроено, зеленая — соединение активно.

=== Пошаговая настройка подключения (OAuth2) ===

      * Перейдите в левую панель n8n и нажмите Credentials.

      * Нажмите кнопку Add Credential и в строке поиска введите Google. Выберите Google Sheets OAuth2 API.

      * В новой вкладке браузера перейдите в Google Cloud Console. В разделе APIs & Services -> Credentials создайте OAuth 2.0 Client ID.

      * Скопируйте полученные Client ID и Client Secret и вставьте их в соответствующие поля внутри окна настройки Credential в n8n.

      * Скопируйте OAuth Redirect URL, который отображается внизу окна n8n, и вставьте его в поле Authorized redirect URIs в настройках проекта Google Cloud.

      * Вернитесь в n8n, нажмите Connect my account. Подтвердите права в появившемся окне браузера Google.

      * После успешной авторизации вы увидите сообщение Account connected successfully. Нажмите Save.

=== Типовые технические ошибки и методы устранения ===

      * Ошибка 403: Forbidden или Insufficient Permissions. Причина: Google API не включен для конкретного проекта. Решение: В Google Cloud Console перейдите в APIs & Services -> Library, найдите Google Sheets API и нажмите кнопку Enable.

      * Ошибка "Redirect URI mismatch". Причина: Адрес, указанный в Google Cloud, не совпадает с тем, что требует n8n. Решение: Скопируйте Redirect URL строго из окна n8n и обновите его в настройках OAuth Client ID в Google Cloud Console.

      * Ошибка 400: Invalid Request (заблокированное приложение). Причина: Вы используете тестовый аккаунт без добавления почты пользователя в список тестировщиков. Решение: В настройках OAuth Consent Screen внутри Google Cloud добавьте свой Google-адрес в раздел Test users.

=== Практическое задание ===

      * Создайте новое подключение Google Sheets в разделе Credentials, используя метод OAuth2.

      * Добавьте ноду Google Sheets на холст (Canvas).

      * В поле Credential for Google Sheets выберите только что созданное подключение из выпадающего списка.

      * В поле Resource выберите Spreadsheet, а в Operation — Get.

      * В поле Spreadsheet ID вставьте ID любой вашей тестовой таблицы (строка символов из URL таблицы между /d/ и /edit).

      * Нажмите Execute Node. Убедитесь, что статус ноды стал зеленым, а во вкладке Output появились метаданные вашей таблицы.

НАЗВАНИЕ: Урок 2.2. Google Sheets: читаем, пишем, обновляем строки автоматически
==================================================

=== Суть работы Google Sheets как базы данных ===

Google Sheets в автоматизации используется как хранилище данных (база данных плоского типа). Каждая строка в таблице воспринимается системой как отдельный объект (JSON-объект), где заголовки столбцов становятся ключами, а ячейки — значениями.

Процесс работы строится на HTTP-запросах к API Google. Нода n8n преобразует действия пользователя в эти запросы, позволяя считывать диапазоны ячеек, добавлять новые записи в конец листа или изменять существующие данные по определенному условию (фильтру).

=== Основные операции и логика управления ===

Для взаимодействия с данными используются следующие поля внутри ноды Google Sheets:

      * Resource: определяет объект манипуляции. Выбираем Row для работы с записями или Spreadsheet для управления метаданными файла.

      * Operation: выбор действия. 

              * Append — добавляет новую строку в самый низ таблицы.

              * Update — изменяет данные в конкретной строке (требует указания номера строки или уникального ключа).

              * Get Many — считывает массив данных из указанного диапазона (например, A1:D100).

      * Sheet Name: точное название вкладки в нижней части вашего документа Google Sheets. Оно должно совпадать до символа, включая пробелы.

      * Options / Column To Match On: критический параметр для обновления данных. Позволяет системе найти строку, которую нужно изменить, основываясь на совпадении данных (например, искать строку, где столбец "Email" равен значению из предыдущей ноды).

      * Value to Match: значение, по которому система ищет строку в таблице.

      * Columns: блок полей для сопоставления данных из автоматизации с заголовками столбцов в таблице (Mapping). В левое поле вписывается имя заголовка из таблицы, в правое — передаваемое значение из предыдущих нод.

=== Алгоритм настройки записи данных ===

      * Добавьте ноду Google Sheets и выберите операцию Append.

      * Укажите Sheet Name, соответствующее вашей вкладке.

      * Нажмите кнопку Add Field в разделе Columns.

      * Введите точное название заголовка вашего столбца в поле Column Name.

      * В поле Value с помощью кнопки с иконкой шестеренки выберите Add Expression для динамической подстановки данных из предыдущих шагов процесса.

      * Нажмите Execute Node для отправки тестовой записи в таблицу.

=== Пошаговая настройка обновления существующей строки ===

      * Добавьте на холст новую ноду Google Sheets и соедините её с предыдущим этапом, откуда приходят обновленные данные.

      * В поле Resource выберите Row, в поле Operation выберите Update.

      * В поле Lookup Column введите название столбца, в котором находится уникальный идентификатор (например, ID или Email).

      * В поле Lookup Value кликните на иконку шестеренки -> Add Expression. В открывшемся окне перетащите переменную из левой панели (Input), которая содержит значение для поиска.

      * В блоке Update Key нажмите кнопку Add Field, выберите название столбца, который нужно обновить, и введите новое значение или также выберите его через Expression.

      * Нажмите Execute Node. Если в таблице найдена строка с соответствующим Lookup Value, данные будут перезаписаны.

=== Технические причины сбоев и способы устранения ===

      * Ошибка "Sheet name does not exist": Возникает из-за несоответствия имени вкладки в настройках ноды и внизу интерфейса Google Sheets. Решение: скопируйте имя вкладки прямо из интерфейса Google Sheets (Ctrl+C) и вставьте его в поле Sheet Name в n8n, убедившись в отсутствии лишних пробелов.

      * Ошибка "Column not found": Возникает, если в настройках ноды указано название столбца (Column Name), которого нет в первой строке вашей таблицы. Решение: проверьте первую строку Google Sheets. Она должна содержать заголовки, идентичные тем, что указаны в ноде. Убедитесь, что вы не используете объединенные ячейки в заголовках.

      * Ошибка "403 Permission Denied": Возникает при попытке записать данные в таблицу, к которой у сервисного аккаунта или OAuth-пользователя нет прав на редактирование. Решение: откройте таблицу в Google, нажмите кнопку Поделиться и выдайте права Редактор тому email-адресу, который используется в ваших Credentials (обычно это email сервисного аккаунта или ваш личный аккаунт).

=== Практическое задание для закрепления ===

Выполните следующие действия в своем сценарии:

      * Создайте в таблице два столбца: Name и Status.

      * Добавьте одну строку с данными: Ivan в колонку Name и Pending в колонку Status.

      * Настройте ноду Google Sheets с операцией Update так, чтобы при запуске сценария статус Ivan менялся с Pending на Done.

      * Используйте Lookup Column: Name и Lookup Value: Ivan.

      * Проверьте изменение значения в интерфейсе Google Sheets после нажатия Execute Node.

НАЗВАНИЕ: Урок 2.3. Google Forms -> Google Sheets -> уведомление: полная связка
==================================================

=== Суть автоматизации передачи данных из Google Forms в Google Sheets ===

Связка Google Forms и Google Sheets работает как поток событий: форма выступает источником данных (триггером), а таблица — местом их структурированного хранения. В n8n процесс выглядит как цепочка: нода Google Forms Trigger постоянно опрашивает API формы на наличие новых ответов. Как только форма получает заполненные поля, n8n мгновенно считывает эти данные в формате JSON и передает их в ноду Google Sheets, которая выполняет операцию Append (добавление новой строки).

=== Интерфейс и логика настройки узлов ===

Для реализации данной связки используются следующие компоненты интерфейса n8n:

      * Google Forms Trigger (нода-источник): В поле Form ID необходимо указать идентификатор формы из её URL (строка символов после /d/ и до /edit). Нажатие кнопки Listen for Event переводит ноду в режим ожидания: до момента получения реального ответа через заполнение формы сценарий не активируется.

      * Google Sheets (нода-приемник): 

              * В поле Resource выбирается Row, в Operation — Append.

              * Document ID: Выбор таблицы через встроенный поиск или вставка ссылки на Google Таблицу.

              * Sheet Name: Точное название вкладки в файле (например, Sheet1).

              * Mapping: В блоке Columns нажимается кнопка Add Column для каждой переменной из формы. В поле Value перетаскиваются (drag-and-drop) соответствующие ключи из выходных данных предыдущей ноды (Trigger).

      * Управление потоком: Для проверки корректности передачи данных используется кнопка Execute Workflow. В панели Output справа отображается сформированный JSON-объект, который нода передает дальше. Если данные отобразились в интерфейсе Google Sheets, значит, соединение между API Google и n8n установлено корректно.

=== Пошаговая инструкция настройки ===

      * Откройте n8n и добавьте ноду Google Forms Trigger. В выпадающем меню Credential выберите созданное подключение к Google API.

      * В поле Form ID вставьте ID вашей формы. Нажмите кнопку Listen for Event.

      * Откройте форму в режиме заполнения (через ссылку «Просмотреть»), введите любые тестовые данные и отправьте форму. Вернитесь в n8n: нода должна отобразить входящие данные в виде списка ключей и значений.

      * Добавьте ноду Google Sheets, соедините её с триггером. Выберите Resource: Row, Operation: Append.

      * В поле Document выберите из списка вашу таблицу. В Sheet укажите название листа (например, Лист1).

      * Нажмите кнопку Add Column для каждого поля формы. В поле Value нажмите на иконку «плюс» (Expression) и выберите соответствующие поля из данных, полученных от триггера.

      * Нажмите Execute Node для теста. Проверьте таблицу: строка с данными должна появиться автоматически.

=== Типичные ошибки и способы их устранения ===

      * Ошибка аутентификации (403 Permission Denied): Возникает, если аккаунт Google, подключенный в n8n, не имеет прав на редактирование таблицы или просмотр формы. Решение: Проверьте раздел Credentials в n8n, убедитесь, что вы предоставили все права при связывании аккаунта (особенно drive.file и spreadsheets).

      * Несоответствие имен столбцов: Вы пытаетесь записать данные в столбец, которого нет в таблице, или название в ноде отличается от заголовка в первой строке таблицы. Решение: Убедитесь, что в первой строке Google Sheets прописаны заголовки, и они в точности совпадают с названиями, указанными в маппинге ноды n8n.

      * Задержка API (Webhook delay): Форма заполнена, но n8n не реагирует. Решение: Нажмите кнопку Listen for Event повторно, чтобы обновить соединение, и убедитесь, что сценарий в n8n находится в статусе Active (переключатель в верхнем правом углу интерфейса).

=== Практическое задание ===

      * Создайте в Google Таблице три заголовка: Date, User, Message.

      * Настройте Google Forms так, чтобы в ней было три соответствующих поля для ввода.

      * Настройте n8n сценарий для автоматического переноса данных из формы в соответствующие колонки таблицы.

      * Удалите последнюю добавленную строку в таблице вручную, перезапустите сценарий в n8n, нажав Execute Workflow, и убедитесь, что данные успешно записались снова.

НАЗВАНИЕ: Урок 2.4. Google Docs и Google Drive: авто-создание документов по шаблону
==================================================

=== Суть автоматизации документов через Google API ===

Автоматизация создания документов строится на использовании шаблона (Template) — обычного файла Google Docs с внедренными переменными-заполнителями в формате {{имя_переменной}}. При запуске сценария в n8n система инициирует копирование файла-шаблона, после чего подставляет в него данные, полученные из предыдущих этапов (например, из Google Таблиц или формы).

Технически это происходит через API-запрос к Google Drive (копирование файла) и Google Docs (поиск и замена текста). В n8n этот процесс реализуется цепочкой нод, где данные передаются из одной ячейки в другую в формате JSON-объектов.

=== Разбор интерфейса и логики в n8n ===

Для реализации задачи используются следующие элементы интерфейса n8n:

      * Google Drive Node (Resource: File, Operation: Copy): Используется для дублирования файла-шаблона. В поле File ID вставляется идентификатор шаблона из URL (строка символов после /d/ и перед /edit).

      * Google Docs Node (Resource: Document, Operation: Update): Основной инструмент для работы с содержимым. Здесь используется параметр Replace Text. В поле Text to Find указывается ключ из шаблона (например, {{Date}}), а в поле Replace With — значение из данных, полученных в предыдущей ноде.

      * Expression Editor (Редактор выражений): При нажатии на поле ввода в Google Docs ноде открывается интерфейс выбора переменных. Вы перетаскиваете нужный узел данных (например, {{$json.Date}}) в поле, чтобы n8n динамически подставлял значения в документ.

      * Node Parameters: Обязательно поле Document ID в ноде Google Docs. Оно должно быть динамическим — в него нужно передать ID файла, созданного на предыдущем шаге (нодой Google Drive).

=== Ключевые настройки ===

      * Credentials: Общая настройка доступа через Google Service Account или OAuth2, которая связывает ваш аккаунт Google с интерфейсом n8n.

      * JSON Structure: Данные от нод всегда приходят в виде массива объектов. В редакторе выражений вы всегда выбираете конкретный ключ объекта, который соответствует заголовку вашей таблицы.

      * Mapping: Процесс сопоставления полей формы с полями в шаблоне документа. Важно, чтобы названия ключей в JSON-структуре совпадали с названиями переменных в тексте документа.

=== Пошаговая инструкция настройки ===

Для создания динамического документа выполните следующие действия:

      * Создайте в Google Docs файл-шаблон. В тексте напишите: Дата: {{date}}, Пользователь: {{user}}, Текст: {{message}}. Запомните ID файла из адресной строки браузера.

      * В n8n перетащите ноду Google Drive. Выберите ресурс File и операцию Copy. В поле File ID вставьте ID вашего шаблона.

      * Добавьте ноду Google Docs. В поле Document ID нажмите на иконку шестеренки и выберите Add Expression. В списке слева найдите ноду Google Drive и выберите параметр id созданного файла.

      * В этой же ноде Google Docs выберите операцию Update и параметр Replace Text. Добавьте три элемента в список Replacements:

              * Text to Find: {{date}} | Replace With: (перетащите из списка слева поле Date).

              * Text to Find: {{user}} | Replace With: (перетащите из списка слева поле User).

              * Text to Find: {{message}} | Replace With: (перетащите из списка слева поле Message).

      * Нажмите Execute Node для каждой ноды по очереди, чтобы проверить корректность передачи данных.

=== Типичные причины сбоев и их устранение ===

      * Ошибка "File not found": Происходит, если ID файла вставлен с ошибкой или у сервисного аккаунта нет прав доступа к файлу. Решение: Нажмите "Поделиться" в Google Docs и добавьте Email сервисного аккаунта (из настроек Credentials в n8n) с правами редактора.

      * Неверная переменная в Replace Text: Если текст в шаблоне написан как {{Date}}, а в ноде указано {{date}} (регистр символов), замена не произойдет. Решение: Скопируйте текст прямо из шаблона и вставьте его в поле Text to Find в n8n.

      * Отсутствие данных в очереди: Сценарий запускается, но документ пуст. Решение: Убедитесь, что нода, стоящая перед Google Docs, успешно получила данные. Нажмите на ноду Google Drive и проверьте вкладку Output — там должны быть данные из Google Таблицы.

=== Практическое задание ===

      * Создайте папку на Google Drive для хранения авто-документов и в ноде Google Drive в поле Folder ID укажите ID этой папки, чтобы документы не сохранялись в корневой директории.

      * Добавьте в цепочку ноду Google Drive (Share) после создания документа, чтобы автоматически открывать доступ к созданному файлу по ссылке (настройте параметр Role как reader).

      * Запустите сценарий, перейдите в созданную папку на Google Drive и проверьте, что документ создан, текст внутри заменен на данные из таблицы, а доступ к файлу открыт.

НАЗВАНИЕ: Урок 2.5. Проект: CRM-минимум в Google Таблицах с автозаполнением
==================================================

=== Суть автоматизации данных в Google Sheets ===

Google Таблицы в архитектуре автоматизации выступают в роли реляционной базы данных. Каждая строка представляет собой отдельный объект, а столбцы — параметры этого объекта. n8n подключается к таблице через API, считывая диапазон ячеек и преобразуя их в структурированный JSON-объект. Это позволяет передавать данные из таблицы в другие сервисы (генераторы документов, почтовые клиенты или CRM-системы) без участия человека.

Работа строится по принципу потока: нода-триггер (или нода чтения) получает массив данных, затем каждая запись проходит через цепочку узлов (нод), где выполняется обработка, форматирование и запись результата в целевой файл или сервис.

=== Интерфейс и логика настройки ===

=== Панель ноды Google Sheets ===

      * Resource: Параметр выбора действия. Для чтения данных используется Row, для действия — Get Many.

      * Operation: Выбор операции (например, Get Many для получения нескольких строк или Append для записи новой строки).

      * Document ID: Идентификатор вашей таблицы (буквенно-цифровой код из URL-адреса таблицы, расположенный между /d/ и /edit).

      * Sheet Name: Точное имя вкладки (листа) внутри файла, откуда производится чтение.

      * Data Mode: Параметр JSON или Define Below. Рекомендуется использовать JSON для работы со сложными массивами данных.

=== Логика передачи данных (Mapping) ===

В n8n данные между нодами передаются через механизм Expression (выражений). Чтобы использовать значение из колонки «Имя» в следующей ноде:

      * Откройте поле ввода в целевой ноде.

      * Нажмите кнопку Expression.

      * В панели Variables перейдите по пути: Nodes -> [Название ноды Google Sheets] -> Output Data -> JSON -> [Имя вашего столбца].

      * Система автоматически вставит конструкцию вида {{ $json.Имя }}, которая будет подставлять данные из таблицы при каждом запуске автоматизации.

=== Контроль состояния ===

      * Execution History: Панель справа, отображающая статус выполнения каждой ноды. Зеленая отметка означает успех, красная — ошибку.

      * Input/Output панели: Внутри каждой ноды позволяют увидеть, что именно пришло из Google Таблицы и какой формат данных был передан дальше по цепочке.

=== Пошаговая настройка автоматизации ===

Для связки Google Таблиц с шаблоном документа выполните следующие действия:

      * В интерфейсе n8n добавьте ноду Google Sheets. В поле Resource выберите Row, в поле Operation выберите Get Many.

      * Вставьте ID вашей таблицы в поле Document ID и укажите имя листа в Sheet Name. Нажмите Execute Node для загрузки данных.

      * Добавьте ноду Google Docs. В поле Operation выберите Create From Template.

      * В поле Template Document ID выберите или вставьте ID файла-шаблона.

      * В секции Template Data нажмите Add Field. В поле Key введите имя плейсхолдера из шаблона (например, client_name), а в поле Value с помощью кнопки Expression выберите соответствующее значение из выпадающего списка данных, полученных от ноды Google Sheets.

      * Нажмите Execute Node. Документ будет создан в корневой папке вашего Google Drive с заполненными данными.

=== Почему это ломается: типичные ошибки ===

      * Несоответствие имен ключей: Если в поле Key ноды Google Docs указано имя, отличающееся от текста в фигурных скобках в Google Документе (например, clientName вместо client_name), система не найдет место для вставки. Решение: проверьте написание ключей в обоих местах и убедитесь, что они идентичны.

      * Пустой массив данных: Если нода Google Sheets не находит данных в указанном диапазоне, последующие ноды выдадут ошибку No data found. Решение: проверьте, не пуста ли строка в Google Таблице, и убедитесь, что в ноде Google Sheets правильно указан Sheet Name.

      * Отсутствие прав доступа (403 Forbidden): Аккаунт, подключенный через Credentials в n8n, не имеет прав на запись в целевую папку или файл. Решение: откройте Google Диск, нажмите правой кнопкой на папку, выберите "Открыть доступ" и добавьте почту, которую вы используете для авторизации API в n8n, предоставив права Редактора.

=== Практическое задание ===

      * Создайте в Google Документе шаблон договора, расставив ключевые слова в двойных фигурных скобках: {{client_name}}, {{date}}, {{sum}}.

      * Настройте ноду Google Docs так, чтобы при запуске сценария каждое из этих полей заполнялось данными из соответствующих колонок вашей Google Таблицы.

      * Добавьте ноду Google Drive (Move) после создания документа. Укажите ID папки, созданной в предыдущем шаге, в поле Folder ID, чтобы переместить туда сгенерированный файл из корня диска.

      * Запустите сценарий и убедитесь, что в Google Таблице считываются данные, в Документе они подставляются в нужные места, а итоговый файл оказывается внутри целевой папки на диске.

НАЗВАНИЕ: Урок 3.1. Создание Telegram-бота через BotFather: пошагово за 10 минут
==================================================

=== 1. Суть инструмента: BotFather ===

BotFather — это официальный управляющий бот от разработчиков Telegram, работающий через стандартный интерфейс чата. Его техническая функция заключается в генерации API-токена — уникального ключа доступа, который связывает ваш сценарий в n8n с серверами Telegram.

Без токена, полученного через BotFather, автоматизированная система не имеет прав на чтение входящих сообщений или отправку ответов от имени вашего бота. Весь процесс взаимодействия сводится к отправке текстовых команд в чат и получению ответных данных для интеграции в ноды автоматизации.

=== 2. Интерфейс и логика настройки ===

Для создания бота необходимо выполнить следующие действия в интерфейсе Telegram:

      * Поиск и запуск: Введите в строке поиска Telegram @BotFather. Выберите аккаунт с синей галочкой и нажмите кнопку Start.

      * Создание бота: Введите команду /newbot. BotFather предложит задать имя бота (отображаемое имя) и его уникальный системный username (должен заканчиваться на _bot).

      * Получение токена: После успешного создания BotFather выведет строку формата Use this token to access the HTTP API: XXXXXX:YYYYYYYYYY. Этот буквенно-цифровой код — ваш единственный идентификатор.

=== Интеграция с n8n ===

Для использования бота внутри сценария n8n выполняются следующие шаги настройки в интерфейсе:

      * Добавьте в рабочее поле любую ноду Telegram (например, Telegram Trigger).

      * В поле Credential выберите Create New.

      * В открывшемся окне конфигурации вставьте скопированный токен в поле Access Token.

      * Нажмите кнопку Save. Теперь нода авторизована и готова к обмену данными с Telegram.

Логика работы: при каждом запуске сценария n8n обращается к API Telegram, используя данный токен, чтобы проверить наличие новых сообщений или выполнить команду отправки файла/текста в конкретный чат.

=== 1. Пошаговая практика: Настройка интеграции ===

После получения токена от BotFather, перейдите в интерфейс n8n:

      * Найдите иконку Credentials в левой боковой панели и нажмите Add Credential.

      * В строке поиска введите Telegram, выберите Telegram API.

      * Вставьте токен из буфера обмена в поле Access Token.

      * Нажмите кнопку Save в нижней части окна. Индикатор статуса должен сменить цвет на зеленый — это подтверждает успешное соединение.

      * Теперь добавьте ноду Telegram Trigger на рабочее поле. В поле Credential for Telegram API выберите созданное вами подключение из выпадающего списка.

      * В поле Updates выберите тип событий, на которые бот должен реагировать (например, message).

=== 2. Ошибки и их решение ===

      * Ошибка авторизации (401 Unauthorized): Возникает, если при копировании токена захвачен лишний пробел или спецсимвол. 
    Решение: Зайдите в Credentials, откройте созданное подключение и повторно вставьте токен, убедившись, что строка чистая.

      * Отсутствие реакции бота: Бот создан, но не отвечает. 
    Решение: Убедитесь, что вы нажали кнопку Start в самом боте (в Telegram), иначе API Telegram не будет пересылать сообщения в n8n.

      * Неверный Credentials ID: Вы используете несколько токенов для разных ботов.
    Решение: В ноде Telegram Trigger в поле Credential for Telegram API убедитесь, что выбрано именно то имя подключения, которое соответствует нужному токену.

=== 3. Практическое задание ===

      * Создайте нового бота через BotFather, используя уникальное имя.

      * Настройте Credentials в n8n и свяжите их с новой нодой Telegram Trigger.

      * Добавьте после триггера ноду Telegram с действием Send Message.

      * В поле Chat ID вставьте ID вашего личного аккаунта в Telegram (можно узнать через бота @userinfobot).

      * В поле Text напишите "Бот запущен".

      * Нажмите кнопку Execute Node и проверьте наличие сообщения в чате с вашим новым ботом.

НАЗВАНИЕ: Урок 3.2. Подключение бота к n8n: Webhook и Polling — в чём разница
==================================================

=== 1. Суть методов получения данных: Webhook против Polling ===

Взаимодействие n8n с Telegram API происходит через отправку и получение HTTP-запросов. Для получения входящих сообщений от бота существуют два фундаментальных метода: Webhook и Polling.

Webhook (Вебхук) — это метод «активного оповещения». Сервер Telegram сам отправляет данные на ваш URL-адрес n8n в ту же секунду, когда пользователь пишет боту. Это обеспечивает мгновенную реакцию и минимальную нагрузку на ресурсы сервера. В n8n для этого используется нода Telegram Trigger.

Polling (Опрос) — это метод «периодического запроса». n8n с заданным интервалом времени (например, каждые 5 секунд) спрашивает сервер Telegram: «Есть ли новые сообщения?». Если сообщения есть, сервер их отдает. Метод требует постоянного поддержания активного соединения и менее эффективен при высокой нагрузке, но полезен, если у вашего экземпляра n8n нет публичного HTTPS-адреса, доступного извне.

=== 2. Разбор интерфейса и логики в n8n ===

Выбор метода получения событий определяется типом триггерной ноды и ее настройками внутри рабочего пространства n8n:

      * Нода Telegram Trigger: Это основной инструмент для работы с Webhook. 

              * Authentication: Поле для выбора сохраненных Credentials (токена бота).

              * Updates: Список типов событий (сообщения, нажатия кнопок), на которые будет реагировать триггер.

              * Webhook URL: n8n автоматически генерирует уникальный URL, который регистрируется в Telegram API как точка приема данных.

      * Логика Polling (в рамках ноды Telegram): Если вы используете обычную ноду Telegram (не Trigger), работа происходит по модели «Запрос-Ответ». 

              * Resource: Выбор объекта (например, Message).

              * Operation: Выбор действия (Send, Edit, Delete).

              * Polling в n8n: При использовании ноды Poll Telegram, в интерфейсе настраивается поле Interval (время задержки между опросами).

      * Панель настроек (Workflow Settings): Здесь можно настроить глобальное поведение триггера, включая опцию Save Execution Progress, которая позволяет отслеживать, какие именно сообщения были обработаны, чтобы избежать дублирования команд при повторном запуске сценария.

=== 1. Практическая настройка Webhook в n8n ===

Для активации метода Webhook выполните следующие действия в редакторе:

      * Откройте редактор n8n и перетащите на рабочее поле ноду Telegram Trigger.

      * В поле Credential выберите созданное ранее подключение к вашему боту.

      * В выпадающем списке Updates выберите message (это позволит боту реагировать на текстовые сообщения).

      * В верхней панели редактора переключите тумблер Production в состояние On. Это действие отправляет команду серверу Telegram «закрепить» ваш публичный URL для получения событий.

      * Нажмите кнопку Listen for Event в интерфейсе ноды.

      * Откройте Telegram, найдите своего бота и отправьте ему любое сообщение. В интерфейсе n8n вы увидите JSON-объект с данными сообщения.

=== 2. Ошибки и методы устранения ===

Чаще всего сценарий перестает работать по следующим причинам:

      * Ошибка 404/Connection Refused: Ваш n8n работает на локальном компьютере (localhost) без внешнего IP или сервиса Tunneling (например, ngrok). Решение: Telegram не может «достучаться» до вашего компьютера. Используйте облачную версию n8n или настройте тоннель для публикации локального порта в интернет.

      * Неверный токен: Вы сменили бота в BotFather, но не обновили токен в ноде Credentials. Решение: Зайдите в меню Credentials (слева), выберите Telegram API и вставьте актуальный токен, полученный в BotFather.

      * Конфликт Webhook: Если вы используете один и тот же токен в двух разных экземплярах n8n или сторонних сервисах. Решение: Telegram разрешает только один активный Webhook. Отключите все другие системы, использующие этот токен, и пересохраните (переоткройте) ноду Telegram Trigger в рабочем сценарии.

=== 3. Практическое задание ===

      * Переименуйте ноду Telegram Trigger, добавив в название слово "Webhook".

      * Настройте ноду так, чтобы при получении сообщения бот автоматически пересылал обратно тот же текст, который вы отправили (используйте выражение {{ $json.message.text }} в ноде Telegram).

      * Нажмите кнопку Activate в правом верхнем углу интерфейса n8n, чтобы сценарий работал в фоновом режиме постоянно.

      * Закройте вкладку с n8n, напишите боту в Telegram и убедитесь, что ответ приходит без открытого окна редактора.

НАЗВАНИЕ: Урок 3.3. Бот-информатор: автоматические уведомления о событиях
==================================================

=== 1. Суть инструмента: автоматизация передачи данных ===

Бот-информатор — это программный сценарий, работающий по принципу «триггер — действие». В n8n такой процесс инициируется входящим событием (webhook), которое поступает от сервера Telegram в момент получения сообщения. Система фиксирует запрос, извлекает из него JSON-объект с данными сообщения и передает его дальше по цепочке нод для обработки.

После получения данных сценарий использует метод API «sendMessage» для отправки ответного запроса обратно на сервер Telegram. Вся логика выполняется на стороне платформы n8n, которая выступает посредником между пользователем и сервером обмена сообщениями, исключая необходимость в написании программного кода.

=== 2. Интерфейс и логика: работа с нодами ===

Для настройки автоматизации используются следующие элементы интерфейса n8n:

      * Telegram Trigger: нода-источник (триггер). Она открывает публичный URL (Webhook) для приема входящих POST-запросов от Telegram. В настройках ноды поле Updates определяет типы событий, на которые реагирует бот (например, message).

      * Telegram Node (Action): нода действия. В ней выбирается ресурс Message и операция Send Text Message. Основное поле для заполнения — Chat ID (идентификатор чата) и Text (содержимое сообщения).

      * Expression Editor (Редактор выражений): открывается при нажатии на кнопку шестеренки (или значок «+») рядом с текстовым полем. Здесь используется синтаксис {{ $json.message.text }} для динамической подстановки данных, полученных от предыдущей ноды.

      * Панель отладки (Node Output): отображает структуру полученного JSON-объекта в правой части окна. Это необходимо для выбора правильного пути к данным, которые нужно передать в последующие ноды.

      * Activate Toggle: переключатель в верхнем углу интерфейса. При активации n8n переводит сценарий в режим постоянного мониторинга входящих событий, даже при закрытом окне браузера.

=== 1. Пошаговая практическая инструкция ===

Для настройки автоматической отправки уведомлений выполните следующие действия в визуальном редакторе n8n:

      * Откройте существующий рабочий процесс с настроенной нодой Telegram Trigger.

      * Нажмите кнопку + на холсте, введите «Telegram» в поиске и добавьте ноду Telegram (тип: Action).

      * Соедините серую точку на ноде Telegram Trigger с левой точкой ноды Telegram.

      * В настройках новой ноды Telegram выберите ресурс Message и операцию Send Text Message.

      * В поле Chat ID нажмите кнопку Add Expression, перейдите во вкладку Nodes -> Telegram Trigger -> Output Data -> JSON -> message -> chat, выберите поле id.

      * В поле Text нажмите Add Expression, вставьте конструкцию {{ $json.message.text }} или выберите путь к сообщению через визуальное дерево данных (Input Data).

      * Нажмите кнопку Execute Node для проверки связи. Если в Telegram пришло сообщение, настройки верны.

=== 2. Ошибки и их устранение ===

      * Ошибка: "400 Bad Request" или "Chat not found". Причина: неверный или пустой Chat ID. Решение: проверьте, что в поле Chat ID подставлена динамическая переменная из триггера, а не статическое число.

      * Ошибка: Сообщение не приходит при закрытом n8n. Причина: сценарий активен только в режиме редактирования (Test Mode). Решение: переведите переключатель Active в положение On в верхнем правом углу.

      * Ошибка: "Conflict: terminated by other getUpdates request". Причина: использование метода Polling одновременно с другим ботом или другим сценарием на этом же токене. Решение: используйте Webhook как единственный способ получения обновлений, убедитесь, что в Telegram Trigger выбран параметр "Webhook".

=== 3. Практическое задание ===

      * Создайте новую ноду Set перед нодой Telegram.

      * В ноде Set добавьте поле типа String, назовите его "prefix" и впишите значение "Эхо:".

      * Измените поле Text в ноде Telegram так, чтобы оно выводило значение из ноды Set и исходный текст сообщения одновременно (используйте визуальный редактор выражений).

      * Нажмите Activate, закройте браузер и отправьте боту любое слово. Убедитесь, что бот отвечает с добавленным префиксом.

      * Откройте раздел Executions в левом меню n8n, найдите последнее событие и проверьте статус выполнения (должен быть зелёный индикатор Success).

НАЗВАНИЕ: Урок 3.4. Бот с кнопками (Inline Keyboard): меню, выбор, ветвление диалога
==================================================

=== 1. Суть Inline-кнопок ===

Inline-клавиатура — это набор кнопок, привязанных непосредственно к конкретному сообщению бота. В отличие от обычных кнопок, которые занимают место в интерфейсе ввода текста, Inline-кнопки существуют в контексте диалога. Когда пользователь нажимает на такую кнопку, Telegram отправляет боту сигнал (callback query), содержащий уникальный идентификатор кнопки. Этот идентификатор позволяет боту однозначно определить, какой вариант выбрал пользователь, и запустить соответствующую ветку сценария.

Технически работа строится по принципу "событие-реакция": нажатие кнопки генерирует входящий запрос, который нода Telegram в n8n интерпретирует как отдельное событие. Используя блок логики Switch, вы направляете сценарий по разным путям в зависимости от того, какой идентификатор был передан в теле этого запроса.

=== 2. Интерфейс и логика настройки ===

Для реализации меню с кнопками используются следующие инструменты в среде n8n:

      * Нода Telegram Trigger: в поле "Updates" необходимо выбрать тип "Callback Query", чтобы бот распознавал нажатия на кнопки.

      * Нода Telegram (отправка сообщения): в разделе настроек ноды нужно найти поле Reply Markup. В нем выбирается опция Inline Keyboard. Здесь добавляется массив (список) строк, внутри каждой из которых создаются кнопки.

      * Поле "Callback Data": самый важный параметр кнопки. Это скрытая текстовая метка (строка), которую бот получает при нажатии. Именно по ней бот "понимает", какую ветку диалога активировать.

      * Нода Switch: обязательный элемент для ветвления. Она принимает на вход поле callback_data из данных, пришедших от ноды Telegram Trigger. В настройках ноды Switch создаются правила (Rules): если значение равно конкретной метке кнопки, поток направляется по соответствующему выходу (Output 1, Output 2 и т.д.).

      * Нода Answer Callback Query: техническая нода, которую необходимо вызывать сразу после нажатия кнопки, чтобы убрать статус "загрузки" (часики) с кнопки в интерфейсе Telegram.

=== 1. Пошаговая настройка сценария ===

Для создания интерактивного меню выполните следующие действия в визуальном редакторе n8n:

      * Добавьте ноду Telegram и в поле Resource выберите Message, в поле Operation — Send Message.

      * В параметре Reply Markup установите значение Inline Keyboard.

      * Нажмите Add Option и выберите Rows. Внутри строки нажмите Add Option -> Buttons.

      * В поле Text кнопки впишите название, которое увидит пользователь (например, "Узнать статус").

      * В поле Callback Data впишите уникальный идентификатор, например: status_btn.

      * Добавьте ноду Switch. В поле Data Type выберите String. В поле Value 1 через визуальный редактор выражений выберите путь: $json.callback_query.data.

      * В настройках Rules ноды Switch создайте правило: если Value 1 равно status_btn, поток пойдет по Output 0.

=== 2. Ошибки и способы их устранения ===

      * "Часики" (Pending) на кнопке: Возникает, если вы не отправили подтверждение нажатия. Решение: Добавьте после ноды Telegram Trigger ноду Telegram с операцией Answer Callback Query, передав в поле Callback Query ID значение {{ $json.callback_query.id }}.

      * Неверная маршрутизация: Ошибка возникает, если Callback Data в кнопке и Rule в ноде Switch не совпадают по символам. Решение: Скопируйте значение из поля Callback Data и вставьте его в правило Switch без лишних пробелов.

      * Ошибки доступа к данным: Если поле с данными пустое, бот не видит нажатие. Решение: Убедитесь, что в ноде Telegram Trigger в списке событий (Updates) обязательно выбрано Callback Query, иначе данные о нажатии не будут передаваться в сценарий.

=== 3. Практическое задание ===

      * Создайте цепочку: Telegram Trigger -> Telegram (Send Message с двумя кнопками).

      * Присвойте кнопкам разные Callback Data: option_a и option_b.

      * Поставьте после триггера ноду Switch и создайте два независимых пути: при выборе option_a бот должен прислать сообщение "Вы выбрали А", при option_b — "Вы выбрали Б".

      * Добавьте ноду Answer Callback Query в самом начале ветки после триггера, чтобы убрать анимацию загрузки с кнопки.

      * Нажмите Test Step, активируйте workflow и проверьте реакцию бота в Telegram.

НАЗВАНИЕ: Урок 3.5. Бот, который пишет в Google Таблицу: сбор данных через чат
==================================================

=== 1. Суть инструмента: Google Sheets как база данных ===

Google Sheets в контексте автоматизации — это хранилище структурированных данных, к которому n8n обращается через API. В отличие от ручного ввода, автоматизация позволяет записывать данные в таблицу построчно в момент выполнения события (например, ответа пользователя в чате).

Механизм работы строится на методе Append (Добавление). Каждый входящий запрос из Telegram преобразуется в объект JSON, который n8n отправляет в Google Sheets. Таблица автоматически находит первую пустую строку и записывает туда значения из полей, которые вы указали в настройках ноды.

=== 2. Разбор интерфейса и логики Google Sheets в n8n ===

Для интеграции Google Sheets в n8n используются следующие элементы интерфейса:

      * Credential (Учетные данные): Нода требует подключения через OAuth2. Вы должны выбрать Google Sheets API и предоставить n8n доступ к конкретной таблице или всему аккаунту Google Drive.

      * Resource и Operation: В параметрах ноды Google Sheets выберите Resource: Row и Operation: Append. Это критически важно для добавления новых данных без удаления старых.

      * Document ID: Поле, куда вставляется уникальный идентификатор вашей таблицы (строка символов из URL-адреса таблицы между /d/ и /edit).

      * Sheet Name: Точное имя вкладки внизу таблицы (например, Sheet1). Регистр и наличие пробелов имеют значение.

      * Columns Mapping (Сопоставление колонок): Интерфейс предлагает секцию Columns to Send. В левом поле (Key) вы вписываете название заголовка вашей колонки в таблице (например, "Имя" или "Выбор"), а в правом (Value) — выражение {{ $json.callback_query.data }}, которое берется из данных Telegram-триггера методом Drag-and-Drop из панели вывода данных (Output).

      * Mapping Mode: Используйте режим Define Below. Он позволяет вручную задать соответствие каждой колонке таблицы конкретному параметру, полученному из предыдущих нод цепочки.

При передаче данных важно соблюдать порядок: Telegram Trigger (получение события) -> Switch (логический выбор) -> Google Sheets (запись результата в выбранную ветку).

=== 1. Пошаговая инструкция настройки ===

      * В рабочей области n8n добавьте ноду Google Sheets и соедините её с выходом ноды Switch (для каждого пути отдельно).

      * В настройках ноды Google Sheets нажмите на поле Credential, выберите Create New и пройдите авторизацию в вашем Google-аккаунте.

      * В поле Document выберите нужный файл через поиск или вставьте Spreadsheet ID из адресной строки браузера.

      * В поле Sheet укажите название листа (например, Лист1).

      * Нажмите кнопку Add Field в разделе Columns to Send.

      * В поле Key напишите название заголовка вашей колонки (например, Ответ).

      * Нажмите на иконку шестеренки (или плюса) рядом с полем Value, перейдите во вкладку Expression и перетащите мышкой (Drag-and-Drop) переменную data из структуры Telegram Trigger или выберите соответствующее значение из списка Input Data.

=== 2. Ошибки и их решение ===

      * Ошибка "404 Not Found" или "Requested entity was not found": Вы неверно указали Document ID или у n8n нет прав доступа к файлу. Решение: Проверьте, чтобы ID был скопирован целиком из URL (от /d/ до следующего /edit), и убедитесь, что Google-аккаунт в Credential совпадает с владельцем таблицы.

      * Ошибка "Invalid JSON" или "Data Mismatch": Попытка записать массив данных в одну ячейку. Решение: Убедитесь, что в поле Value вы передаете конкретное строковое значение (например, option_a), а не весь объект целиком.

      * Несоответствие заголовков: Данные записываются не в тот столбец. Решение: В поле Key название должно строго совпадать с заголовком в первой строке вашей Google Таблицы (учитывая регистр и лишние пробелы).

=== 3. Практическое задание ===

      * Подготовьте таблицу: в первой строке (ячейка A1) напишите слово Ответ.

      * Настройте ноду Google Sheets в обеих ветках (А и Б) вашего сценария так, чтобы при выборе кнопки в таблицу записывался текст "Выбран вариант А" или "Выбран вариант Б".

      * Запустите выполнение сценария кнопкой Test Step.

      * Откройте Google Таблицу в соседней вкладке и убедитесь, что при каждом нажатии на кнопку в Telegram в таблице появляется новая строка с соответствующим текстом.

      * Добавьте в таблицу вторую колонку (ячейка B1) с названием Время и используйте встроенную функцию n8n {{ $now }} в поле Value для автоматической фиксации времени клика.

НАЗВАНИЕ: Урок 3.6. Проект: Telegram-бот для записи клиентов (имя -> дата -> таблица)
==================================================

=== Суть инструмента: Telegram-бот и автоматизация данных ===

В данной архитектуре Telegram выступает в качестве интерфейса ввода (клиентского терминала), а n8n — в качестве процессора данных. Взаимодействие происходит по протоколу API: Telegram отправляет JSON-пакет с сообщением пользователя на Webhook-адрес вашего экземпляра n8n, после чего сценарий (workflow) обрабатывает полученную строку текста и передает её в Google Таблицы.

Для реализации записи данных используется метод Append в ноде Google Sheets. Он принимает структурированные пары «ключ-значение» и создает новую строку в таблице при каждом входящем событии, обеспечивая последовательное сохранение истории взаимодействий.

=== Разбор интерфейса и логики ===

Для создания цепочки "Имя -> Дата -> Таблица" используются следующие компоненты:

      * Telegram Trigger: Основная входная нода. В поле Updates необходимо выбрать message. Нода ожидает входящее текстовое сообщение, которое попадает в переменную {{ $json.message.text }}.

      * Google Sheets (Append): Нода для записи данных. В интерфейсе ноды необходимо:

              * Выбрать Operation: Append.

              * Указать Sheet ID: идентификатор из URL вашей таблицы.

              * В разделе Columns добавить два поля: Name (соответствует колонке A) и Date (соответствует колонке B).

      * Expression Editor (поле ввода): Инструмент для динамического заполнения ячеек.

              * В поле Name вставляется ссылка на данные из Telegram: {{ $json.message.text }}.

              * В поле Date вставляется встроенная функция n8n: {{ $now }}.

      * Connection Node: Визуальный коннектор между Telegram Trigger и Google Sheets. В n8n он передает объект (JSON-структуру), содержащий текст сообщения, в ноду записи, позволяя Google Sheets считать данные напрямую из входного пакета.

=== Алгоритм работы ===

      * Сценарий находится в режиме ожидания (Waiting).

      * При поступлении сообщения от пользователя Telegram отправляет JSON-объект в n8n.

      * Нода Telegram Trigger преобразует этот объект в читаемый формат.

      * Нода Google Sheets считывает данные из входного потока, подставляет текущую системную дату и время через $now, и отправляет команду записи в API Google.

=== Пошаговая настройка сценария ===

Для создания полноценной цепочки записи выполните следующие действия в интерфейсе n8n:

      * Настройка триггера: Перетащите на рабочее поле ноду Telegram Trigger. В поле Updates выберите message. Нажмите Listen for Test Event и отправьте любое текстовое сообщение своему боту в Telegram.

      * Добавление Google Sheets: Перетащите ноду Google Sheets и соедините ее с Telegram Trigger. В настройках укажите Resource: Sheet, Operation: Append.

      * Привязка данных: 

              * Нажмите на кнопку Add Field в разделе Columns и выберите Name. В поле ввода нажмите на иконку шестеренки, выберите Add Expression. Перетащите в редактор поле text из раздела Input Data (левая панель).

              * Добавьте второе поле Date. В поле ввода выберите Add Expression, найдите в списке функций DateTime и выберите $now.

      * Активация: Переключите тумблер Execute Workflow в режим Active в правом верхнем углу, чтобы бот работал постоянно.

=== Типичные ошибки и способы их устранения ===

      * Ошибка авторизации Google: Если нода подсвечивается красным, значит, срок действия токена истек. 
        Решение: Зайдите в Credentials, выберите ваш Google Account и нажмите Reconnect, подтвердив доступ в появившемся окне браузера.

      * Отсутствие данных в таблице: Данные уходят из n8n, но не появляются в листе.
        Решение: Проверьте Sheet Name в настройках ноды — он должен строго совпадать с названием вкладки в Google Таблице (например, Sheet1). Убедитесь, что в первой строке таблицы (A1, B1) уже прописаны заголовки (Ответ, Время).

      * Неверный JSON-путь: Вы получили ошибку "undefined".
        Решение: Убедитесь, что вы перетащили переменную text именно из блока message. Если структура данных изменилась, нажмите на Listen for Test Event заново, чтобы обновить схему входящих данных в интерфейсе.

=== Практическое задание ===

      * Создайте новый лист в вашей Google Таблице и назовите его Записи. Обновите название листа в ноде Google Sheets.

      * Добавьте в ноду Google Sheets третью колонку с названием Username. С помощью функции Expression заберите данные из поля message.from.first_name, чтобы бот записывал, кто именно отправил сообщение.

      * Нажмите Execute Workflow, отправьте боту свое имя, проверьте появление строки в таблице.

      * Проверьте работу бота, изменив сообщение: теперь бот должен фиксировать имя пользователя, текст сообщения и точное время отправки в трех разных колонках.

НАЗВАНИЕ: Урок 4.1. Что такое промпт и почему «напиши текст» — плохой промпт
==================================================

=== Что такое промпт ===

Промпт — это структурированный набор текстовых инструкций, передаваемых языковой модели для управления результатом её работы. Технически, это входной параметр API-запроса, который определяет контекст, формат выходных данных и правила обработки информации. В системе автоматизации n8n промпт передается в ноду AI Agent или HTTP Request как строковое значение.

Запрос «напиши текст» является невалидным, так как он не содержит дескрипторов роли, ограничений по длине, схемы выходных данных (JSON/Markdown) и критериев оценки качества. Отсутствие параметров приводит к недетерминированному поведению модели, что делает невозможным автоматизированную обработку полученного текста дальнейшими нодами в цепочке.

=== Интерфейс и конфигурация промпта в n8n ===

      * Нода AI Agent или Basic LLM: Основная точка ввода промпта. В поле Prompt вы указываете системную инструкцию.

      * Поле Prompt (Expression): Используйте иконку шестеренки рядом с полем для перехода в режим Expression. Это позволяет динамически подставлять данные из предыдущих нод (например, данные из Google Sheets или Telegram) прямо в текст инструкции.

      * Переменные (Input Data): Чтобы сделать промпт эффективным, используйте синтаксис {{ $json.message.text }} для вставки данных из входящего сообщения в тело промпта.

      * Системная инструкция (System Message): В продвинутых нодах типа AI Agent существует отдельное поле System Message. Здесь вы задаете глобальные правила поведения (например: «Отвечай строго в формате JSON»), которые модель не может нарушить, в отличие от стандартного поля ввода.

      * Кнопка Test Step: После ввода промпта всегда используйте кнопку Test Step внутри ноды, чтобы увидеть сырой ответ от API и убедиться, что модель придерживается заданного формата до того, как данные уйдут в Google Таблицу.

=== Пошаговая инструкция настройки промпта ===

Для корректной обработки данных в n8n выполните следующие действия:

      * Откройте ноду AI Agent (с подключенной под-нодой OpenAI Chat Model) в вашем рабочем пространстве.

      * В поле Prompt нажмите кнопку Add Expression.

      * В открывшемся окне редактора слева выберите нужную переменную (например, message.text из ноды Telegram).

      * Сформируйте промпт в поле ввода, добавив текстовые ограничители: "Ты — помощник. Тебе пришло сообщение: {{ $json.text }}. Извлеки из него только дату и статус, верни результат строго в формате JSON."

      * Нажмите кнопку Save и закройте окно редактора.

      * Нажмите Test Step для проверки корректности формирования строки перед отправкой данных дальше по цепочке.

=== Почему промпты ломаются: типичные ошибки ===

      * Отсутствие формата ответа: Модель выдает ответ в виде обычного текста с приветствиями, что ломает парсинг JSON в следующих нодах. Решение: Добавьте в промпт жесткое ограничение: «Не пиши ничего, кроме JSON».

      * Пустые входящие данные: Нода пытается отправить промпт, но переменная из Telegram пуста, из-за чего модель выдает ошибку API. Решение: Используйте ноду If перед промптом для проверки наличия текста в сообщении.

      * Превышение лимита токенов: Слишком длинный текст, передаваемый в промпт, приводит к обрыву связи. Решение: Добавьте инструкцию в промпт: «Сократи входящий текст до 500 символов перед анализом».

=== Практическое задание ===

      * Создайте в n8n связку: Telegram Trigger -> AI Agent -> Google Sheets.

      * В ноде AI Agent в поле System Message впишите строгое правило: «Твоя задача — извлекать из входящего текста только цифры. Если цифр нет, пиши 0».

      * Настройте Expression в поле ввода промпта так, чтобы он принимал text из Telegram.

      * Отправьте боту сообщение с буквами и цифрами (например: «Заказ 1500 рублей»).

      * Проверьте, записалось ли число 1500 в соответствующую колонку вашей Google Таблицы.

НАЗВАНИЕ: Урок 4.2. Структура идеального промпта: роль, задача, контекст, формат, ограничения
==================================================

=== 1. Суть структуры промпта ===

Промпт в контексте AI-автоматизации — это набор текстовых инструкций, которые определяют логику обработки данных нейронной сетью. Без четкой структуры модель интерпретирует входящий сигнал произвольно, что приводит к непредсказуемым результатам в конечной системе (Google Sheets или базе данных).

Технически промпт работает как фильтр: входные данные (строка из Telegram) проходят через системную инструкцию, которая задает правила преобразования (формат, ограничения, роль). Если инструкция не содержит конкретных параметров, модель выдает неструктурированный текст, который невозможно использовать для автоматического заполнения полей в таблицах.

=== 2. Разбор интерфейса n8n для настройки промпта ===

Для реализации логики промпта в n8n используются следующие элементы:

      * Нода "AI Agent" (или "Basic LLM Chain"): Основной узел обработки. Внутри него находится поле System Message. Это поле является "директивой" — оно задает поведение модели до получения пользовательского сообщения.

      * Поле "System Message": Здесь фиксируется Роль (кто модель), Задача (что сделать), Контекст (условия) и Ограничения (чего делать нельзя). Данные в этом поле не меняются при каждом запуске.

      * Поле "Prompt" (в ноде AI Agent): Сюда подаются динамические данные. Для подключения переменной из Telegram используйте кнопку Expression (иконка шестеренки или "плюс"). В открывшемся редакторе выберите переменную {{ $json.message.text }} из ноды Telegram Trigger.

      * Логика связки:

              * Роль: "Ты бухгалтерский скрипт".

              * Задача: "Извлеки сумму из текста".

              * Контекст: "Текст присылает пользователь из Telegram".

              * Ограничения: "Возвращай только целое число. Никаких пояснительных слов, никаких знаков валют".

      * Панель отладки (Execution): После нажатия кнопки Execute Workflow используйте правую часть окна для просмотра входных данных (Input) и того, что выдала модель (Output). Если вывод содержит лишние символы — корректируйте поле System Message до тех пор, пока формат данных не станет строго числовым.

=== 1. Пошаговая настройка в интерфейсе ===

      * В редакторе n8n откройте ноду AI Agent.

      * Перейдите во вкладку Prompt. Найдите поле System Message. Вставьте туда: «Твоя роль — извлекать числовые значения. Задача: найти число в тексте и вернуть его без знаков препинания и букв. Если чисел нет, верни 0. Ограничение: ответ должен состоять только из цифр, никаких пояснений».

      * Кликните на поле ввода основного промпта (ниже System Message). Нажмите кнопку Expression.

      * В дереве переменных слева найдите ноду Telegram Trigger, раскройте ветку message и выберите параметр text. В поле должен появиться текст {{ $json.text }}.

      * Нажмите Execute Node для теста. Убедитесь, что выходной поток содержит только число.

      * Соедините выход ноды AI Agent с нодой Google Sheets. В настройках последней выберите операцию Append и укажите нужную ячейку, сопоставив выход модели с полем колонки.

=== 2. Почему это ломается: типовые ошибки ===

      * Ошибка "Смешанный вывод": Модель добавляет слова (например: "Сумма: 1500"). 
    Решение: Усильте ограничение в System Message: "Отвечай строго числом, без дополнительных символов".

      * Ошибка "Неверное поле данных": Данные из Telegram приходят в другом формате (например, message.text может быть глубже в структуре). 
    Решение: Нажмите на Telegram Trigger, посмотрите вкладку JSON. Найдите точный путь к тексту и перетащите переменную в Expression заново.

      * Ошибка "Отсутствие типа данных": Google Sheets воспринимает число как текст. 
    Решение: В ноде Google Sheets проверьте поле Data Mode. Убедитесь, что оно настроено на автоматическое распознавание типа или принудительно задайте формат ячейки в самой таблице как "Числовой".

=== 3. Практическое задание ===

      * Измените System Message так, чтобы модель добавляла к числу префикс "ID-". Проверьте, что в Google Sheets записывается значение вида "ID-1500".

      * Отправьте боту текст без цифр (например, "Привет, как дела?"). Убедитесь, что в Google Sheets попал "0".

=== 1. Суть инструмента: обработка текстовых данных через LLM ===

Инструмент "Промпт" — это набор инструкций, который передается нейросетевой модели для обработки входного текста. В контексте автоматизации это работает как фильтр: на вход ноды подается неструктурированный текст (например, сообщение пользователя), а на выход подается структурированный ответ, соответствующий заданным правилам (JSON, число, конкретная фраза).

В n8n модель выступает в роли обработчика, который анализирует содержание сообщения, выполняет логические проверки (если-то) и преобразует данные в формат, пригодный для записи в ячейки Google Sheets. Это позволяет автоматизировать классификацию заявок без написания сложного программного кода.

=== 2. Разбор интерфейса и логики ноды ===

      * Нода AI Agent (в связке с OpenAI Chat Model): Основной узел для взаимодействия. В поле System Message задается поведение модели. Это критическая зона: всё, что здесь написано, является "законом" для обработки входящего потока данных.

      * Output Parser (Парсер вывода): Нода, которая преобразует "сырой" ответ нейросети в формат, понятный для последующей передачи в Google Sheets. При работе с классификацией данных рекомендуется выбирать формат Structured Output, где вы задаете схему данных (имя поля и тип данных — String, Number).

      * Меню "Prompt Options": Находится внутри настроек ноды модели. Параметр Temperature определяет "креативность". Для обработки заявок и классификации установите значение 0. Это заставит модель давать предсказуемые и строго логические ответы без "фантазий".

=== 1. Суть инструмента: Системный промпт ===

Системный промпт — это скрытая инструкция, которая определяет поведение языковой модели до того, как она получит основной запрос пользователя. С точки зрения архитектуры n8n, системный промпт задает контекстуальные границы и формат выходных данных (например, JSON или структурированный текст), предотвращая галлюцинации и отклонения модели от заданного алгоритма.

Модель использует эту инструкцию как фундаментальный приоритет. Если в системном промпте указано строго классифицировать данные на категории "Вопрос" и "Заказ", модель будет игнорировать любые попытки пользователя сменить тему или нарушить структуру вывода. Это превращает LLM из чат-бота в предсказуемый функциональный компонент автоматизации.

НАЗВАНИЕ: Урок 4.5. Цепочки промптов (Chain of Thought): когда одного запроса недостаточно
==================================================

=== 1. Суть метода Chain of Thought (Цепочки промптов) ===

Цепочка промптов — это архитектурный подход в автоматизации, при котором сложная задача разбивается на последовательность мелких, специализированных запросов к LLM (большой языковой модели). Вместо одного универсального промпта, который часто выдает ошибки при попытке обработать разнородные данные, мы используем поток данных через серию нод, где каждая последующая нода уточняет или структурирует результат предыдущей.

Технически это выглядит как передача объекта JSON из одной ноды в другую, где данные обогащаются или переформатируются. Это позволяет добиться детерминированного поведения модели, при котором она сначала классифицирует входящий запрос, затем извлекает из него параметры, и только в конце формирует итоговый ответ для базы данных.

=== 2. Разбор интерфейса и логики в n8n ===

Для реализации логики цепочки промптов в интерфейсе n8n используются следующие инструменты:

      * AI Agent Node: Основной исполнительный блок. В поле Prompt необходимо задавать строго ограниченную роль модели (System Message). Для цепочек рекомендуется разделять агент на «Аналитика» (классификация намерения) и «Генератор» (формирование вывода).

      * Memory (Window Buffer Memory): Нода, подключаемая к AI Agent. Обеспечивает передачу контекста предыдущих сообщений. В настройках необходимо указать Session ID, чтобы модель «помнила», что пользователь ответил на предыдущий вопрос.

      * Code Node: Ключевой элемент для парсинга данных. В поле Language выбирается JavaScript. Здесь вы обращаетесь к переменной $input.item.json, чтобы применить метод JSON.parse() к строке, полученной от AI. Это превращает текстовый ответ модели в структурированный JSON-объект, доступный для дальнейшей маппинг-логики.

      * Edit Fields (Set) Node: Используется для финального преобразования данных перед отправкой в Google Sheets. В интерфейсе ноды вы добавляете поля (например, Column_A, Column_B), а в значении используете выражения (Expression), например: {{ $json.parsedData.price }}, где parsedData — ключ, созданный в предыдущей Code-ноде.

      * Webhook Node: Точка входа данных. В поле HTTP Method выбирается POST. Все данные, полученные через body запроса, становятся доступны для всех последующих нод через переменную {{ $json.body }}.

Важное примечание: при настройке связи между нодами всегда проверяйте вкладку JSON в панели предпросмотра (Output). Если поле содержит невалидный JSON, нода Code выдаст ошибку Unexpected token. Всегда используйте инструменты отладки (Execution History), чтобы видеть, на каком этапе цепочки данные теряют структуру.

=== 1. Пошаговая инструкция реализации ===

      * Создание потока: Добавьте ноду Webhook. В поле HTTP Method выберите POST, в Authentication установите None.

      * Первый AI этап: Подключите ноду AI Agent. Выберите провайдера модели (например, OpenAI). В поле Prompt впишите инструкцию: "Проанализируй входящее сообщение. Если это вопрос о цене, верни JSON: {"intent": "price", "value": "null"}. Если это запрос количества, верни JSON: {"intent": "order", "value": "число"}".

      * Парсинг: Подключите ноду Code. В поле Mode выберите Run Once for All Items. В редакторе кода используйте функцию return JSON.parse(items[0].json.output);. Это превратит текстовую строку модели в объект, с которым работают остальные ноды.

      * Финальное действие: Добавьте ноду Google Sheets. В поле Operation выберите Append. В разделе Columns Mapping нажмите кнопку Map Each Column Manually. В поля для ввода значений перетащите мышкой (Drag-and-Drop) ключи intent и value из левой панели (Input Data).

=== 2. Почему это ломается: типичные ошибки ===

      * Галлюцинация формата: Модель добавила лишний текст (например, "Конечно, вот ваш JSON: ..."). Решение: В системный промпт AI Agent добавьте фразу: "Отвечай строго в формате JSON, без пояснительного текста".

      * Тип данных в Code-ноде: Попытка парсить пустой ответ или некорректную строку. Решение: Добавьте ноду If перед Code-нодой и проверьте наличие данных в поле output. Если поле пустое, направьте поток в сторону Error Trigger.

      * Ошибки маппинга: В Google Sheets приходят значения [object Object]. Решение: Проверьте, что в ноде Set/Edit Fields вы выбираете именно конкретное поле (например, $json.value), а не весь объект целиком.

=== 3. Практическое задание ===

НАЗВАНИЕ: Урок 4.6. Галлюцинации и нестабильность ИИ: как их контролировать
==================================================

=== Системный промпт как инструмент ограничения галлюцинаций ===

Галлюцинации ИИ — это генерация моделью фактов или структур данных, отсутствующих в контексте запроса. С технической точки зрения, это результат вероятностного характера предсказания следующего токена. Контроль осуществляется через System Message (системный промпт) — инструкцию, которая задает жесткие рамки поведения модели до начала обработки пользовательского ввода.

Системный промпт работает как фильтр: он определяет формат выходных данных (например, строго JSON) и ограничивает область знаний агента, запрещая ему додумывать информацию, если она отсутствует во входных данных. В n8n это первый уровень защиты перед передачей данных в ноду Code.

=== Настройка System Message в интерфейсе n8n ===

      * Откройте узел AI Agent в рабочей области.

      * Найдите секцию System Message (обычно располагается в поле Prompt Type или System Prompt).

      * В поле ввода вставьте текст, определяющий формат ответа: "Ты — анализатор запросов. Возвращай данные строго в формате JSON. Если данных нет, используй значение 'unknown'. Не добавляй пояснений."

      * Перейдите в настройки Output Parser внутри агента. Выберите Structured Output Parser, если модель поддерживает вызов функций (Function Calling).

      * В поле Schema (внутри Output Parser) добавьте параметры: intent (тип String) и value (тип Number). Это заставит модель принудительно следовать структуре, что минимизирует риск получения "сырого" текста, который ломает работу следующей ноды Code.

=== Логическая верификация через режим отладки ===

      * Нажмите кнопку Execute Workflow.

      * В панели Output узла AI Agent проверьте вкладку JSON. Если поле intent содержит нестандартные символы или пустой объект — системный промпт настроен некорректно.

      * Используйте кнопку Test Step для каждой ноды по отдельности, чтобы изолировать этап генерации от этапа парсинга. Если нода Code выдает ошибку, значит, системный промпт не ограничил ИИ, и он вывел лишние символы (например, текст "Конечно, цена составляет...").

      * При возникновении ошибки: вернитесь в AI Agent, усильте инструкцию в System Message фразой "Отвечай только JSON-объектом без дополнительных слов" и повторите тест.

=== Пошаговая настройка валидации вывода ===

      * Выберите ноду AI Agent и перейдите во вкладку Options.

      * Активируйте переключатель Return Trace, чтобы видеть, какие именно этапы рассуждения проходит модель перед отправкой данных в Code.

      * В поле Prompt Parameters (если используется модель через LangChain) установите Temperature в значение 0. Это минимизирует творческую составляющую модели и стабилизирует формат вывода.

      * В ноде Code переключите режим языка с JavaScript на JSON, если вам нужно просто отфильтровать поля, либо оставьте JavaScript и используйте метод item.json.intent || "unknown" для обработки пустот.

      * Нажмите кнопку Save Workflow, чтобы зафиксировать состояние всех параметров узлов.

=== Типичные технические сбои и методы исправления ===

      * Сбой 1: Модель добавляет "Markdown-обертку" (три обратные кавычки ```json). 
    Решение: В системном промпте добавьте инструкцию "Do not use markdown formatting". В ноде Code используйте метод .replace(/```json|```/g, '') при получении строки, чтобы очистить данные перед парсингом.

      * Сбой 2: ИИ возвращает массив вместо объекта. 
    Решение: В настройках AI Agent проверьте, чтобы Output Parser был настроен на получение одного объекта. Если ошибка сохраняется, в ноде Code явно укажите return [items[0].json];, чтобы принудительно выбрать первый элемент массива.

      * Сбой 3: Превышение лимита токенов в ответе. 
    Решение: В поле Max Tokens ноды AI Agent установите значение 50-100. Это вынудит модель быть лаконичной и снизит вероятность "рассуждений" на посторонние темы.

=== Практическое задание ===

      * Добавьте в цепочку ноду If сразу после AI Agent.

      * Настройте условие в If: если поле intent равно unknown, направьте поток в ноду Set, которая проставит статус "Требует ручной проверки".

      * Измените системный промпт так, чтобы при получении непонятного запроса модель возвращала intent: "manual_check", и проверьте, как изменится путь данных в редакторе.

=== Суть библиотеки промптов в автоматизации ===

Библиотека промптов — это централизованное хранилище структурированных текстовых инструкций, которые управляют поведением AI-модели в рамках вашей цепочки (workflow). Технически это набор переменных, где каждый промпт состоит из жестко заданных блоков: контекста, ограничений и ожидаемого формата вывода.

В No-Code системах библиотека позволяет избежать дублирования кода. Вместо того чтобы прописывать инструкцию внутри каждой ноды AI Agent, вы обращаетесь к единому объекту-шаблону. Это гарантирует, что при изменении логики обработки данных вам нужно отредактировать промпт в одном месте, а не в десятках нод по всей схеме автоматизации.

=== Разбор интерфейса и логика интеграции ===

Для реализации библиотеки в n8n или аналогичных платформах используются следующие компоненты:

      * Нода "Static Data" или "Code" (JavaScript): Используется как база данных промптов. Вы создаете объект, где ключи — это названия задач (например, "Summarization", "Sentiment_Analysis"), а значения — строки с инструкциями.

      * Поле "System Message" в ноде AI Agent: Вместо прямого ввода текста, в это поле вставляется выражение типа {{ $json.prompts.manual_check }}. Это делает систему динамической.

      * Интерфейс "Expression Editor": Окно, в котором происходит связка данных из вашей библиотеки с нодой AI Agent. Здесь вы видите структуру JSON, которая передается в API модели.

      * Нода "Edit Fields" (или Set): Используется для переопределения переменных промпта на лету. Если данные из Webhook меняют контекст задачи, вы через эту ноду подменяете значение в переменной промпта перед тем, как она попадет в AI Agent.

=== Технические требования к структуре промпта ===

      * Ролевая модель: Первый блок промпта всегда определяет роль (System Prompt). Пример: "Ты — технический ассистент".

      * Ограничения: Блок инструкций, запрещающий модели выходить за рамки заданного формата JSON.

      * Примеры (Few-Shot): Блок с примерами входных данных и ожидаемых ответов. Это ключевой элемент, обеспечивающий стабильную работу условия If, которое вы настроили в предыдущем задании.

      * Output Format: Строгое требование вывода только в формате JSON для последующей корректной обработки нодами типа If или Switch.

=== Пошаговая настройка библиотеки промптов ===

Для создания хранилища промптов внутри n8n выполните следующие действия:

      * Создайте ноду Edit Fields (Set) в начале цепочки, до AI Agent. Назовите её "Prompt Library".

      * В настройках ноды выберите тип JSON.

      * Добавьте поля: ключ system_prompt (в значении напишите инструкцию для AI) и ключ error_handler (в значении напишите инструкцию для обработки неизвестных команд).

      * В ноде AI Agent перейдите в поле System Message. Нажмите на иконку шестеренки и выберите Add Expression.

      * В открывшемся редакторе выберите ноду "Prompt Library" из списка доступных данных слева и перетащите переменную system_prompt в поле ввода.

      * Теперь AI будет использовать текст из вашей ноды "Prompt Library" как системную инструкцию.

=== Типичные причины сбоев и их устранение ===

      * Несоответствие структуры JSON: AI вернул текст без ожидаемых полей (например, забыл про intent). Решение: В системном промпте добавьте строгое правило: "Отвечай исключительно в JSON формате с ключом intent".

      * Ошибка в Expression: Ссылка на переменную из ноды "Prompt Library" не работает. Решение: Проверьте панель Execution Data. Если нода не была запущена (серый индикатор), данные не попадут в AI Agent. Нажмите Execute Node на ноде библиотеки перед запуском всего сценария.

      * Конфликт типов данных: Нода If ожидает строку, а AI прислал объект. Решение: В ноде If убедитесь, что в выпадающем списке выбран тип сравнения String (строка) и четко указано значение для сравнения.

=== Практическое задание ===

      * Создайте в ноде "Prompt Library" три разных варианта системных промптов (для вежливого общения, для технической поддержки и для "неизвестного" статуса).

      * Добавьте ноду Switch после Webhook, которая будет переключать поток в зависимости от темы запроса (например, "сказка" или "поломка").

      * Привяжите разные промпты из вашей библиотеки к разным веткам Switch.

      * Запустите цепочку с разными входящими сообщениями и проверьте в логах Execution Data, подставил ли AI Agent правильную инструкцию в поле System Message для каждого отдельного сценария.

=== Суть интеграции OpenAI и n8n ===

OpenAI API предоставляет доступ к вычислительным мощностям языковых моделей через протокол HTTP. В n8n версии 2026 года для интеграции используется современная архитектура Advanced AI. n8n выступает в роли оркестратора, управляющего поведением ИИ-агентов.

Взаимодействие происходит через Credential — токен доступа, который подтверждает подлинность запроса, основную ноду AI Agent, задающую сценарий и промпт работы агента, и подключенную к ней через специальный коннектор под-ноду OpenAI Chat Model, которая отвечает непосредственно за генерацию ответов.

=== Получение ключа API ===

      * Перейдите на платформу platform.openai.com.

      * В разделе API Keys нажмите кнопку Create new secret key.

      * Скопируйте полученную строку и сохраните её локально — повторно она не отобразится.

=== Настройка в интерфейсе n8n ===

=== Добавление Credentials ===

      * В рабочем пространстве n8n откройте левое меню, перейдите в раздел Credentials.

      * Нажмите Add Credential и выберите в поиске OpenAI API.

      * В поле API Key вставьте ключ, полученный ранее. Нажмите Save.

=== Настройка цепочки Advanced AI ===

      * Добавьте ноду AI Agent на холст (Canvas) через поиск в правой панели (раздел Advanced AI).

      * Перетащите на холст под-ноду OpenAI Chat Model и подключите её к порту "Model" ноды AI Agent.

      * В настройках под-ноды OpenAI Chat Model выберите созданный ранее объект Credential for OpenAI API.

      * В поле Model выберите актуальную модель (например, gpt-4o или gpt-4o-mini).

      * В настройках ноды AI Agent используйте поле Prompt / Input Text для динамической передачи пользовательского сообщения, например, {{ $json.body.message }}, а поле System Message — для задания глобальных правил и инструкций поведения вашего ИИ-агента.

=== Пошаговая инструкция: создание первого запроса ===

      * Убедитесь, что на холсте размещена нода AI Agent с подключенной к ней под-нодой OpenAI Chat Model.

      * В настройках под-ноды OpenAI Chat Model выберите ваш Credential и укажите модель gpt-4o-mini.

      * Откройте настройки ноды AI Agent. В поле System Message впишите инструкцию: "Ты — технический ассистент".

      * В поле Prompt / Input Text нажмите на иконку Expression (шестеренка или значок цепочки). В открывшемся редакторе выберите из списка входных данных ноду Webhook и её поле, содержащее входящий текст (например, {{ $json.body.message }}). Нажмите Save.

      * Нажмите кнопку Execute Node внизу панели настроек ноды AI Agent, чтобы запустить выполнение агента и отправить тестовый запрос. Ответ от модели отобразится напрямую в свойстве output.

=== Почему это ломается: типичные ошибки ===

      * Ошибка 401 Unauthorized: API-ключ неверный или истек срок его действия. Решение: Перейдите в Credentials, выберите свой объект OpenAI и заново вставьте ключ, убедившись, что в начале и конце нет лишних пробелов.

      * Ошибка 429 Too Many Requests: Исчерпан лимит средств (Credits) на аккаунте OpenAI. Решение: Зайдите в личный кабинет platform.openai.com, проверьте раздел Billing и наличие активных средств на балансе.

      * Ошибка "Model not found": Выбранная модель устарела или недоступна на текущем тарифе. Решение: В под-ноде OpenAI Chat Model в поле Model выберите или вручную введите актуальное название (например, gpt-4o-mini), так как выпадающий список моделей периодически обновляется производителем.

=== Практическое задание ===

      * Создайте цепочку: Webhook -> AI Agent (с подключенной под-нодой OpenAI Chat Model) -> Respond to Webhook.

      * В ноде Respond to Webhook настройте ответ так, чтобы он возвращал значение генерации ИИ напрямую (используйте Expression для выбора поля {{ $json.output }} из ноды AI Agent).

      * Запустите тест: отправьте JSON-запрос через любой инструмент (например, Postman или расширение браузера), передав сообщение "Привет, как дела?".

      * Откройте вкладку Execution Data в n8n и проверьте, пришел ли корректный текст в поле output ноды AI Agent и правильно ли он транслируется в финальный ответ.

      * Измените модель в под-ноде OpenAI Chat Model на другую (например, gpt-4o) и убедитесь, что структура ответа (прямая отдача текста в поле output) осталась прежней.

НАЗВАНИЕ: Урок 5.2. Нода OpenAI в n8n: Chat, Completion, Embeddings — что выбрать

=== Суть инструментов OpenAI в n8n ===

В современной AI-архитектуре n8n версии 2026 года для работы с искусственным интеллектом используется концепция Advanced AI. Вместо одной универсальной ноды OpenAI на холст выносится нода AI Agent, к которой через специализированные коннекторы подключаются другие узлы: под-нода модели (например, OpenAI Chat Model) или ноды памяти и инструментов. Это позволяет гибко менять провайдеров и собирать сложные ИИ-системы.

Выбор конкретной модели и её параметров определяет тип операции, которую вы запрашиваете у искусственного интеллекта. Разные модели подходят под разные задачи: от простых текстовых диалогов и классификации до сложных структурированных парсингов данных и векторизации.

=== Разбор современной архитектуры и интерфейсов ===

В n8n для разных типов ИИ-задач используются разные ноды:

      * AI Agent + OpenAI Chat Model: Это основная связка для ведения диалога и рассуждений. В ноде AI Agent настраивается системный промпт (System Message), а к порту Model подключается нода OpenAI Chat Model. Этот стек используется для 95% задач автоматизации: написание текстов, анализ данных, классификация или запуск инструментов ИИ. Вся генерация отдает чистый текст напрямую в удобное поле output.

      * Embeddings (нода OpenAI Embeddings): Специальная нода для преобразования текста в числовой вектор (массив чисел). Она не генерирует текст. Она используется для подготовки данных к поиску по сходству или созданию ИИ-баз знаний (векторных баз данных). Результат операции — массив чисел (вектор), который подключается к нодам векторных хранилищ (Vector Stores).

=== Технические поля интерфейса Advanced AI ===

      * AI Agent: Основной узел. В поле Prompt / Input Text передается пользовательский запрос (например, через Expression), а в поле System Message пишется инструкция о том, кем является агент и как он должен себя вести.

      * Model (OpenAI Chat Model): Подключаемая нода. В ней задается Model (например, gpt-4o-mini) и Credentials. От модели зависят стоимость и качество ответов.

      * Options (в ноде модели): Параметр Temperature (от 0 до 1). 0 — делает ответы ИИ строго предсказуемыми (идеально для обработки данных и JSON), 1 — делает их более "творческими".

При использовании ноды OpenAI Embeddings интерфейс меняется: на холст выносится специализированная нода, где указывается поле Text для векторизации. На выходе нода возвращает объект embedding, содержащий вектор с плавающей запятой.

=== Практическая настройка: переход от AI Agent к Embeddings ===

Для переключения логики с генерации на векторизацию выполните следующие действия:

      * Добавьте на холст ноду OpenAI Embeddings.

      * В настройках выберите ваш Credential для OpenAI.

      * В поле Text нажмите кнопку Add Expression. В открывшемся окне выберите данные из входящего Webhook, например, {{ $json.body.message }}.

      * В поле Model выберите актуальную версию векторной модели, например, text-embedding-3-small.

      * Нажмите кнопку Execute Node. В окне вывода во вкладке Output вы увидите массив чисел (вектор), а не текст. Это означает, что данные успешно подготовлены для векторной базы.

=== Технические причины сбоев и их устранение ===

      * Ошибка 401 (Unauthorized): Проблема в Credentials. 
        Решение: Перейдите в настройки Credentials под-ноды OpenAI Chat Model, убедитесь, что API Key скопирован без лишних пробелов. Проверьте баланс в личном кабинете OpenAI.

      * Ошибка 429 (Rate Limit): Вы превысили лимит запросов. 
        Решение: В настройках ноды AI Agent (вкладка Settings) включите параметр Retry On Fail для автоматического повтора запроса.

      * Несоответствие структуры данных: Попытка вывода текстового ответа из ноды Embeddings.
        Решение: Поскольку Embeddings возвращает вектор, а не текст, прямое обращение к тексту выдаст ошибку. Для диалоговых ответов всегда используйте связку AI Agent + OpenAI Chat Model, которая отдает результат в простом текстовом поле output.

=== Практическое задание ===

      * Создайте дубликат текущего сценария.

      * Настройте современную связку AI Agent + OpenAI Chat Model. В поле System Message добавьте инструкцию: "Ты — технический ассистент, отвечай только цифрами".

      * Подключите ноду Edit Fields (Set) после AI Agent. В ней добавьте поле result, в значении которого укажите прямое получение ответа: {{ $json.output }}. Современные ИИ-ноды n8n отдают чистый текст напрямую в это свойство!

      * Протестируйте цепочку: отправьте запрос через Postman, убедитесь, что в ответе пришло только число.

      * Добавьте на холст ноду OpenAI Embeddings, запустите её и посмотрите в логах Execution Data, как меняется структура JSON (вместо текстового output возвращается векторный массив в поле embedding).

НАЗВАНИЕ: Урок 5.3. Автоматическая обработка входящих сообщений с помощью GPT
==================================================

=== Суть интеграции ИИ и n8n ===

В современной архитектуре Advanced AI в n8n версии 2026 года интеграция ИИ-моделей работает через ноду AI Agent в связке с под-нодой модели (например, OpenAI Chat Model). AI Agent принимает динамический запрос (Webhook), обрабатывает его согласно заложенным инструкциям, и отдает результат.

Важнейшее улучшение современной платформы — это уход от сложного ручного разбора JSON-ответов от API. Если раньше приходилось писать длинные формулы вроде choices[0].message.content, то теперь нода AI Agent отдает готовый очищенный текст напрямую в свойство output. Для извлечения строго структурированных данных (например, JSON с четкими полями) используется под-нода Structured Output Parser, которая подключается напрямую к порту Output Parser ноды AI Agent.

=== Интерфейс и логика настройки AI-цепочки ===

      * AI Agent: Главная управляющая нода. In поле Prompt / Input Text указывается динамический промпт, а в System Message задаются правила игры для агента.

      * OpenAI Chat Model: Подключается к порту Model. В ней выбирается Credential и конкретная модель (например, gpt-4o-mini).

      * Structured Output Parser: Современная под-нода, которая подключается к порту Output Parser ноды AI Agent. В ней вы визуально или через JSON-схему описываете структуру данных, которую хотите получить от ИИ (например, поля summary, sentiment). ИИ гарантированно вернет JSON строго в таком формате.

=== Контроль данных через интерфейс Execution Data ===

После каждого запуска (кнопка Execute Workflow) n8n фиксирует результат в панели Execution Data. Вкладка Output отображает дерево JSON-структуры. В современном n8n ответ ИИ находится в корневом поле output. Если вы использовали Structured Output Parser, то в поле output будет лежать уже распарсенный готовый объект с вашими свойствами, готовый к немедленному использованию в последующих нодах без какого-либо дополнительного кода.

=== Пошаговая настройка узла обработки ===

      * Откройте редактор сценария. В вашей цепочке после Webhook должна идти нода AI Agent с подключенной к ней под-нодой OpenAI Chat Model.

      * Добавьте ноду Edit Fields (Set) на рабочее поле, соединив выход ноды AI Agent с её входом.

      * Нажмите на ноду Edit Fields (Set). В открывшейся панели выберите кнопку Add Field, затем выберите тип String.

      * В поле Name введите result.

      * В поле Value нажмите на иконку шестеренки и выберите пункт Add Expression.

      * В открывшемся редакторе выражений выберите ноду AI Agent и просто кликните на поле output. Убедитесь, что в поле выражения появилась лаконичная и современная строка: {{ $json.output }}.

      * Нажмите кнопку Save в нижней части панели.

=== Технические причины сбоев и их устранение ===

      * Ошибка разбора структуры: Возникает при попытке использовать устаревший синтаксис choices[0].message.content с новыми нодами Advanced AI. Решение: Используйте прямое поле {{ $json.output }}, так как современные ИИ-ноды берут всю рутину парсинга на себя.

      * Отклонение от схемы (Parser Error): ИИ не смог упаковать ответ в заданную схему Structured Output Parser. Решение: Упростите требования в схеме парсера или слегка поднимите температуру модели в настройках OpenAI Chat Model до 0.2.

      * Пустой результат (Null): Возникает, если в ноде Webhook не переданы данные, на которые настроена нода AI Agent. Решение: Проверьте вкладку Input в ноде AI Agent. Если она пуста, значит Webhook не принял данные. Проведите тестовый запрос из Postman еще раз.

НАЗВАНИЕ: Урок 5.4. Классификация и маршрутизация: ИИ решает, куда направить данные
==================================================

=== Суть инструмента: классификация данных ===

Классификация — это процесс присвоения входящим данным конкретной категории на основе анализа их содержимого. В автоматизации с n8n это реализуется путем передачи сырого текста из входящего вебхука в языковую модель (LLM), которая по заданному системному промпту (инструкции) возвращает строго определенный тег или значение.

Маршрутизация — это использование полученного классификационного тега для направления данных по разным веткам сценария. Использование ноды Switch позволяет разделить поток обработки: если ИИ определил категорию как "запрос в поддержку", данные уходят в базу тикетов, если "продажи" — в CRM. Это исключает ручную сортировку и автоматизирует логику принятия решений внутри системы.

=== Интерфейс и настройка маршрутизации ===

      * Нода Switch: Основной инструмент логического разделения. В поле Data Type выберите String. В поле Value 1 через Expression укажите путь к переменной, которую вернул ИИ (например, {{ $json.category }}).

      * Правила (Rules): Внутри ноды Switch добавьте необходимое количество правил. В поле Value 2 впишите строгое текстовое значение, которое ожидает получить ИИ (например, support или sales). Каждое совпадение создает отдельный выходной порт у ноды.

      * Нода IF: Используется для бинарной логики (да/нет). В поле Condition выберите String, Contains или Equals. Позволяет быстро отсеять входящие данные по ключевому слову.

      * Панель Expression (Add Expression): Используется для динамической подстановки данных. Чтобы передать результат работы ИИ в Switch, нажмите кнопку Add Expression в поле Value 1, найдите в левой панели (Input Data) вывод предыдущей ноды с ИИ и выберите нужное поле с категорией.

      * Соединение узлов: После настройки правил в ноде Switch, перетащите линию от каждого выходного порта (подписанного как Rule 1, Rule 2 и т.д.) к следующей целевой ноде (например, Google Sheets для логирования или HTTP Request для отправки уведомления в Telegram).

=== Пошаговая настройка классификации ===

      * Добавьте ноду AI Agent после ноды Webhook. Подключите к её порту Model под-ноду OpenAI Chat Model. В настройках под-ноды выберите ваш Credential и укажите модель gpt-4o-mini.

      * В поле Prompt задайте жесткую инструкцию: "Классифицируй входящее сообщение. Верни только одно слово: 'support' или 'sales'. Никаких дополнительных пояснений".

      * Добавьте ноду Switch. Соедините выход ноды AI Agent со входом Switch.

      * В ноде Switch нажмите кнопку Add Rule. В поле Value 2 введите support.

      * Нажмите Add Rule еще раз. В поле Value 2 введите sales.

      * Соедините выход Rule 1 (соответствующий 'support') с нодой Edit Fields (Set) или Google Sheets, чтобы зафиксировать действие для службы поддержки.

=== Технические причины сбоев и их устранение ===

      * Несоответствие регистра (Case Sensitivity): ИИ вернул "Support" (с заглавной), а в ноде Switch в правиле прописано "support" (строчная). Решение: в настройках ноды Switch активируйте тумблер Ignore Case.

      * Лишние символы в ответе ИИ: ИИ добавил точку или пробел к ответу (например, "support."), из-за чего условие в Switch не сработало. Решение: в поле System Message ноды AI Agent добавьте инструкцию "Return ONLY the word, no punctuation".

      * Отсутствие данных в поле: Нода ИИ вернула пустой результат или ошибку API, и Switch не знает, что маршрутизировать. Решение: добавьте ноду IF перед Switch, чтобы проверить поле на наличие данных (Exists), и направьте пустые запросы на ноду Error Trigger или в отдельный лог ошибок.

=== Практическое задание ===

      * Создайте сценарий, который принимает запрос от пользователя через Webhook.

      * Используйте ноду AI Agent (с подключенной под-нодой OpenAI Chat Model) для определения, является ли сообщение "вопросом по тарифу" или "отзывом".

      * Настройте ноду Switch так, чтобы при определении категории "отзыв" данные уходили в Google Таблицу (через ноду Google Sheets), а при определении "вопрос по тарифу" — отправлялись в Telegram (через ноду Telegram).

      * Проверьте работу сценария, отправив два разных текста через Postman, и убедитесь, что данные попадают в разные конечные ноды.

=== Генерация контента через OpenAI: принципы работы ===

Интеграция с OpenAI в n8n работает как посредник между входными данными (Webhook) и алгоритмом обработки естественного языка. Вы передаете текст в модель через API, указываете системную инструкцию (System Prompt), а модель возвращает структурированный ответ, который затем парсится (разбирается) нодами для дальнейших действий.

Технически это происходит так: текст из Webhook упаковывается в JSON-объект, отправляется на сервер OpenAI, где обрабатывается нейросетью согласно заданным вами параметрам (температура, модель), и возвращается обратно в n8n как массив данных, доступных для использования в следующих узлах сценария.

=== Интерфейс и настройка цепочки Advanced AI ===

      * AI Agent + OpenAI Chat Model: Основная связка для работы. На холст выносится управляющая нода AI Agent, а к порту Model подключается под-нода OpenAI Chat Model.

      * Credentials: В настройках под-ноды OpenAI Chat Model выберите ваш API-ключ.

      * Model (Модель): В под-ноде OpenAI Chat Model выберите gpt-4o-mini.

      * System Message (в ноде AI Agent): Поле для ввода жесткой инструкции промпта. Пример: "Ты классификатор. Анализируй текст и ответь строго одним словом: 'тариф' или 'отзыв'".

      * Prompt / Input Text (в ноде AI Agent): Сюда через Expression передается текст, пришедший из ноды Webhook.

      * Temperature (в под-ноде модели): Установите на 0 для предсказуемости, чтобы исключить вариативность и сделать ответы ИИ предсказуемыми.

=== Логика передачи данных в ноду Switch ===

После получения ответа от OpenAI, данные сохраняются в объекте JSON. Чтобы направить их в Switch:

      * Откройте настройки ноды Switch.

      * В поле Data Type выберите String.

      * В поле Value 1 вставьте выражение, ссылающееся на поле ответа ИИ (обычно это {{ $json.output }}).

      * В разделе Rules выберите String -> Equal.

      * Для правила 1 укажите значение тариф и направьте поток в Telegram.

      * Для правила 2 укажите значение отзыв и направьте поток в Google Sheets.

=== Пошаговая настройка цепочки ===

      * В рабочей области n8n перетащите ноду Webhook. В поле HTTP Method выберите POST. Скопируйте Test URL для вставки в Postman.

      * Добавьте ноду AI Agent с под-нодой OpenAI Chat Model, соедините её с Webhook. В настройках Prompt нажмите на иконку шестеренки рядом с полем ввода и выберите Add Expression. В открывшемся окне перетащите переменную body из входных данных Webhook.

      * Добавьте ноду Switch. В поле Data Type выберите String. В поле Value 1 через Expression выберите путь: {{ $json.output }}.

      * В разделе Rules нажмите Add Rule дважды. В первом правиле выберите Equals и впишите тариф. Во втором — Equals и впишите отзыв.

      * К выходам Switch (названным согласно правилам) подключите соответствующие ноды: Telegram (отправка сообщения) и Google Sheets (добавление строки).

=== Технические причины сбоев и методы устранения ===

      * Несоответствие формата ответа: OpenAI может добавить лишние пробелы или точки в ответ. 
    Решение: В поле System Message добавьте инструкцию: "Ответь строго одним словом без знаков препинания и пробелов: 'тариф' или 'отзыв'". В ноде Switch используйте функцию .trim() в выражении (например, {{ $json.output.trim() }}).

      * Тайм-аут API: Модель долго генерирует ответ, и Webhook закрывает соединение. 
    Решение: В настройках ноды Webhook установите параметр Respond в режим Immediate Response, чтобы не ждать окончания обработки сценария.

      * Отсутствие данных на входе: Если в Webhook не пришло поле с текстом, нода AI Agent выдаст ошибку 400. 
    Решение: Добавьте ноду If сразу после Webhook. Проверьте наличие ключа body.message. Если он пуст — направьте поток в Error Trigger или ноду HTTP Respond с кодом 400.

=== Практическое задание для закрепления ===

=== Принцип работы HTTP Request для взаимодействия с LLM ===

Внешние языковые модели (Mistral, Claude, Gemini) предоставляют доступ к своим мощностям через API. Для взаимодействия с ними в n8n не используются специализированные ноды, а применяется универсальная нода HTTP Request. По сути, это отправка структурированного JSON-запроса на определенный адрес (Endpoint) провайдера с передачей уникального ключа доступа в заголовках (Headers). Ответ от сервера приходит в том же формате, который затем парсится для извлечения текстового результата.

=== Интерфейс и настройка ноды HTTP Request ===

Для подключения сторонней модели в n8n необходимо выполнить следующие действия в интерфейсе ноды HTTP Request:

      * Method: Выбирается POST, так как мы отправляем данные для обработки.

      * URL: Указывается адрес API провайдера (например, https://api.anthropic.com/v1/messages для Claude или https://generativelanguage.googleapis.com/... для Gemini).

      * Authentication: Выбирается тип Header Auth. В поле Name вводится ключ авторизации (например, x-api-key для Claude), а в Value — токен, полученный в личном кабинете разработчика модели.

      * Send Body: Устанавливается значение true.

      * Body Parameters: Выбирается формат JSON. В открывшемся поле ввода формируется тело запроса. Оно строго соответствует документации API конкретной модели и обычно содержит параметры model (название версии ИИ) и messages (массив объектов с текстом пользователя).

      * Response Format: Устанавливается JSON, чтобы n8n автоматически преобразовал ответ сервера в объект, доступный для дальнейшей обработки в следующих нодах сценария.

Важно: каждая модель имеет уникальную структуру JSON-запроса. Перед заполнением поля Body необходимо открыть документацию API (например, API Reference для Gemini) и скопировать структуру тела запроса, заменив статические данные на динамические переменные из предыдущих нод через выражение {{ $json.message }}.

=== Пошаговая настройка интеграции (на примере Anthropic Claude) ===

      * Откройте редактор n8n, перетащите на рабочее поле ноду HTTP Request.

      * В параметре Method выберите POST.

      * В поле URL вставьте официальный API endpoint (например, https://api.anthropic.com/v1/messages).

      * Перейдите в раздел Authentication, выберите Header Auth, нажмите Create New Credential. В поле Name введите x-api-key, в Value — ваш секретный токен из консоли разработчика.

      * В поле Send Body поставьте true, выберите формат JSON.

      * В поле JSON Parameters нажмите Add Option -> Body Parameters. Нажмите кнопку Add Field, выберите тип Object, назовите его messages, добавьте внутрь строку content и вставьте переменную из предыдущего узла через выражение {{ $json.text }}.

      * Нажмите Execute Node для проверки связи.

=== Типичные ошибки и методы их устранения ===

      * Ошибка 401 Unauthorized: Возникает из-за неверного ключа или ошибки в названии заголовка. Решение: Проверьте в разделе Authentication, совпадает ли имя заголовка с тем, что требует документация API конкретного сервиса.

      * Ошибка 400 Bad Request (Malformed JSON): Возникает при нарушении структуры JSON-тела. Решение: Убедитесь, что все открывающие скобки { имеют соответствующие закрывающие }, а вложенные массивы данных соответствуют формату, указанному в документации провайдера.

      * Ошибка 429 Too Many Requests: Возникает при исчерпании лимитов на количество запросов в минуту. Решение: Добавьте ноду Wait перед HTTP Request, чтобы принудительно замедлить выполнение сценария.

=== Практическое задание ===

      * Зарегистрируйтесь в консоли Google AI Studio, получите API Key для модели Gemini.

      * Добавьте ноду HTTP Request в свой текущий сценарий после получения сообщения из Telegram.

      * Настройте ноду так, чтобы текст из Telegram передавался в параметр parts (текстовое сообщение) модели Gemini.

      * Используйте ноду Edit Fields (Set) после HTTP Request, чтобы извлечь только текст ответа из длинного JSON-ответа, который присылает сервер.

      * Соедините выход этой ноды с нодой Telegram (Send Message), чтобы бот отвечал пользователю сгенерированным текстом.

      * Протестируйте сценарий, отправив боту произвольный вопрос, и убедитесь, что в Telegram приходит ответ от модели.

НАЗВАНИЕ: Урок 5.7. Проект: «Умный секретарь» (бот читает вопрос, GPT отвечает)
==================================================

=== 1. Суть инструмента: HTTP-запросы и JSON ===

В рамках проекта «Умный секретарь» n8n выступает в роли посредника между Telegram и нейросетью Gemini. Механизм работы основан на протоколе HTTP: когда бот получает ваше сообщение, он отправляет его на сервер Google в виде структурированного пакета данных (JSON). Этот пакет содержит ваш вопрос, инструкции для модели и API-ключ для авторизации.

Сервер обрабатывает запрос и возвращает ответ также в формате JSON — это многоуровневая структура данных, где полезный текст скрыт внутри вложенных массивов и объектов. Задача инженера — правильно настроить отправку данных и выделить нужную текстовую строку из полученного массива для последующей отправки пользователю.

=== 2. Разбор интерфейса и логики нод ===

      * HTTP Request (Метод POST): Основной узел для передачи данных. В поле URL вставляется адрес API Google. В разделе Send Body необходимо выбрать тип JSON. В поле Body Parameters создается структура, соответствующая спецификации API: ключ contents, содержащий массив объектов с вложенным ключом parts и массивом text.

      * Authentication: В настройках ноды HTTP Request выбирается тип Header Auth. Вы добавляете заголовок x-goog-api-key, куда вставляете полученный ранее ключ. Это авторизует ваш запрос на стороне Google.

      * Edit Fields (Set): Эта нода используется для «фильтрации» ответа. После выполнения запроса нода HTTP Request выведет массив данных. В поле Mapping Mode вы используете путь к данным: json.candidates[0].content.parts[0].text. Это извлекает только сгенерированный текст из технического ответа сервера.

      * Telegram (Send Message): Финальная точка сценария. В поле Chat ID используется переменная {{$json.message.chat.id}} из триггера Telegram, а в поле Text подставляется результат обработки из ноды Edit Fields.

      * Execution (Запуск): Кнопка Execute Workflow в верхней панели n8n запускает процесс. При возникновении ошибки нода подсвечивается красным — при клике на неё в правой панели отображается системный лог с кодом ошибки (например, 401 Unauthorized при неверном ключе или 400 Bad Request при ошибке в структуре JSON).

=== 1. Пошаговая практическая настройка ===

      * Откройте редактор n8n, нажмите кнопку + в конце цепочки и выберите ноду HTTP Request.

      * В поле Method выберите POST. В поле URL вставьте: https://generativelanguage.googleapis.com/v1beta/models/gemini-1.5-flash:generateContent?key=ВАШ_API_KEY.

      * Нажмите Send Body -> JSON. В блоке Body Parameters нажмите Add Field, выберите Add JSON. Вставьте конструкцию: {"contents": [{"parts": [{"text": "Текст вопроса"}]}]}. Замените "Текст вопроса" на выражение {{$json.message.text}}, выбрав его из выпадающего списка переменных Telegram.

      * Добавьте ноду Edit Fields (Set). Нажмите Add Field -> String. В поле Name напишите answer. В поле Value нажмите на иконку шестеренки -> Add Expression. В появившемся окне найдите в списке выходных данных ноды HTTP Request путь: candidates -> 0 -> content -> parts -> 0 -> text.

      * Добавьте ноду Telegram, действие Send Message. В Chat ID выберите переменную {{$json.message.chat.id}} из триггера. В Text выберите переменную {{$json.answer}} из ноды Edit Fields.

=== 2. Ошибки и методы их устранения ===

      * Ошибка 401 (Unauthorized): Проблема в API-ключе. Решение: Проверьте, что ключ вставлен целиком в URL или в заголовок без лишних пробелов или спецсимволов. Пересоздайте ключ в Google AI Studio, если статус не меняется.

      * Ошибка 400 (Bad Request): Ошибка в структуре JSON. Решение: Убедитесь, что JSON в ноде HTTP Request валиден (все кавычки закрыты, структура вложенности contents -> parts -> text соблюдена). Если используется выражение, убедитесь, что оно обернуто в двойные кавычки.

      * Ошибка 500 (Internal Server Error): Переполнение или сбой модели. Решение: Нажмите кнопку Execute Node отдельно на HTTP Request, чтобы увидеть детали ошибки в правой панели. Часто это означает, что модель заблокировала запрос из-за нарушения политики безопасности или превышения лимитов квоты в консоли Google.

=== 3. Практическое задание ===

      * Создайте «режим эха» внутри ноды Edit Fields: добавьте второе поле, которое к ответу нейросети добавляет приписку (Отвечено моделью Gemini) через оператор конкатенации в выражении (Expression Editor).

      * Протестируйте сценарий: отправьте боту длинный вопрос, содержащий более 20 слов, чтобы проверить, корректно ли нода Edit Fields извлекает полный объем текста без обрезания.

      * Переименуйте все ноды в сценарии (кнопка карандаша в заголовке ноды), чтобы они логически назывались: «Telegram Trigger», «Gemini API», «Extract Text», «Send to User».

НАЗВАНИЕ: Урок 5.8. Работа с аудио: подключение Whisper API для распознавания голосовых сообщений
==================================================

=== Суть инструмента: распознавание аудиосообщений через OpenAI Whisper API ===

В современной автоматизации n8n часто приходится работать не только с текстовыми сообщениями, но и с бинарными файлами (Binary Data), такими как голосовые сообщения (Voice) из Telegram. Чтобы ИИ мог обработать такое сообщение, его необходимо транскрибировать — перевести аудио в текстовый формат.

Для решения этой задачи используется связка n8n с OpenAI Whisper API. Сценарий n8n получает бинарный файл аудио от Telegram Trigger, отправляет его с помощью универсальной ноды HTTP Request на эндпоинт Whisper API (https://api.openai.com/v1/audio/transcriptions), получает текстовую расшифровку и передает её дальше в ИИ-агенты или CRM.

=== Интерфейс и логика работы с бинарными данными ===

      * Telegram Trigger (Скачивание файлов): Чтобы n8n получил не просто техническую ссылку на аудиозапись, а сам файл голосового сообщения, в настройках ноды Telegram Trigger необходимо активировать опцию Download files. После этого аудиофайл сохраняется в оперативной памяти сценария как бинарный объект.

      * HTTP Request (Настройка Multipart POST): Для отправки файла в Whisper API нода HTTP Request должна быть сконфигурирована следующим образом:

              * Method: POST

              * URL: https://api.openai.com/v1/audio/transcriptions

              * Authentication: Header Auth (заголовок Authorization со значением Bearer [ваш_API_ключ]).

              * Send Body: Включено.

              * Body Content Type: Multipart-Form Data (этот тип обязателен для передачи файлов).

              * Body Parameters: 

                      * Ключ file: Тип параметра устанавливается в Binary, а в значении указывается имя бинарного свойства из предыдущего шага (обычно это data).

                      * Ключ model: Тип String, значение whisper-1.

=== Пошаговая настройка цепочки ===

      * Добавьте ноду Telegram Trigger. Укажите ваш API-токен бота. В поле Updates выберите message. Перейдите во вкладку Options и включите Download Files.

      * Отправьте голосовое сообщение вашему Telegram-боту, чтобы n8n зафиксировал структуру входящих данных. Убедитесь, что в панели ввода n8n появился бинарный объект во вкладке Binary (с именем data и типом audio/ogg).

      * Добавьте ноду HTTP Request после Telegram Trigger. Настройте параметры: URL https://api.openai.com/v1/audio/transcriptions, Method POST.

      * Включите Header Auth и передайте ваш ключ OpenAI API (значение: Bearer [ваш_API_ключ]).

      * Включите Send Body, выберите тип Multipart-Form Data.

      * Добавьте параметр model со значением whisper-1 (тип String).

      * Добавьте параметр file, переключите его тип в Binary, а в значении введите имя бинарного свойства из Telegram Trigger (например, data).

      * Нажмите Execute Node. В ответ API вернет JSON с текстовой расшифровкой в свойстве text.

      * Добавьте в конец ноду Telegram (Send Message). В поле Text через Expression сошлитесь на распознанный текст: {{ $json.text }}, чтобы бот отправил расшифровку обратно пользователю.

=== Типичные ошибки и методы отладки ===

      * Превышение размера файла (File too large): Whisper API имеет лимит на размер одного аудиофайла в 25 МБ. При превышении лимита API вернет ошибку 400. Решение: Добавьте проверку размера файла на шаге перед отправкой или используйте сжатие аудио.

      * Неверное имя бинарного свойства (Binary property mismatch): HTTP Request возвращает ошибку, если в поле file указано неверное имя свойства. Решение: Внимательно проверьте имя бинарного ключа во вкладке Binary ноды-триггера Telegram и укажите его символ в символ (по умолчанию data).

      * Ошибка mime-type (Telegram .ogg формат): Telegram записывает голосовые сообщения в формате `.ogg` (с кодеком Opus). Whisper полностью поддерживает этот формат, но n8n должен передать правильный mime-type в заголовках multipart формы. Как правило, n8n делает это автоматически, если бинарный файл скачан напрямую через триггер.

=== Практическое задание ===

      * Собрайте в n8n работающий сценарий: Telegram Trigger (с загрузкой файлов) -> HTTP Request (Whisper API) -> Telegram (Send Message).

      * Отправьте в своего бота короткое голосовое сообщение (например, "Проверка связи для искусственного интеллекта").

      * Убедитесь, что бот в течение нескольких секунд успешно распознал аудиозапись и прислал её текстовую расшифровку вам в ответ.

      * Сделайте скриншот успешного выполнения цепочки в панели Execution History, где виден распознанный текст.

НАЗВАНИЕ: Урок 6.1. Airtable как база данных для автоматизации: подключение и работа
==================================================

=== 1. Суть инструмента: Airtable как структурированное хранилище ===

Airtable — это реляционная база данных с графическим интерфейсом, представленная в виде таблиц. В контексте автоматизации n8n, Airtable выступает как хранилище данных (состояний), где каждая строка является записью (record), а столбцы — полями с жестко заданным типом данных (текст, число, дата, чекбокс).

Принципиальное отличие от Excel заключается в наличии API-ключа и уникального идентификатора таблицы (Table ID), которые позволяют n8n обращаться к конкретным ячейкам, обновлять их или создавать новые записи без прямого участия пользователя в интерфейсе самого Airtable.

=== 2. Интерфейс и логика интеграции в n8n ===

Для работы Airtable в n8n используются следующие технические компоненты:

      * Credential (Учетные данные): В меню «Credentials» необходимо создать запись типа «Airtable API». Для авторизации используется Personal Access Token, генерируемый в настройках профиля Airtable. Он предоставляет право на чтение и запись в конкретные базы (Base).

      * Node Airtable: Основной инструмент для взаимодействия. Внутри ноды присутствуют следующие параметры:

              * Operation: Выбор действия — «Create» (создать строку), «Get» (получить данные), «Update» (изменить существующую запись) или «List» (вывести все записи).

              * Base ID: Уникальный идентификатор базы, отображается в URL вашего браузера при открытии таблицы (начинается с app...).

              * Table Name: Точное имя таблицы внутри базы. Регистр имеет значение.

      * Mapping Fields: После выбора таблицы, n8n автоматически подгружает список доступных колонок. Вы используете кнопку «Add Field» для сопоставления данных, пришедших из предыдущих нод (например, из Telegram или Gemini), с конкретными колонками в Airtable.

      * Filter/Query (при операции List): Позволяет задать условие выборки через формулу Airtable, например, {Статус} = 'В работе', чтобы отфильтровать записи на стороне базы перед передачей данных в n8n.

=== 1. Пошаговая инструкция по настройке ===

      * Откройте Airtable в браузере, создайте новую базу и переименуйте колонки: «Message» (тип Single line text) и «Status» (тип Single select).

      * В n8n перетащите ноду Airtable на рабочее поле.

      * Нажмите на поле Credential — Create New. Вставьте Personal Access Token, полученный в разделе Developer Hub вашего аккаунта Airtable.

      * В параметре Operation выберите «Create».

      * В поле Base выберите созданную базу из выпадающего списка. Аналогично выберите Table.

      * Нажмите кнопку Add Field, выберите «Message». Нажмите на иконку шестеренки справа от поля ввода — Expression. В открывшемся окне перетащите переменную с текстом из предыдущей ноды (например, из Telegram Trigger).

      * Нажмите Execute Node для отправки тестовой строки в базу.

=== 2. Ошибки и методы их устранения ===

      * Ошибка 404 (Table/Base not found): Возникает, если вы изменили название таблицы в интерфейсе Airtable, а n8n продолжает искать старое имя. Решение: Перезайдите в настройки ноды Airtable и обновите выбор Table в выпадающем списке.

      * Ошибка 403 (Permission denied): Возникает, если у токена доступа нет прав на чтение/запись конкретной базы. Решение: В настройках API в Airtable убедитесь, что вы выдали токену (Scopes) права data.records:write и data.records:read, а также добавили конкретную базу в разделе Access.

      * Ошибка типа данных (Invalid Value): Возникает при попытке записать текст в поле типа «Single select», если такого значения еще нет в списке. Решение: Заранее создайте все варианты выбора (опции) в самой таблице Airtable через интерфейс или убедитесь, что вводимый текст идентичен существующему варианту.

=== 3. Практическое задание ===

      * Создайте цепочку: Telegram Trigger -> Airtable (Create).

      * Настройте запись так, чтобы каждое сообщение из Telegram сохранялось в Airtable в колонку «Message».

      * Добавьте вторую ноду Airtable (операция Update), которая срабатывает сразу после записи: она должна менять статус в колонке «Status» на значение «Processed». Для этого вам потребуется поле Record ID, которое передается в качестве выходного параметра первой ноды Airtable.

      * Проверьте результат в интерфейсе Airtable: после выполнения сценария строка должна появиться и мгновенно изменить статус с пустого на «Processed».

НАЗВАНИЕ: Урок 6.2. Notion + n8n: автоматическое ведение задач и баз знаний
==================================================

=== 1. Суть связки Notion и n8n ===

Notion выступает в роли структурированной базы данных (объекта), где каждая запись — это страница с набором свойств. n8n — это серверный оркестратор, который с помощью API-запросов отправляет данные в Notion или забирает их оттуда. Работа строится на JSON-структурах: n8n преобразует входящую информацию (текст, даты, чек-листы) в формат, понятный Notion, и через метод POST или PATCH обновляет записи в вашей базе.

=== 2. Интерфейс и логика настройки ===

Для интеграции в n8n используются следующие технические компоненты:

      * Notion Trigger: Нода, работающая в режиме вебхука или опроса. Она отслеживает событие "Database Item Updated" или "Database Item Created" в Notion. Важно: для работы ноды необходимо добавить интеграцию n8n в меню "Connections" внутри конкретной страницы Notion.

      * Notion (Resource & Operation): Основной узел для манипуляции данными. Вы выбираете Resource: Database Page и Operation: Create или Update.

      * Mapping (Сопоставление данных): В интерфейсе n8n вы увидите кнопку "Add Field". Она открывает список свойств, которые есть в вашей таблице Notion (например, Select, Multi-select, Date, Text). Вы перетаскиваете данные из предыдущей ноды в эти поля.

      * Property ID: Каждый объект в Notion имеет уникальный идентификатор. В n8n он передается через системную переменную Page ID. При обновлении записи (Update) это поле является обязательным для указания того, какую именно строку нужно изменить.

      * Authentication: В настройках ноды используется "Notion API Key". Он генерируется в панели разработчика Notion и вставляется в поле Credentials в n8n для авторизации каждого запроса.

=== 1. Пошаговая инструкция настройки ===

      * В рабочем пространстве n8n выберите ноду Notion. В поле Credential выберите созданный ранее ключ интеграции.

      * В поле Resource установите значение Database Page, в поле Operation — Create.

      * В поле Database ID нажмите на кнопку поиска (лупа) или вставьте ID из URL страницы Notion. После этого нажмите кнопку Add Field и выберите из списка названия столбцов вашей базы (например, «Name» или «Status»).

      * Перетащите мышью необходимые переменные (например, из Telegram или Google Sheets) в соответствующие поля Notion внутри ноды.

      * Нажмите кнопку Execute Node. Если в интерфейсе Notion появилась новая строка — конфигурация верна.

=== 2. Ошибки и методы их устранения ===

      * Ошибка прав доступа (403 Forbidden): Возникает, если вы добавили API-ключ в n8n, но не «поделились» базой данных с интеграцией. Решение: в интерфейсе Notion нажмите кнопку Share (три точки в правом верхнем углу) и выберите вашу интеграцию из списка, предоставив ей права редактирования.

      * Несоответствие типов данных: Ошибка возникает, если вы пытаетесь записать текст в поле типа Select (выпадающий список) или Date. Решение: убедитесь, что в n8n выбран корректный тип поля. Если поле требует выбора из списка, используйте функцию выражения (Expression) или убедитесь, что передаваемая строка точно совпадает с вариантом в Notion.

      * Отсутствие Page ID при обновлении: При операции Update нода возвращает ошибку, если поле Page ID пустое. Решение: убедитесь, что нода, стоящая перед Notion, передает ID созданной страницы. Используйте поле Expression для выбора переменной {{ $json.id }} из предыдущего шага.

=== 3. Практическое задание ===

      * Создайте базу данных в Notion с колонками: «Task Name» (Title), «Deadline» (Date) и «Status» (Status).

      * Настройте автоматизацию: при получении сообщения в Telegram нода Notion должна создавать новую строку в этой базе, устанавливая «Task Name» равным тексту сообщения.

      * Добавьте вторую ноду Notion с операцией Update: она должна автоматически менять статус задачи в Notion на «Done» сразу после того, как запись была успешно создана.

      * Проверьте корректность записи: статус в Notion должен смениться на «Done» в течение 2-3 секунд после появления строки.

НАЗВАНИЕ: Урок 6.3. Email-автоматизация: Gmail / SMTP — парсинг писем и автоответы
==================================================

=== 1. Суть email-автоматизации в n8n ===

Автоматизация почтовых рассылок и обработки входящих сообщений базируется на протоколах IMAP (для получения писем) и SMTP (для отправки). В n8n нода Gmail или стандартная нода IMAP/SMTP выступает как посредник, который циклично опрашивает почтовый сервер на наличие новых сообщений по заданным фильтрам (отправитель, тема, наличие вложений) или инициирует отправку данных из внешних сервисов.

При получении письма нода преобразует его содержимое из сырого формата (MIME) в JSON-объект. Это позволяет извлекать из письма ключевые параметры: адрес отправителя, тему, тело письма (в текстовом или HTML-формате) и метаданные вложений для последующей передачи в другие сервисы.

=== 2. Разбор интерфейса и логики нод ===

Для работы с почтой в n8n используются следующие функциональные узлы и настройки:

      * Нода Gmail / IMAP Trigger: Используется для прослушивания входящих событий. Основные поля настройки:

              * Credential: Выбор авторизованного подключения (OAuth2 для Gmail или логин/пароль для SMTP).

              * Resource: Выбор операции (например, Message для работы с письмами).

              * Operation: Выбор действия (Get, GetAll, Send).

              * Query: Поле для ввода параметров поиска (например, is:unread для обработки только непрочитанных писем).

      * Логика парсинга данных:

              * После получения письма данные отображаются в окне Input/Output.

              * Для извлечения текста используйте поле Expression. Путь к данным в JSON выглядит как {{ $json.snippet }} для краткого содержания или {{ $json.textHtml }} для полного текста письма.

      * Нода Email (SMTP): Используется для отправки ответов.

              * To: Поле для указания адресата (можно подставить переменную {{ $json.from.address }} из предыдущего шага, чтобы ответить отправителю).

              * Subject: Тема ответного письма.

              * Text / HTML: Основное тело сообщения. Здесь допустимо использование переменных n8n для динамической генерации текста на основе данных из входящего письма.

=== 1. Пошаговая инструкция по настройке ===

      * Нажмите кнопку Add Node и выберите Gmail Trigger. В поле Credential выберите созданное подключение к вашему почтовому аккаунту.

      * В поле Event установите значение Message Received. В разделе Options добавьте фильтр Label, указав «INBOX», чтобы считывать только входящие.

      * Добавьте вторую ноду Gmail и выберите операцию Send.

      * В поле To нажмите на иконку шестеренки (Expression) и перетащите из панели данных слева поле from -> value из предыдущей ноды Gmail Trigger.

      * В поле Subject введите «Автоответ: задача получена».

      * В поле Text используйте выражение Здравствуйте, мы получили ваше письмо с темой: {{ $json.subject }}. Нажмите кнопку Test Step для отправки пробного письма.

=== 2. Ошибки и их решение ===

      * Ошибка авторизации (401 Unauthorized): Возникает при истечении срока действия токена. Решение: зайдите в раздел Credentials в меню n8n, выберите ваш аккаунт Gmail и нажмите Reconnect для обновления прав доступа через браузер.

      * Отсутствие данных в переменных: Происходит, если структура письма отличается от ожидаемой (например, письмо пустое). Решение: добавьте ноду If после триггера, чтобы проверять наличие поля textHtml перед передачей данных в следующую ноду.

      * Зацикливание (Infinite Loop): Если ваш автоответ вызывает новый триггер (например, вы настроили пересылку). Решение: добавьте фильтр в Gmail Trigger Query: -from:ваш-email@gmail.com, чтобы исключить собственные исходящие письма из обработки.

=== 3. Практическое задание ===

      * Настройте цепочку: Gmail Trigger -> Использовать ноду Set (для фильтрации темы письма) -> Gmail Send.

      * В ноде Set создайте переменную «TaskStatus» со значением «In Progress».

      * Настройте отправку письма-подтверждения, в теле которого будет написано: «Статус вашего запроса: {{ $json.TaskStatus }}».

      * Отправьте письмо на свой ящик с любого другого адреса. Убедитесь, что в полученном ответе статус отображается корректно.

      * В интерфейсе n8n перейдите во вкладку Executions и проверьте логи выполнения, чтобы убедиться, что ошибки (красные индикаторы) отсутствуют.

НАЗВАНИЕ: Урок 6.4. Webhook-интеграции: как принимать данные от любого сервиса
==================================================

=== 1. Суть Webhook-интеграций ===

Webhook — это механизм передачи данных в реальном времени между двумя системами по протоколу HTTP. В контексте n8n Webhook выступает в роли «слушателя» или точки входа (URL-адреса), который ожидает поступления данных от внешнего сервиса. Когда стороннее приложение отправляет HTTP POST-запрос на этот адрес, n8n мгновенно активирует ваш рабочий процесс и принимает входящие данные в формате JSON.

В отличие от триггеров типа «опрос» (Polling), которые проверяют наличие изменений через фиксированные интервалы времени, Webhook инициируется событием на стороне отправителя. Это обеспечивает минимальную задержку между возникновением события и запуском автоматизации.

=== 2. Интерфейс и логика настройки в n8n ===

Для работы с входящими данными в n8n используется нода Webhook. Порядок действий при настройке:

      * Добавление ноды: В редакторе сценариев нажмите кнопку «+», введите в поиске «Webhook» и перетащите ноду на рабочее поле.

      * Тип запроса (HTTP Method): В настройках ноды выберите метод POST. Этот метод используется для передачи данных в теле запроса.

      * Путь (Path): Укажите уникальный идентификатор пути (например, my-incoming-data). Он станет частью URL-адреса, на который сторонний сервис будет отправлять данные.

      * Параметры URL: n8n сгенерирует два адреса: Production URL (для рабочих процессов) и Test URL (для отладки). При настройке интеграции на стороне другого сервиса используйте именно эти ссылки.

      * Режим ожидания: Нажмите кнопку Execute Node. n8n перейдет в режим ожидания (Waiting). После этого совершите тестовое действие в стороннем сервисе (отправьте данные). Как только данные будут получены, нода отобразит структуру JSON-объекта во вкладке Output.

      * Обработка данных: Все принятые данные будут доступны в последующих нодах через выражение {{ $json.имя_поля }}. Если отправитель присылает сложные структуры, используйте ноду Set или Edit Fields для приведения данных к нужному формату перед их передачей в следующие сервисы.

=== 1. Пошаговая инструкция по настройке ===

      * Создайте новый Workflow в n8n. Добавьте ноду Webhook.

      * В поле HTTP Method выберите POST. В поле Path введите test-receiver.

      * Скопируйте адрес из поля Test URL.

      * Откройте сервис, который будет отправлять данные (например, Postman или форму на сайте). Вставьте скопированный URL в поле адреса запроса (Endpoint).

      * Вернитесь в n8n и нажмите кнопку Execute Node. Статус ноды изменится на «Waiting for Webhook call».

      * Отправьте запрос из внешнего сервиса. В интерфейсе n8n нода сменит статус на «Success», а во вкладке JSON вы увидите структуру пришедших данных.

      * Подключите следующую ноду (например, Google Sheets или Slack) к выходу Webhook-ноды, чтобы передать полученные параметры дальше.

=== 2. Ошибки и методы их устранения ===

      * Ошибка 404 (Not Found): Чаще всего возникает, если вы отправили данные на Test URL, когда нода не находится в режиме ожидания (Execute Node не запущен). Решение: всегда нажимайте «Execute Node» перед отправкой тестового запроса.

      * Ошибка 405 (Method Not Allowed): Вы пытаетесь отправить данные методом GET, хотя в ноде настроен POST. Решение: проверьте настройки метода в отправляющем сервисе и в ноде Webhook (они должны совпадать).

      * Отсутствие данных в структуре: Внешний сервис отправил данные в формате JSON, но вы используете неверный путь (Key) в следующей ноде. Решение: проверьте вкладку Output ноды Webhook, скопируйте имя нужного ключа оттуда и используйте его через $json.имя_ключа в ноде Set.

=== 3. Практическое задание ===

      * Создайте цепочку: Webhook -> Set -> HTTP Request (отправка ответа обратно).

      * В ноде Set создайте поле «Message» со значением «Данные получены: {{ $json.body.user_name }}» (где user_name — поле из вашего входящего запроса).

      * Запустите выполнение ноды Webhook.

      * Отправьте с помощью стороннего сервиса (например, Postman) POST-запрос с JSON-объектом: {"user_name": "TestUser"}.

      * Убедитесь, что в логах выполнения n8n нода Set корректно сформировала текст с именем, переданным из внешнего источника.

      * Проверьте вкладку Executions, чтобы убедиться, что все узлы цепочки подсвечены зеленым цветом.

НАЗВАНИЕ: Урок 6.5. Работа с файлами: загрузка, чтение PDF, отправка в облако
==================================================

=== Работа с файловыми данными в n8n ===

В n8n файлы обрабатываются не как простой текст, а как бинарные данные (Binary Data). Каждый файл в системе состоит из двух частей: метаданных (имя, тип файла, размер) и содержимого, хранящегося в памяти или временном хранилище. Для чтения содержимого PDF-документов используется специализированная библиотека внутри ноды, которая извлекает текстовый слой из бинарного потока.

Процесс автоматизации строится на цепочке: прием файла (через Webhook или HTTP Request) -> обработка нодой "Read Binary File" или "Extract from File" -> передача содержимого в облачное хранилище или LLM-модель.

=== Интерфейс и настройка узлов ===

      * Binary Data в нодах: В интерфейсе любой ноды, принимающей файл, появляется раздел "Binary Property". По умолчанию поле называется data. Это системный идентификатор файла, который вы должны указывать в последующих нодах для обращения к контенту.

      * Нода "Read PDF": 

              * Поле Binary Property: укажите имя ключа (например, data), в котором содержится файл.

              * Поле Options: здесь настраивается диапазон страниц для чтения. Оставьте пустым, если нужно извлечь текст из всего документа.

      * Меню "Binary Data" (вкладка ноды): В левом нижнем углу интерфейса n8n после запуска ноды отображается панель с иконкой скрепки. Там видны технические параметры: MIME type (например, application/pdf) и размер файла. Если эта вкладка пуста — файл не был успешно передан в ноду.

      * Нода "HTTP Request" (для отправки в облако):

              * Вкладка Send Binary Data: переключите тумблер в состояние ON.

              * Binary Property: укажите идентификатор файла, который был сформирован на предыдущем этапе.

              * Если облачное хранилище требует форму (multipart/form-data), используйте опцию Send Request Body и выберите формат Multipart, добавив ключ файла в поле Binary Parameters.

=== Пошаговая настройка цепочки обработки файла ===

      * Создайте ноду Webhook. В поле HTTP Method выберите POST. В разделе Response Mode выберите On Received.

      * Добавьте ноду Read PDF. В поле Binary Property введите data. Это стандартное имя, под которым Webhook сохраняет входящий файл.

      * Добавьте ноду HTTP Request. В поле Method выберите POST. В поле URL вставьте адрес вашего целевого облачного хранилища.

      * В ноде HTTP Request перейдите во вкладку Send Binary Data, активируйте переключатель и в поле Binary Property впишите data.

      * Соедините узлы стрелками и нажмите кнопку Execute Workflow.

=== Типовые технические сбои и методы устранения ===

      * Ошибка "Binary data property not found": Система не видит файл. 

              * Решение: Проверьте ноду Webhook. В настройках должно быть включено поле Binary Data. Если оно выключено, нода будет игнорировать любые вложения в POST-запросе.

      * Ошибка "Invalid PDF format" или "Empty text": Файл был передан, но нода PDF не смогла извлечь данные. 

              * Решение: Убедитесь, что загружаемый файл является именно PDF-документом с текстовым слоем, а не отсканированным изображением (картинкой в формате PDF). OCR-обработка в базовой ноде не производится.

      * Ошибка 413 "Request Entity Too Large": Сервис облачного хранилища или сам n8n блокирует отправку из-за превышения лимита веса. 

              * Решение: Проверьте параметры лимитов вашего экземпляра n8n (обычно по умолчанию до 50MB). Попробуйте сжать исходный PDF-файл перед отправкой.

=== Практическое задание ===

Для закрепления материала выполните следующие действия в редакторе n8n:

      * Реализуйте цепочку: Webhook -> Read PDF -> Set.

      * В ноде Set создайте поле file_text. В качестве значения выберите данные из ноды Read PDF (используйте визуальный селектор Expression, нажав на иконку шестеренки рядом с полем).

      * Отправьте через Postman (или аналогичный инструмент) любой небольшой PDF-файл (до 1 Мб) через form-data, где ключ файла — data.

      * Откройте вкладку Execution и убедитесь, что в ноде Set в поле file_text отображается весь текстовый контент вашего документа.

==================================================

=== Суть связки: Веб-форма и передача данных ===

Воронка автоматизации начинается с точки сбора данных. Webhook — это технический эндпоинт, который n8n предоставляет для приема входящих HTTP-запросов. Когда пользователь заполняет форму на вашем сайте, данные (имя, телефон, запрос) отправляются по протоколу POST на URL-адрес вашего вебхука. n8n перехватывает этот пакет, преобразует его в JSON-объект и делает доступным для дальнейшей обработки всеми последующими нодами в сценарии.

GPT-квалификация — это следующий этап, где полученные данные передаются через API-запрос к модели OpenAI. Нода HTTP Request отправляет JSON-объект с данными пользователя в систему OpenAI, которая анализирует текст по заданному системному промпту и возвращает структурированный ответ: статус квалификации («лид» или «спам») и резюме интереса клиента.

=== Разбор интерфейса и логика настройки ===

=== 1. Нода Webhook ===

      * HTTP Method: Выберите POST. Это стандарт для отправки данных из форм.

      * Path: Укажите уникальный идентификатор (например, lead-capture), который станет частью URL вашего вебхука.

      * Authentication: Установите в режим None, если форма находится на внешнем сайте.

      * Respond: Выберите «Immediate», чтобы сайт не «зависал» в ожидании ответа от сервера, пока идет анализ GPT.

=== 2. Нода HTTP Request (Интеграция с GPT) ===

      * URL: https://api.openai.com/v1/chat/completions.

      * Method: POST.

      * Authentication: Выберите «Header Auth» (или создайте Credential с названием OpenAI API), добавьте заголовок Authorization со значением Bearer [ваш_API_ключ].

      * Send Body: Включите опцию «Send Body».

      * Body Parameters: В поле JSON вставьте структуру: {"model": "gpt-4o-mini", "messages": [{"role": "user", "content": "Проанализируй данные клиента: {{ $json.body.user_message }}"}]}.

=== 3. Логика работы с данными (Data Flow) ===

      * Переменные: Используйте окно «Expression» для доступа к данным. Для обращения к данным из вебхука в последующих нодах используйте синтаксис {{ $json.body.имя_поля }}.

      * Тестирование: После настройки ноды Webhook перейдите в режим «Listen for Test Event» и отправьте данные через Postman или реальную форму на сайте. Данные отобразятся в нижней части ноды в виде древовидной структуры JSON.

      * Mapping: Чтобы передать результат квалификации из GPT в CRM (например, Airtable или Google Sheets), используйте ноду соответствующего сервиса, где в полях ввода через селектор Expression выберите выходящий объект от ноды HTTP Request.

=== Пошаговая инструкция настройки ===

      * Создание CRM-записи: Добавьте ноду целевой CRM (например, Google Sheets). В поле Operation выберите «Append». В поле Sheet Name укажите имя листа. В разделе Columns нажмите «Add Column» для каждого поля (Имя, Статус, Резюме). В поле значения нажмите иконку шестеренки, выберите Add Expression, в открывшемся окне найдите результат ноды HTTP Request и перетащите нужное поле (например, выборку из choices[0].message.content) в строку выражения.

      * Уведомление в Telegram: Добавьте ноду Telegram. В поле Chat ID вставьте ID вашего чата. В поле Text составьте сообщение с помощью визуального редактора, вставляя переменные из предыдущих нод через перетаскивание (Drag-and-drop) из списка слева в интерфейсе n8n.

      * Активация: Соедините ноды линиями (Nodes connector). Убедитесь, что все ноды подсвечены активным цветом. Нажмите кнопку Execute Workflow для ручной проверки или кнопку Activate в верхнем правом углу для перевода сценария в режим постоянной работы.

=== Почему это ломается: типичные ошибки ===

      * Ошибка 401 Unauthorized в HTTP Request: Происходит, если ключ OpenAI API введен неверно или отсутствует в Credential. Решение: Перейдите в настройки Credentials ноды, удалите старую запись и создайте новую, скопировав API Key напрямую из панели управления OpenAI без пробелов.

      * Ошибка пустых полей в CRM: Возникает, если структура JSON, пришедшая от GPT, не совпадает с тем, что вы указали в Expression. Решение: Откройте вкладку Input в ноде CRM, найдите путь к данным в дереве JSON и обновите выражение в ноде, перетащив ключ заново.

      * Тайм-аут (Timeout): Возникает, если GPT долго отвечает или связь между серверами нестабильна. Решение: Увеличьте значение Timeout в настройках ноды HTTP Request (поле «Options») до 60 секунд.

=== Практическое задание ===

      * Настройте цепочку Webhook -> HTTP Request (GPT) -> Google Sheets -> Telegram.

      * В системном промпте ноды GPT укажите жесткое условие: «Отвечай строго в формате JSON: {"status": "ok", "summary": "..."}».

      * В ноде Google Sheets настройте автоматическое создание строки только в том случае, если поле status равно «ok» (используйте кнопку Add Condition в настройках ноды).

      * Отправьте тестовый запрос через Postman, откройте вкладку Execution и сделайте скриншот успешного прохождения данных через все 4 ноды.

НАЗВАНИЕ: Урок 6.7. Интеграция n8n с Firebase Firestore через HTTP REST API
==================================================

=== Суть инструмента: REST API интеграция n8n с NoSQL БД Firestore ===

Google Firebase Firestore — это облачная гибкая документо-ориентированная NoSQL база данных, которая идеально подходит для хранения пользовательских сессий, стейтов ботов, логов и профилей клиентов. В n8n отсутствует идеальная встроенная нативная нода для прямой интеграции с Firestore. По этой причине стандартом работы является использование универсальной ноды HTTP Request для взаимодействия с базой через официальный REST API Firebase.

Работа по протоколу HTTP REST API обеспечивает максимальную гибкость и контроль: вы можете напрямую отправлять структурированные JSON-запросы для чтения, записи, обновления и удаления документов без ограничений, присущих готовым NoSQL плагинам.

=== Логика формирования URL и методов запросов ===

Взаимодействие с Firestore REST API базируется на отправке запросов по стандартным URL с использованием классических HTTP-методов:

      * Базовый URL для запросов: https://firestore.googleapis.com/v1/projects/{project_id}/databases/(default)/documents/{collection}, где {project_id} — уникальный идентификатор вашего Firebase-проекта, а {collection} — имя целевой коллекции документов (например, users).

      * Методы взаимодействия:

              * POST: Создание нового документа с автогенерацией уникального ID на стороне Firebase.

              * PATCH: Создание или обновление существующего документа по конкретному пути. Используется URL с явным ID документа: .../documents/{collection}/{document_id}.

              * GET: Получение данных конкретного документа по его ID.

              * DELETE: Удаление документа по его ID.

=== Формат структурирования данных (Типизация Firestore) ===

Важнейшая техническая деталь при работе с REST API Firestore — это требование строго типизировать каждое отправляемое поле. Вы не можете просто передать стандартный плоский JSON вроде {"name": "Ivan"}. Каждее поле должно быть явно обернуто в объект с указанием типа данных Firestore:

      * Строка (String): {"name": {"stringValue": "Ivan"}}

      * Целое число (Integer): {"step": {"integerValue": 25}}

      * Булево (Boolean): {"isActive": {"booleanValue": true}}

Пример корректного тела запроса (Body JSON) для создания документа:

{
  "fields": {
    "name": { "stringValue": "Ivan" },
    "telegramId": { "stringValue": "123456789" },
    "step": { "integerValue": 0 }
  }
}

=== Пошаговая настройка записи в Firestore ===

      * Добавьте ноду HTTP Request на рабочее полотно.

      * Установите метод Method: POST (для создания документа) или PATCH (для обновления существующего).

      * В поле URL вставьте адрес эндпоинта, заменив {project_id} на ID вашего проекта из консоли Firebase, а {collection} — на users. Для создания документа с ID пользователя передайте параметр ?documentId={{ $json.message.from.id }} в конце URL (при методе POST).

      * Включите опцию Send Body и установите тип Body Content Type: JSON.

      * В поле Body Parameters укажите JSON-структуру с типизированными полями:

{
  "fields": {
    "username": { "stringValue": "{{ $json.message.from.username }}" },
    "telegram_id": { "stringValue": "{{ $json.message.from.id.toString() }}" },
    "last_active": { "stringValue": "{{ $now.toString() }}" }
  }
}

      * Запустите ноду. В случае успеха Firestore создаст запись и вернет JSON-объект, содержащий системные метаданные документа и его поля.

      * Успешно запустите сценарий через Execute Workflow, отправьте боту сообщение и проверьте в консоли Firebase появление нового документа в вашей коллекции с корректно сохраненными данными пользователя.

НАЗВАНИЕ: Урок 6.8. Разработка State Machine: сохранение шагов диалога Telegram-бота в базу
==================================================

=== Суть инструмента: управление состоянием диалога (State Machine) ===

По умолчанию все чат-боты и интеграции n8n являются stateless (без сохранения состояния). Это значит, что бот обрабатывает каждое сообщение пользователя как первое и уникальное, абсолютно не помня предыдущий контекст диалога. Чтобы создать умный пошаговый опрос (например, Шаг 1: Спросить имя -> Шаг 2: Спросить телефон -> Шаг 3: Спросить email), боту требуется память.

Для реализации такой логики в автоматизации применяется концепция State Machine (Конечный автомат). Текущий шаг пользователя ("стейт" или "step") сохраняется во внешнюю базу данных (например, Cloud Firestore или Google Sheets) с привязкой к его уникальному Telegram User ID. При получении нового сообщения n8n сначала считывает текущий шаг пользователя из базы, а нода Switch направляет сценарий по нужной ветке логики.

=== Архитектура и логика работы State Machine в n8n ===

Многошаговая воронка-опросник строится по следующему логическому циклу:

      * Вход события: Нода Telegram Trigger получает входящее сообщение от пользователя.

      * Запрос стейта (Get State): n8n обращается к базе данных (Firestore через HTTP Request или Google Sheets через Get Row), используя выражение {{ $json.message.from.id }} в качестве ключа поиска.

      * Проверка шага:

              * Если пользователя нет в базе (это его первый запуск): база данных возвращает пустоту или ошибку. Сценарий создает запись пользователя в БД с шагом 0, отправляет приветствие и задает вопрос первого шага (например, "Как вас зовут?"), обновляя стейт на шаг 1.

              * Если пользователь найден: нода Switch считывает значение его шага (например, step = 1).

      * Маршрутизация Switch:

              * При step = 1 (Ожидаем имя): Сценарий сохраняет пришедший текст сообщения как "Имя" в карточку пользователя, отправляет сообщение "Принято! Теперь укажите ваш номер телефона" и обновляет стейт в базе данных на шаг 2.

              * При step = 2 (Ожидаем телефон): Сценарий валидирует телефон, сохраняет его в базу, отправляет сообщение "Спасибо! Регистрация завершена" и переводит шаг пользователя в финальный статус (например, 3 или done).

=== Типичные ошибки разработки конечных автоматов ===

      * Зацикливание (State Lock): Пользователь застревает на одном шаге и бот бесконечно повторяет один и тот же вопрос. Решение: Тщательно проверьте, что в конце каждого шага нода записи в базу данных физически обновляет поле step на следующее значение.

      * Потеря контекста при сбое БД (stateless fallback): Если база данных временно недоступна, сценарий прерывается. Решение: Используйте в настройках ноды получения стейта дефолтное значение (например, через выражение {{ $json.step ? $json.step : 0 }}), чтобы при отсутствии данных опрос всегда начинался сначала.

=== Практическое задание ===

Соберите в n8n работающую интерактивную воронку-опросник из двух шагов:

      * Настройте Telegram Trigger на прием сообщений.

      * Добавьте ноду получения данных из базы (например, Google Sheets Get Row или Firestore GET Document) для поиска пользователя по Telegram ID.

      * Подключите ноду Switch. Настройте правила:

              * Если шаг пустой или равен 0 — отправить сообщение "Привет! Напиши свое имя", создать запись в БД со значением step = 1.

              * Если шаг равен 1 — записать пришедший текст в поле "Имя" пользователя в БД, отправить сообщение "Супер! Теперь напиши свой телефон", обновить статус на step = 2.

              * Если шаг равен 2 — записать текст в поле "Телефон" в БД, отправить сообщение "Регистрация завершена!", обновить статус на step = done.

      * Протестируйте воронку в Telegram от начала до конца и убедитесь, что все шаги переключаются корректно, а данные пользователя сохраняются в базе.

НАЗВАНИЕ: Урок 7.1. Варианты деплоя n8n: обзор облака n8n и Railway

=== Развертывание n8n: Облачный сервис vs Railway ===

n8n Cloud (SaaS): Это управляемая инфраструктура от разработчиков платформы. Вы получаете готовый экземпляр n8n, где техническое обслуживание, обновление версий и обеспечение отказоустойчивости берет на себя провайдер. Доступ осуществляется через авторизованный URL, предоставленный при регистрации.

Railway (PaaS): Это облачная платформа для деплоя контейнеризированных приложений. В отличие от n8n Cloud, вы разворачиваете инстанс n8n самостоятельно. Это дает полный контроль над переменными окружения (Environment Variables), версией движка и базой данных, но требует ручной настройки лимитов памяти и портов.

=== Интерфейс и логика развертывания ===

      * n8n Cloud: Управление осуществляется через личный кабинет на сайте n8n. Основная настройка — это раздел Settings, где задаются ключи API для внешних сервисов и производится управление учетными записями пользователей (User Management). Обновление версии происходит автоматически по нажатию кнопки Upgrade в интерфейсе панели управления.

      * Railway Dashboard: Работа строится на создании проекта (кнопка + New Project -> Deploy from Template). Для n8n используется шаблон, который автоматически создает Service.

          * Variables: Вкладка, где прописываются критические параметры: N8N_ENCRYPTION_KEY (для шифрования данных), DATABASE_URL (для внешней базы данных) и WEBHOOK_URL (для корректной работы входящих триггеров).

          * Deployments: Журнал развертывания. Отображает статус сборки (Build) и запуска (Runtime). Если статус «Active», система готова к приему трафика.

          * Settings (Domain): Раздел, где генерируется публичный URL. В поле Custom Domain задается адрес, по которому будет доступен ваш экземпляр n8n.

      * Синхронизация данных: При смене способа деплоя (перенос с n8n Cloud на Railway) используется функция Export Workflow (файл .json), который импортируется через интерфейс Workflow Editor в новом инстансе с помощью кнопки Import from File.

=== Пошаговая инструкция: Деплой n8n в Railway ===

Для развертывания инстанса выполните следующие действия в панели управления Railway:

      * Нажмите кнопку + New Project, затем выберите Deploy from Template.

      * В строке поиска введите n8n и выберите официальный шаблон.

      * После завершения сборки перейдите на вкладку Settings вашего нового сервиса.

      * Найдите раздел Domains и нажмите Generate Domain — это адрес вашего сервера.

      * Перейдите на вкладку Variables. Добавьте переменную N8N_PORT со значением 5678 и N8N_PROTOCOL со значением https.

      * Нажмите кнопку Deploy (или дождитесь автоматического перезапуска), чтобы применить изменения.

      * Перейдите по сгенерированной ссылке в браузере, чтобы открыть интерфейс n8n.

=== Типичные ошибки при деплое ===

      * Ошибка 404 или Connection Refused: Причина — неверный порт. Решение: проверьте на вкладке Settings -> Networking в Railway, что порт в настройках контейнера совпадает со значением N8N_PORT в переменных окружения.

      * Ошибка "Webhook URL not set": Причина — n8n не знает свой внешний адрес. Решение: в настройках Railway добавьте переменную WEBHOOK_URL и вставьте туда полный адрес вашего домена, сгенерированного на этапе настройки.

      * Сброс рабочих процессов после перезагрузки: Причина — использование внутренней SQLite базы данных в эфемерном контейнере. Решение: на вкладке Volumes в Railway добавьте новый Volume, примонтируйте его к директории /home/node/.n8n.

=== Практическое задание ===

      * Создайте проект n8n в Railway по инструкции выше.

      * Сгенерируйте токен доступа (через меню Settings -> API Keys внутри вашего инстанса n8n).

      * Импортируйте любой существующий рабочий процесс (Workflow) из предыдущего урока в облачную версию n8n через кнопку Import from File.

      * В настройках ноды Webhook измените значение поля Webhook URLs (Production) на новый URL, полученный после деплоя в Railway.

      * Нажмите Activate в верхнем правом углу, чтобы запустить процесс в облаке.

      * Сделайте скриншот вкладки Execution, подтверждающий, что событие было обработано именно на домене, который вы создали в Railway.

НАЗВАНИЕ: Урок 7.2. Установка n8n на бесплатный сервер Railway через визуальный интерфейс
==================================================

=== Суть инструмента n8n ===

n8n — это система автоматизации процессов (Workflow Automation Tool) на основе узлов (nodes). Каждый узел представляет собой логический блок, выполняющий конкретное действие: прием данных, их трансформацию или отправку в сторонний сервис через API. Система работает по принципу визуального программирования, где логика выстраивается соединением узлов линиями передачи данных (JSON-объектов).

В контексте Railway, n8n разворачивается как Docker-контейнер. Это обеспечивает постоянную работу сервера в облаке, что необходимо для обработки Webhook-событий в режиме реального времени. В отличие от локального запуска, облачная версия не зависит от состояния вашего персонального компьютера.

=== Интерфейс и логика настройки ===

Для корректной работы системы необходимо понимать назначение следующих функциональных областей:

      * Workflow Editor (Рабочая область): Основное поле для построения схемы. Содержит ноды (узлы), которые соединяются коннекторами. Данные проходят через них последовательно.

      * Webhook Node (Нода приема данных): Ключевой элемент для запуска автоматизации. Она создает уникальный URL, который принимает POST или GET запросы из внешних источников. Поля Test URL и Production URL должны различаться: первый используется для настройки, второй — для эксплуатации.

      * Execution Menu (Мониторинг): Вкладка, расположенная в левой панели интерфейса. Здесь фиксируются все запуски (executions). Статус Success означает успешное выполнение, Failed — наличие ошибки в логике или сетевом соединении.

      * Settings -> Environment Variables (Railway): Внешнее меню управления параметрами сервера. Здесь задаются переменные окружения, такие как N8N_ENCRYPTION_KEY или WEBHOOK_URL. Любое изменение переменных приводит к автоматическому перезапуску контейнера (Redeploy).

      * Credentials (Управление доступом): Меню в левом нижнем углу. Используется для хранения API-ключей и токенов авторизации сторонних сервисов. Это исключает хранение паролей внутри самих нод.

      * Activate Button: Переключатель в правом верхнем углу интерфейса. Активация переводит процесс из режима редактирования в рабочий режим, позволяя вебхукам принимать входящие сигналы в фоновом режиме сервера.

=== Пошаговая инструкция по деплою и интеграции ===

      * Создание проекта: В панели управления Railway нажмите кнопку + New Project, выберите Deploy from GitHub repo. Укажите официальный репозиторий n8n.

      * Настройка домена: Перейдите во вкладку Settings вашего нового сервиса. В блоке Domains нажмите Generate Domain. Скопируйте полученный адрес (например, n8n-app.up.railway.app).

      * Переменные среды: Перейдите в раздел Variables. Нажмите + New Variable. Добавьте ключ WEBHOOK_URL со значением https://[ВАШ_ДОМЕН_РАЙЛВЕЙ]/. Нажмите Add. Дождитесь завершения процесса пересборки (статус Deploying сменится на Success).

      * Обновление Workflow: Откройте интерфейс n8n по вашему новому адресу. Откройте нужный Workflow. Кликните по ноде Webhook. В поле Webhook URLs убедитесь, что адрес теперь соответствует вашему домену Railway.

      * Активация: Переключите тумблер Active в положение ON в правом верхнем углу экрана.

=== Типовые ошибки и их устранение ===

      * Ошибка "Webhook URL Mismatch": Возникает, когда в ноде Webhook прописан локальный адрес (localhost), а сервер работает в облаке. Решение: Убедитесь, что в настройках ноды выбрано значение "Production" и оно соответствует домену Railway.

      * Ошибка "Execution Failed - Timeout": Сервер Railway перешел в "спящий режим" (Inactivity) из-за отсутствия активности или нехватки памяти. Решение: Зайдите в панель Railway, вкладка Metrics. Если потребление RAM близко к пределу, увеличьте лимиты в настройках сервиса или перезапустите контейнер (кнопка Deploy -> Redploy).

      * Ошибка "404 Not Found" при запросе к Webhook: Вы отправили запрос на старый домен или забыли сохранить изменения в ноде Webhook после деплоя. Решение: Переоткройте Workflow, убедитесь, что изменения сохранены (кнопка Save в верхнем углу), и повторно активируйте тумблер Active.

=== Практическое задание ===

      * Создайте в n8n пустой Workflow с двумя нодами: Webhook (метод POST) и Wait (на 5 секунд).

      * Опубликуйте Workflow и получите уникальный Production URL.

      * Отправьте тестовый POST-запрос на этот URL через любой сервис тестирования (например, Postman или curl-онлайн инструменты).

      * Откройте вкладку Executions в n8n и добейтесь статуса Success.

      * Сделайте скриншот, на котором отчетливо видно, что в поле URL ноды Webhook отображается именно ваш домен Railway, а не локальный адрес.

НАЗВАНИЕ: Урок 7.3. Домены и Webhook-URL в Railway для production-бота
==================================================

=== Суть инструментов: Домены и Webhook-URL ===

В архитектуре автоматизации Webhook — это уникальный HTTP-адрес, который ожидает поступления данных от внешних систем. Когда внешняя платформа (например, Telegram или CRM) отправляет запрос на этот адрес, n8n мгновенно запускает рабочий процесс.

В контексте Railway ваш инстанс n8n получает публичный домен. Без привязки домена или использования стандартного URL от Railway, сервис не сможет принимать входящие сигналы из глобальной сети. Webhook-URL — это мост, связывающий событие на стороннем сервере с логикой вашего workflow.

=== Интерфейс и логика настройки ===

Для работы с Webhook в n8n используются следующие элементы:

      * Нода Webhook: Основной узел для входящих соединений. В поле HTTP Method выбирается метод передачи данных (обычно POST). В поле Path задается уникальный идентификатор пути, который дописывается к базовому домену вашего проекта.

      * Production URL: Адрес, который генерируется n8n после нажатия кнопки Save и перевода переключателя Active в положение "Включено". Этот адрес содержит ваш домен Railway и специфичный путь для конкретного workflow.

      * Вкладка Settings (внутри ноды): Здесь настраиваются параметры аутентификации. Для простых задач на этапе обучения используйте режим None.

      * Интерфейс Railway: В панели управления Railway во вкладке Deployments или Settings -> Domains можно найти базовый URL (вида project-name.up.railway.app). Убедитесь, что этот адрес совпадает с тем, что отображается в поле URL ноды Webhook внутри n8n.

      * Вкладка Executions: Служебное меню n8n, где фиксируются все входящие запросы. Статус Success означает, что запрос прошел через домен, был корректно принят нодой и обработан без ошибок.

=== Пошаговая инструкция настройки ===

Для активации рабочего Webhook выполните следующие действия в интерфейсе n8n:

      * Откройте нужный Workflow. Перетащите на рабочее поле ноду Webhook.

      * В настройках ноды установите HTTP Method в значение POST. В поле Path впишите латинскими буквами уникальный идентификатор, например incoming-data.

      * В поле Respond выберите Immediate Response, чтобы сервер мгновенно подтверждал получение данных.

      * В верхнем правом углу нажмите кнопку Save.

      * Переключите тумблер Active в состояние ON. В верхней части окна появится поле Production URL. Скопируйте этот адрес в буфер обмена.

      * В браузере откройте сервис для тестирования (например, Webhook.site или POST-клиент). Вставьте скопированный URL и нажмите кнопку Send (отправка запроса).

=== Почему это ломается: распространенные ошибки ===

      * Ошибка 404 (Not Found): Workflow не активирован или не сохранен. Решение: Проверьте, горит ли тумблер Active в верхней панели. Без этого n8n не "слушает" входящие соединения.

      * Ошибка 403 (Forbidden) или отсутствие реакции: Неверно указан путь или метод запроса. Решение: Убедитесь, что в тестовом сервисе выбран метод POST, а не GET, и путь в URL полностью совпадает с тем, что указан в поле Path ноды Webhook.

      * Тайм-аут запроса (Timeout): Нет связи между Railway и n8n. Решение: Проверьте во вкладке Deployments в Railway, что ваш сервис находится в статусе Healthy. Если сервис "уснул" (Sleeping), он не ответит на запрос.

=== Практическое задание ===

      * Создайте пустой Workflow. Добавьте ноду Webhook, настройте метод POST и путь test-link.

      * Активируйте Workflow, скопируйте Production URL.

      * Отправьте на этот адрес любой тестовый JSON-объект (например, {"status": "ok"}) через внешний сервис.

      * Откройте вкладку Executions и найдите запись о полученном запросе.

      * Убедитесь, что в деталях выполнения отображается корректный JSON-ответ. Сделайте скриншот всей страницы с открытой вкладкой Executions и видимым URL-адресом.

НАЗВАНИЕ: Урок 7.4. Мониторинг и восстановление: что делать, если бот завис
==================================================

=== Суть инструмента: Мониторинг состояний ===

Мониторинг в n8n — это система отслеживания жизненного цикла выполнения каждого процесса (Workflow). Когда ваш бот получает внешний запрос, n8n создает запись в базе данных, называемую Execution (выполнение). Эта запись содержит входные данные, промежуточные результаты обработки каждой нодой и итоговый статус: Success (успешно), Error (ошибка) или Waiting (ожидание).

Если бот «завис», мониторинг позволяет увидеть, на какой конкретно ноде остановился процесс. Статус выполнения показывает, завершился ли сценарий корректно или система прервала его из-за тайм-аута, нехватки ресурсов на сервере или синтаксической ошибки в данных.

=== Интерфейс и логика отладки ===

      * Вкладка Executions: Основная панель управления в левом боковом меню n8n. Она разделена на две части: список всех запусков и область детального просмотра конкретного события.

      * Индикатор статуса: Зеленая точка означает успешное прохождение всех нод. Красная — критическую ошибку. Желтая или «часики» означают, что процесс все еще выполняется или «завис» в ожидании ответа от внешней системы.

      * Панель детального анализа (Node View): При клике на конкретное выполнение открывается визуальная схема вашего Workflow. Ноды, которые были успешно пройдены, подсвечиваются цветом. Клик по любой ноде открывает окно Input/Output, где хранятся сырые данные, полученные ботом на данном этапе.

      * Кнопка Rerun: Позволяет повторно запустить Workflow с теми же входными данными. Это критически важно для отладки: если бот завис, вы можете исправить настройки ноды и нажать Rerun, не отправляя повторный запрос извне.

      * Раздел JSON: Вкладка внутри ноды, отображающая структуру данных. Если в поле Output пусто или отображается ошибка, значит, бот перестал получать или обрабатывать информацию именно на этом этапе.

=== Пошаговая инструкция по диагностике ===

      * В интерфейсе n8n перейдите в левое меню и нажмите на иконку Executions (значок часов).

      * В списке выберите последнюю запись, помеченную красным или желтым статусом.

      * Нажмите на строку выполнения: откроется карта вашего Workflow.

      * Найдите ноду, которая подсвечена красным контуром. Кликните по ней.

      * В открывшемся окне переключитесь на вкладку Error — там будет текстовое описание причины, почему процесс не завершился.

      * Если данных нет, переключитесь на вкладку Output. Если поле пустое, значит, нода не получила данные от предыдущего узла.

=== Типичные причины сбоев и способы их устранения ===

      * Тайм-аут (Timeout): Внешний сервис долго отвечает или сервер Railway перешел в режим сна. Решение: В настройках ноды (HTTP Request) найдите поле Timeout и увеличьте значение (например, с 10 до 60 секунд) или убедитесь, что сервис-источник работает в режиме «Always On».

      * Неверная структура данных (Data Mismatch): Вы ожидаете JSON, но получаете HTML-ошибку от сервера. Решение: Проверьте вкладку Input в ноде, которая выдает ошибку. Сравните ключи в JSON с тем, что реально пришло от сервиса. Отредактируйте ноду, чтобы она корректно считывала актуальные поля.

      * Отсутствие прав доступа (Authentication Error): Токен авторизации истек. Решение: Перейдите во вкладку Credentials в настройках ноды, удалите старый профиль и создайте новый, повторно вставив актуальный API-ключ.

=== Практическое задание ===

      * Спровоцируйте ошибку: в настройках ноды Webhook измените метод с POST на GET, сохраните Workflow.

      * Попробуйте отправить POST-запрос на этот же адрес.

      * Зайдите в раздел Executions, найдите проваленный запуск и изучите ошибку во вкладке Error.

      * Исправьте метод обратно на POST, нажмите кнопку Rerun в интерфейсе Execution, чтобы убедиться, что процесс завершился со статусом Success.

      * Сделайте скриншот, где видна панель с историей запусков и статус последнего успешного выполнения (зеленая точка).

НАЗВАНИЕ: Урок 7.5. Экспорт workflow и техническая документация проекта
==================================================

=== Экспорт Workflow: архитектурная целостность ===

Экспорт workflow в n8n — это процесс преобразования визуальной схемы автоматизации в текстовый формат JSON (JavaScript Object Notation). Этот файл содержит полное описание структуры нод, их параметров, секретных ключей (в зашифрованном виде) и связей между ними. Файл экспорта является единственным достоверным техническим документом проекта, позволяющим перенести логику на другой экземпляр n8n или восстановить состояние системы после сбоя.

=== Техническая документация: стандарт описания ===

Техническая документация автоматизации — это фиксация входных и выходных данных для каждой ноды. Она необходима для отладки, так как позволяет сравнить ожидаемую структуру объекта (JSON-схему) с фактической, которую система получает на каждом шаге. Без документирования структуры данных процесс становится "черным ящиком", в котором невозможно выявить причину ошибки.

=== Интерфейсные элементы и логика работы ===

      * Меню экспорта (Download): Находится в правом верхнем углу редактора Workflow (три точки — Options). При выборе "Download Workflow" браузер инициирует загрузку файла с расширением .json.

      * Вкладка JSON в редакторе: Внутри каждой ноды существует переключатель "JSON". Он позволяет увидеть "сырые" данные, которыми оперирует нода. При документировании вы копируете содержимое этой вкладки для создания эталонного образца данных.

      * Версионирование (Snapshots): В панели управления workflow доступна функция "Workflow History". Она фиксирует изменения параметров. Технически это база данных состояний, которая позволяет откатиться к предыдущему рабочему JSON-коду в случае деструктивных изменений.

      * Поле "Notes" (Sticky Note): Специальная нода в интерфейсе, которая не выполняет логических действий, но является обязательным элементом документации. В ней фиксируются: API-методы (POST/GET), URL-адреса эндпоинтов, ожидаемые заголовки (Headers) и формат ответа (JSON/XML).

=== Критическая логика импорта ===

При импорте JSON-файла через кнопку "Import from file", n8n проводит парсинг структуры. Если в импортируемом файле присутствуют ссылки на отсутствующие учетные данные (Credentials), ноды будут помечены красным индикатором ошибки. Это означает, что для завершения импорта необходимо заново привязать валидные токены к соответствующим полям внутри каждой ноды в интерфейсе Credentials.

=== Пошаговая инструкция: Экспорт и документирование ===

      * Экспорт структуры: Откройте созданный workflow. В правом верхнем углу нажмите на иконку три точки (Options). Выберите пункт Download. Сохраните полученный файл на локальный диск — это ваш бэкап логики.

      * Создание документации: В левой панели инструментов (Nodes) найдите иконку Sticky Note (стикер). Перетащите её на рабочее поле. В поле ввода текста укажите: "Цель: пересылка данных из Webhook в Google Sheets. Метод: POST. Параметры: email, name".

      * Архивация данных: Скопируйте JSON-структуру последней ноды (вкладка JSON), откройте текстовый редактор, вставьте код и сохраните его как log_structure.txt.

=== Причины сбоев и методы исправления ===

      * Несоответствие типов данных (Type Mismatch): Вы экспортировали workflow, где нода ожидает число (Number), а при импорте передается строка (String). Исправление: Зайдите в настройки ноды, переключите тип поля (Expression/Fixed) или используйте ноду Edit Fields для приведения данных к нужному формату.

      * Потеря контекста Credentials: При переносе workflow на другой аккаунт (или после удаления учетных данных) нода не видит ключ доступа. Исправление: В выпадающем меню Credential внутри ноды выберите Create New и повторно введите API-ключ или авторизационные данные.

      * Битые ссылки (Broken References): После удаления ноды-источника, последующие ноды теряют связь с данными (поле "Input Data" пустое). Исправление: Пересоберите цепочку нод, удалив поврежденный элемент и перетащив соединительную линию (Input/Output port) от источника к целевой ноде.

=== Практическое задание ===

      * Экспортируйте текущий рабочий Workflow в формате .json.

      * Удалите текущий Workflow из списка (Delete) и импортируйте его обратно через кнопку Import from file.

      * Если после импорта ноды подсвечены красным, откройте их, выберите существующие Credentials и нажмите кнопку Test Step для проверки связи.

      * Добавьте на рабочее поле Sticky Note и кратко опишите, что делает каждая нода в вашей цепочке.

      * Сделайте скриншот рабочего поля с видимым стикером и всеми настроенными нодами, где отсутствуют индикаторы ошибок.
