Урок 6.1. Airtable как база данных для автоматизации: подключение и работа

1. Суть инструмента: Airtable как структурированное хранилище

Airtable — это реляционная база данных с графическим интерфейсом, представленная в виде таблиц. В контексте автоматизации n8n, Airtable выступает как хранилище данных (состояний), где каждая строка является записью (record), а столбцы — полями с жестко заданным типом данных (текст, число, дата, чекбокс).

Принципиальное отличие от Excel заключается в наличии API-ключа и уникального идентификатора таблицы (Table ID), которые позволяют n8n обращаться к конкретным ячейкам, обновлять их или создавать новые записи без прямого участия пользователя в интерфейсе самого Airtable.

2. Интерфейс и логика интеграции в n8n

Для работы Airtable в n8n используются следующие технические компоненты:

  • Credential (Учетные данные): В меню «Credentials» необходимо создать запись типа «Airtable API». Для авторизации используется Personal Access Token, генерируемый в настройках профиля Airtable. Он предоставляет право на чтение и запись в конкретные базы (Base).
  • Node Airtable: Основной инструмент для взаимодействия. Внутри ноды присутствуют следующие параметры:
    • Operation: Выбор действия — «Create» (создать строку), «Get» (получить данные), «Update» (изменить существующую запись) или «List» (вывести все записи).
    • Base ID: Уникальный идентификатор базы, отображается в URL вашего браузера при открытии таблицы (начинается с app...).
    • Table Name: Точное имя таблицы внутри базы. Регистр имеет значение.
  • Mapping Fields: После выбора таблицы, n8n автоматически подгружает список доступных колонок. Вы используете кнопку «Add Field» для сопоставления данных, пришедших из предыдущих нод (например, из Telegram или Gemini), с конкретными колонками в Airtable.
  • Filter/Query (при операции List): Позволяет задать условие выборки через формулу Airtable, например, {Статус} = 'В работе', чтобы отфильтровать записи на стороне базы перед передачей данных в n8n.

1. Пошаговая инструкция по настройке

  • Откройте Airtable в браузере, создайте новую базу и переименуйте колонки: «Message» (тип Single line text) и «Status» (тип Single select).
  • В n8n перетащите ноду Airtable на рабочее поле.
  • Нажмите на поле Credential — Create New. Вставьте Personal Access Token, полученный в разделе Developer Hub вашего аккаунта Airtable.
  • В параметре Operation выберите «Create».
  • В поле Base выберите созданную базу из выпадающего списка. Аналогично выберите Table.
  • Нажмите кнопку Add Field, выберите «Message». Нажмите на иконку шестеренки справа от поля ввода — Expression. В открывшемся окне перетащите переменную с текстом из предыдущей ноды (например, из Telegram Trigger).
  • Нажмите Execute Node для отправки тестовой строки в базу.

2. Ошибки и методы их устранения

  • Ошибка 404 (Table/Base not found): Возникает, если вы изменили название таблицы в интерфейсе Airtable, а n8n продолжает искать старое имя. Решение: Перезайдите в настройки ноды Airtable и обновите выбор Table в выпадающем списке.
  • Ошибка 403 (Permission denied): Возникает, если у токена доступа нет прав на чтение/запись конкретной базы. Решение: В настройках API в Airtable убедитесь, что вы выдали токену (Scopes) права data.records:write и data.records:read, а также добавили конкретную базу в разделе Access.
  • Ошибка типа данных (Invalid Value): Возникает при попытке записать текст в поле типа «Single select», если такого значения еще нет в списке. Решение: Заранее создайте все варианты выбора (опции) в самой таблице Airtable через интерфейс или убедитесь, что вводимый текст идентичен существующему варианту.

3. Практическое задание

  • Создайте цепочку: Telegram Trigger -> Airtable (Create).
  • Настройте запись так, чтобы каждое сообщение из Telegram сохранялось в Airtable в колонку «Message».
  • Добавьте вторую ноду Airtable (операция Update), которая срабатывает сразу после записи: она должна менять статус в колонке «Status» на значение «Processed». Для этого вам потребуется поле Record ID, которое передается в качестве выходного параметра первой ноды Airtable.
  • Проверьте результат в интерфейсе Airtable: после выполнения сценария строка должна появиться и мгновенно изменить статус с пустого на «Processed».
