Урок 1.3. Нода HTTP Request: как «разговаривать» с любым сервисом в интернете

Суть ноды HTTP Request

Нода HTTP Request — это универсальный инструмент для передачи данных между n8n и любыми внешними веб-сервисами, у которых есть API (интерфейс прикладного программирования). Если для конкретного сервиса в n8n нет готовой ноды, HTTP Request позволяет обратиться к нему напрямую, отправляя «запросы» на веб-серверы и получая от них ответы в формате JSON.

Технически процесс выглядит как обмен структурированными сообщениями: вы формируете пакет данных (запрос), указываете адрес сервера (URL) и метод взаимодействия (GET для получения данных, POST для отправки), а сервер возвращает результат выполнения операции.

Разбор интерфейса и логики

Внутри ноды HTTP Request критически важны следующие настройки:

  • Method (Метод): Определяет тип действия. GET используется для получения информации, POST — для отправки новых данных на сервер.
  • URL: Поле для ввода адреса API-конечной точки (endpoint). Сюда вставляется прямая ссылка на сервер, с которым вы планируете взаимодействовать.
  • Authentication (Аутентификация): Меню выбора способа подтверждения доступа. Обычно используются Header Auth (ключ в заголовке) или OAuth2. Без этого этапа сервер отклонит ваш запрос с ошибкой 401 или 403.
  • Send Body (Отправка тела запроса): Активность этого переключателя требуется при методе POST. Здесь вы формируете структуру данных (JSON), которые сервис должен принять и обработать.
  • Headers (Заголовки): Дополнительные параметры запроса. Используются для передачи мета-информации: например, указание формата данных (Content-Type: application/json) или токенов авторизации.
  • Query Parameters (Параметры запроса): Дополнительные фильтры, которые добавляются в конец URL. Используются для уточнения запроса, например: ?limit=10 или ?category=news.

Логика работы ноды всегда строго последовательна: ввод конфигурации -> отправка запроса -> получение ответа (Response). Ошибки в ответе (например, 404 — Not Found или 500 — Internal Server Error) отображаются во вкладке Output ноды, что позволяет диагностировать проблему на уровне API.

Пошаговая инструкция по настройке HTTP Request

Для интеграции внешнего API выполните следующие действия в редакторе n8n:

  • Добавьте на холст ноду HTTP Request и соедините её с предыдущим этапом сценария.
  • В поле Method выберите необходимое действие (например, GET для запроса данных).
  • В поле URL вставьте API-адрес конечной точки.
  • Если API требует авторизацию, нажмите Authentication, выберите Header Auth или API Key и введите предоставленные сервисом данные в соответствующие поля.
  • При использовании POST-запроса перейдите в раздел Send Body, установите переключатель в положение JSON, нажмите Add Field и вручную пропишите ключи и значения согласно документации API.
  • Нажмите кнопку Execute Node. Результат выполнения отобразится в нижней панели во вкладке JSON или Table.

Ошибки и способы их устранения

  • Ошибка 401 (Unauthorized): Система отклоняет запрос из-за неверного ключа. Решение: Проверьте раздел Authentication. Убедитесь, что токен скопирован полностью без лишних пробелов, а название заголовка в разделе Headers соответствует требованиям API.
  • Ошибка 400 (Bad Request): Сервер не понимает структуру данных. Решение: Проверьте вкладку Body. Убедитесь, что все обязательные поля, требуемые документацией API, заполнены, а их типы данных (число или строка) соответствуют ожиданиям сервера.
  • Ошибка 404 (Not Found): Запрос ушел по несуществующему адресу. Решение: Проверьте URL в поле ввода. Ошибки часто возникают из-за опечаток или пропущенных символов в пути к API. Также убедитесь, что вы используете правильный метод (GET вместо POST).

Практическое задание

  1. Создайте новую цепочку: Manual Trigger -> HTTP Request.
  2. Используйте сервис JSONPlaceholder (адрес: https://jsonplaceholder.typicode.com/posts/1) в поле URL для теста GET-запроса.
  3. Настройте ноду на метод GET и выполните её.
  4. В разделе Output убедитесь, что вы получили JSON-объект с полями userId, id, title и body.
  5. Добавьте после HTTP Request ноду Set Node и выведите в ней значение поля title, полученное от сервера, используя Expression Editor.
