Урок 5.3. Автоматическая обработка входящих сообщений с помощью GPT

Суть интеграции OpenAI в n8n

Интеграция OpenAI в n8n работает как посредник между вашим входящим запросом (Webhook) и API нейросети. Нода OpenAI принимает JSON-объект, содержащий текстовое сообщение, отправляет его на серверы OpenAI, где модель обрабатывает данные согласно системной инструкции, и возвращает ответ в формате JSON.

В контексте автоматизации эта цепочка преобразует неструктурированные данные в предсказуемые форматы. Весь процесс является асинхронным обменом данными: n8n ожидает ответа от API, после чего передает полученные данные в следующую ноду сценария для дальнейшей обработки или записи в базу данных.

Интерфейс и логика настройки ноды OpenAI

  • Credential (Учетные данные): Поле для выбора ключа API. Здесь хранятся учетные данные (API Key), которые авторизуют ваш доступ к серверам OpenAI.
  • Resource и Operation: Выпадающие списки, определяющие метод работы. Для классического диалога выбирается Chat, для генерации векторов текста — Embeddings. Изменение этой настройки полностью меняет структуру входных и выходных параметров.
  • Model: Поле выбора версии нейросети (например, gpt-3.5-turbo или gpt-4o). От выбора модели зависит лимит токенов и формат возвращаемого JSON-объекта.
  • Messages: Массив объектов. Внутри каждого объекта задается Role (System, User, Assistant) и Content.
    • System: задает жесткие правила поведения и формат вывода (например, ограничение на ответ только цифрами).
    • User: содержит динамический контент, который передается через Webhook.
  • Expression (Выражения): Кнопка (иконка шестеренки или "Expression"), позволяющая динамически подставлять данные из предыдущих шагов сценария, например, {{ $json.body.message }}, что делает сценарий гибким.

Контроль данных через интерфейс Execution Data

После каждого запуска (кнопка Execute Workflow) n8n фиксирует результат в панели Execution Data. Вкладка Output отображает дерево JSON-структуры. Ваша задача — отследить путь к нужному значению (например, choices -> [0] -> message -> content). Ошибки в цепочке чаще всего возникают из-за неправильного указания пути к полю в ноде Edit Fields (Set), если структура JSON изменилась из-за смены операции (например, при переходе с Chat на Embeddings).

Пошаговая настройка узла обработки

  • Откройте редактор сценария и перетащите ноду Edit Fields (Set) на рабочее поле, соединив выход ноды OpenAI с входом этой ноды.
  • Нажмите на ноду Edit Fields (Set). В открывшейся панели выберите кнопку Add Field, затем выберите тип String.
  • В поле Name введите result.
  • В поле Value нажмите на иконку шестеренки и выберите пункт Add Expression.
  • В открывшемся редакторе выражений перейдите во вкладку Current Node > Input Data > JSON. Найдите путь choices, раскройте его, затем 0, далее message и выберите content. Убедитесь, что в поле выражения появилась строка: {{ $json.choices[0].message.content }}.
  • Нажмите кнопку Save в нижней части панели.

Технические причины сбоев и их устранение

  • Ошибка пути к данным (Cannot read property of undefined): Возникает, если структура ответа OpenAI изменилась (например, при переключении на Embeddings), а путь в ноде остался прежним. Решение: Нажмите на ноду OpenAI, запустите её отдельно, посмотрите актуальную структуру во вкладке Output и заново перетащите путь в поле выражения в ноде Edit Fields.
  • Неверная роль (System/User): Если модель игнорирует инструкцию, значит, системное сообщение не было отправлено первым в массиве. Решение: В ноде OpenAI убедитесь, что блок с ролью System стоит выше блока с ролью User в списке параметров Messages.
  • Пустой результат (Null): Возникает, если в ноде Webhook не переданы данные, на которые настроена нода OpenAI. Решение: Проверьте вкладку Input в ноде OpenAI. Если она пуста, значит Webhook не принял данные. Проведите тестовый запрос из Postman еще раз и убедитесь, что в верхнем правом углу Webhook появилась зеленая галочка.

Практическое задание

Для закрепления материала выполните следующие действия:

  • Создайте новое поле в ноде Edit Fields (Set) с именем model_used.
  • В поле Value через кнопку Add Expression выберите значение поля model, которое находится в корневой структуре ответа OpenAI.
  • Добавьте ноду Webhook в режиме Response: On Received в конец цепочки.
  • Настройте ноду Respond to Webhook так, чтобы она возвращала пользователю JSON-объект, содержащий оба поля: result и model_used.
  • Успешно протестируйте сценарий, отправив любой текст через Postman и получив в ответ структурированный JSON с числом и названием модели.
